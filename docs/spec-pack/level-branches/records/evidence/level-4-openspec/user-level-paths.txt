Where the temp folder is (node -p 'os.tmpdir()'): with TMPDIR set to a scratch folder it is that folder; with TMPDIR unset on this machine it is /tmp.
macOS login shells normally set TMPDIR to a per-user folder under /var/folders (the folder that the command below prints), so there the cache sits in that folder.
The scratch temp folder of the whole T11 task (set as TMPDIR for every run of this task) holds node-compile-cache with 2454 files.

How to see it:   ls "$(node -p 'os.tmpdir()')/node-compile-cache"    and    find "$(node -p 'os.tmpdir()')/node-compile-cache" -type f | wc -l
How to undo it:  rm -r "$(node -p 'os.tmpdir()')/node-compile-cache"   (it is a cache; Node rebuilds it, and the OS purges its temp folder by itself)
Not covered by npm cache clean: it lives outside ~/.npm.

Added check: in the shell used for this task (macOS) TMPDIR is set: yes, and node -p 'os.tmpdir()' prints a folder under /var/folders: yes (masked here).
Correction to the last undo line: when the OS clears its temp folders differs by system (and on Linux /tmp may be kept until reboot); delete the folder to be sure.
