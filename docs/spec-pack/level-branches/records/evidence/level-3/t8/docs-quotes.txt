[Q3] hooks.md lines 964-972: what counts as a failure for onFailure, and what block then does
    964 | Each of these counts as a failure:
    965 |
    966 | * **Can't start**: a command hook fails to start, for example because the script or executable doesn't exist
    967 | * **Exit code other than 0 or 2**: counts for a command hook even if it printed JSON that allows the action, such as `permissionDecision: "allow"`. To return a JSON decision, exit 0
    968 | * **HTTP error**: an HTTP hook's connection fails, or the response status isn't 2xx
    969 | * **Timeout**: the hook reaches its [`timeout`](#common-fields)
    970 | * **Invalid output**: the JSON output [can't be parsed](#exit-code-0) or fails [schema validation](#json-output). For an HTTP hook, a 2xx body that is neither empty nor a JSON object also counts. Plain-text stdout from a command hook isn't a failure
    971 |
    972 | With `"block"` set, a failure does what [exit code 2 does on that event](#exit-code-2-behavior-per-event), except on `PermissionRequest`, where it denies the request. For example, a `PreToolUse` failure blocks the tool call and a `UserPromptSubmit` failure blocks the prompt.

[Q5] hooks.md lines 876-876: an exit code other than 0 or 2 is a non-blocking error unless the failure blocks the action
    876 | A `<hook name> hook error` notice with `Failed with non-blocking status code:` means your hook's exit code wasn't 0 or 2 and its stdout was plain text or empty. [Q6] tools-reference.md lines 481-490: Bash deny rules turn the PowerShell tool off unless CLAUDE_CODE_USE_POWERSHELL_TOOL=1 or a PowerShell rule; a Bash rule does not restrict it
    481 | ### Bash deny rules also turn off the PowerShell tool
    482 |
    483 | On Windows with Git Bash installed, denying Bash also turns the PowerShell tool off for the session. This applies to scoped rules such as `Bash(git push *)` as well as a bare `Bash`, and to rules from one of your settings files or `--disallowedTools`. Claude Code does this because a `Bash` rule doesn't restrict the PowerShell tool, which has [its own permission rules](https://code.claude.com/docs/en/permissions.md#powershell). With PowerShell left on, Claude could run there what your rule denies in Bash.
    484 |
    485 | To keep the PowerShell tool on alongside a Bash deny rule, do either of these:
    486 |
    487 | * Set `CLAUDE_CODE_USE_POWERSHELL_TOOL=1` in your environment or in the `env` block of a settings file, as shown in [Enable the PowerShell tool](#enable-the-powershell-tool).
    488 | * Add a scoped [`PowerShell` permission rule](https://code.claude.com/docs/en/permissions#powershell) to a settings file, such as a `PowerShell(git push *)` deny rule.
    489 |
    490 | Without one of these, a scoped Bash deny rule leaves the Bash tool available, and Claude Code turns PowerShell off without a warning. A rule that removes the whole Bash tool leaves Claude with no shell tool for the session.
