## Part A: LSP {/* #part-a-lsp */}

About 10 minutes.

Claude Code has a built-in, read-only LSP tool. With a code intelligence plugin installed, it gives go to definition, find references, type info, document and workspace symbols, implementations and call hierarchy. Claude Code also reports diagnostics automatically after every edit.

### 1. Check the binary

```bash
which jdtls
```

Windows: inside WSL. If the binary is missing, install it as in the [setup check](./00-setup-check.md#install-jdtls).

### 2. Install the plugin

Run this inside Claude Code:

```text
/plugin install jdtls-lsp@claude-plugins-official
```

If the marketplace is missing, add it first and then repeat the install:

```text
/plugin marketplace add anthropics/claude-plugins-official
```

Choose a scope: user scope keeps the plugin out of the repository, and project scope writes it to `.claude/settings.json`. Confirm the plugin on the **Installed** tab of `/plugin`.

### 3. Use it

Ask Claude:

```text
Find all references to `Money.of`.
```

The answer comes from the language server, not from a text search. It spans several layers: domain, flows and mappers, and tests.

### 4. Make one deliberate type error

Ask Claude to break the code on purpose:

:::tip[Checkpoint]

```text
In `Book.java`, make `price()` return `String` instead of `Money`. Do not touch the callers yet.
```

Expected: Claude Code prints `Found N new diagnostic issues ...` under the edit.

:::

Then ask Claude to repair it:

```text
Fix the new diagnostics.
```

Watch the agent read the diagnostics and repair the code.

### 5. Nothing appears?

Check `/plugin` (tab **Errors**) and start Claude Code with debug output:

```bash
claude --debug
```

The debug output goes to a log file under `~/.claude/debug/` and prints nothing extra in the terminal. Look in that file for a line with `LSP server` and `failed to start`.

The error `Executable not found in $PATH: "jdtls"` means the binary is missing.

<details>
<summary>Debugging options: five checks and a diagnosis prompt</summary>

Try these in order and stop as soon as the diagnostics appear:

1. The binary: run `which jdtls` in the same terminal that you start `claude` from. It must print a path (Windows: inside WSL). If it prints nothing, install it as in the [setup check](./00-setup-check.md#install-jdtls), open a new terminal and start `claude` again.
2. Java: run `java -version`. The language server needs Java 21 or later.
3. The plugin: open `/plugin`. `jdtls-lsp` must be on the **Installed** tab and enabled, and the **Errors** tab must not list it.
4. A new session: if you installed `jdtls` or the plugin after Claude Code started, or put `jdtls` on the `PATH` in another terminal, start a new session from a shell where `which jdtls` prints a path.
5. The first Java edit: the language server starts the first time Claude edits a `.java` file. Repeat the deliberate type error (Part A, step 4) before you decide that it is broken.

Or paste this prompt and let Claude check what it can. It only reads and changes nothing:

```text
The jdtls language server plugin shows no diagnostics. Check without changing anything: run which jdtls and java -version and tell me the results, read .claude/settings.json and ~/.claude/settings.json and tell me whether jdtls-lsp@claude-plugins-official is enabled, and tell me what else I should check on the Errors tab of /plugin. Then name the most likely cause and the one fix to try first. Do not edit, install or delete anything.
```

Claude may not see exactly the shell that you start it from, so trust your own `which jdtls` over its answer.

</details>

Still stuck after two minutes: continue with Part B.

## Part B: MCP {/* #part-b-mcp */}

About 8 minutes.

### 1. Start the distributor

```bash
./mvnw -pl distributor spring-boot:run
```

Or run `java -jar distributor.jar`. Leave the distributor running while you work through Part B.

### 2. Register it for the project

```bash
claude mcp add --transport http --scope project distributor http://localhost:8090/mcp
```

This writes `.mcp.json`. If Claude Code asks you to approve the project MCP server, approve it. Restart Claude Code if needed.

:::tip[Checkpoint]

```text
/mcp
```

Expected: `/mcp` shows `distributor` connected with 4 tools.

:::

### 3. Ask one question

```text
Which science-fiction titles does the distributor have that we do not sell yet?
```

The tools show up as `mcp__distributor__*`.

### 4. Use it as development context

Ask Claude:

```text
Using the distributor MCP, find a title that has a translator or illustrator among its contributors. Write an ACL contract test for `DistributorAppServiceImpl` with that exact payload shape and prove that only authors end up in our catalogue.
```

The existing tests deliberately do not cover this case. Run `./mvnw verify` to see your new test green.

### 5. See how little code a tool is

An MCP tool is little code. Look at `distributor/src/main/java/nl/openvalue/distributor/mcp/CatalogMcpTools.java`. It holds the four tools `search_titles`, `get_title`, `list_subjects` and `check_availability`.

:::tip[Make it yours]

The best harness has a creative engineer tweaking it all the time. Think of a fifth tool that Claude would use on the bookstore, and write down its name, its inputs and what it returns. Or add one rule to `CLAUDE.md` that tells Claude to ask the language server before it searches the text.

:::
