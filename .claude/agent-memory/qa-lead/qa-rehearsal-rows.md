Siblings: [[qa-harness-staging-specs]], [[review-scope-rulings]] (nit classing).

1. **Rehearsal rows must produce the state they premise.** Verifiers check row wording and tokens, not whether setup, reset and judge commands give "fresh" runs. On one clone, `git restore . && git clean -fd` keeps the ignored `target/` (a stale `target/classes/db/migration/V5__*.sql` reaches the next run's Flyway classpath) and any commit (a CLAUDE.md asking for "small commits" invites them); working-tree-only judging then misreads a committed run. Require a recorded start sha, `git reset --hard <start> && git clean -fdx` (or a fresh clone), judging against `<start>` and `./mvnw clean verify`. A third witness lives outside the repo: Claude Code's per-project auto memory, keyed by the clone path, survives any reset in the same folder: require a new clone folder per run or a `/memory` check before each run. List all three witnesses up front.
2. **Staged exercise reference tests over existing production (characterization tests).** A "red" from a missing contract file proves nothing; the binding proof is a role-mutant ladder plus a control showing the pre-task suite lets the main mutant live. At strategy time: (a) for an allow-list rule (`"AUTHOR".equals`) list the deny-list of values the data happens to hold as a falsifier and a witness value outside that set (EDITOR), and check the seed for a title carrying it BEFORE the card pins "one contract file"; (b) when the task adds a row to a participant-facing provenance doc, direct the verifier to re-check every section claim for the new row (run-naming headings, column headers, exhaustive enumerations): verifiers rate such contradictions as nits.
   - The nit-rating also hits NEW authored files: a universal claim about the code ("every end to end test is named `*IntegrationTest`") falls to one `git grep` on the base; direct verifiers to counterexample-search every "every/all/only/never". A rule reworded to match the code can contradict the file's declared source of truth: route a product finding against the source, never reword back. Demand a per-round hash file of changed files. Mirror sites reach past the module: grep the sibling endpoint repo-wide.
3. **Lifecycle premises in rehearsal rows.** Rows state "added here" facts about WHEN Claude Code starts something (the first references request is the LSP cold start) and nobody checks them. Claude Code's docs say the language server starts the first time Claude EDITS a file of the plugin's extension (code-intelligence page, "Confirm the server starts"); a read-only first request may meet no server and fail as "text search". At strategy time require every row's lifecycle premise (LSP, MCP, plugin, hook, skill load) to be sourced in an evidence file with a branch for the other behaviour, and the measurement to start at the event that really starts the component.
   - When I write such a branch as an RA, dry-run it through the NEXT row of the suggested order: a branch pulling an edit forward leaves the tree changed under a later "unchanged tree" premise, and a "started but not ready" first answer needs its own stop event. A component started BY an edit has a second "not ready" form (no report under that edit, so no stop event): list both forms and the "never started" case in every timing branch.
4. **Row literals measured with another command.** Dry runs count with `git status --porcelain -uall`, rows print plain `git status --short`, which folds a new untracked folder into one line (29 files -> 10 lines). In every row review run the printed command verbatim and compare with the literal; reject premises measured by a variant.
