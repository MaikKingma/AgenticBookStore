Rules settled while meta-reviewing verifier verdicts. Apply them in every review so verdicts stay consistent. See also [[qa-directive-traps]].

1. **Carrying probe evidence into a rework round.** A verifier may skip re-running earlier mutation probes only if (a) the sha256 of every production file equals the earlier baseline; (b) the test diff is insertion-only (every earlier quoted asserting line found verbatim at its recorded or shifted line); (c) the earlier probe logs are still on disk. Why: a mutant's kill depends only on the production bytes and the killing test; an edited killing test silently voids old evidence. That is why I quote asserting lines into the ledger every round. If (a) to (c) fail, CHALLENGE for a re-run.
   - A verifier can prove (b) without my quotes: copy the test file, delete the inserted method, hash against the earlier baseline, plus a control (the REJECT's survivor run against the pre-rework copy still passes). Key carried probes by handler and field or runner mutant text, never by bare ID (verifiers renumber and reuse IDs): prefix IDs with the task, point at the runner file, and diff mutant text against the earlier runner line before writing "X killed".
   - Keeps the carry: a rework changing only how a killing test captures output (new capture sees a superset, asserting lines verbatim, mutants only that test kills re-run); a production edit when every carried mutant edits an untouched line and no killing input reaches the changed branch (list tokens with `git grep -oh`; read the rework numstat myself, "no product file changed" often means the site); a whitespace-only edit (`diff` against `.orig`) or comment-only edit of a guarded TS/JS file (comment-stripped files byte-identical, guarding test hash unchanged); an input-only edit (undo it in a copy and hash; no carried probe has the edited test as its only killer).
   - An inserted-statement survivor (`if (x === null) continue`) is no REJECT when the simple mutation of the same guard dies and other rows pin the policy: rule 3 allowance plus a test-only follow-up. A cross-class state check carries only when the inserted test writes fresh keys inside a rolled-back slice transaction after the cleaning hook.
2. **Null guards count as validation branches.** In domain and domaininteraction code, an `Objects.requireNonNull` or any throwing null check needs a test that fails when it is removed, unless removal is equivalent (a later statement throws the same type on the same input: `List.copyOf(null)`). Feed forward to impl directives.
3. **REJECT threshold for surviving mutations.** On money, ISBN or numbering, persistence, transaction and cross-module contract criteria, a survivor I can show from the code is a REJECT. On a low-risk criterion, a survivor that only distinguishes decided wording (`strip()` vs `trim()`, `Locale.ROOT`) with no listed falsifier and the decided form in the code is inspection-proven: record it, feed forward a witness. Why: the strategy's falsifier list is the advance bar; a cosmetic distinction in the last rework round moves it. Prevent by naming the witness at strategy time ([[qa-directive-traps]] item 15). The same allowance (inspection, test-only follow-up, qa-final probe, no last-round REJECT) covers:
   - An exemption the code never names (one label carved out of a generic loop whose siblings are pinned) when a real-page probe shows the gated checker flags it: send the case to the last task owning the files before a freeze.
   - A verifier's "equivalent under the tested requests": find the reachable input that differs (Accept header, edge whitespace); if only clients the consumer never is see it and no falsifier was listed, allowance applies.
   - Defensive path guards in an unscoped advice (415 guard, `getContextPath()` in a prefix) are equivalent only after I read the config myself (actuator `exposure.include`, `server.servlet.context-path`, `consumes`) and a witness tried the reachable routes. A prefix survivor (`/api` for `/api/`) differs only on raw URIs, where the mutant gives the better answer: plan-level residual.
   - A survivor on input my strategy priced as a residual, or adding behaviour where no guard exists, with production correct by reading. A survivor of an existing throwing guard is still a REJECT.
   - A survivor equivalent only because of a pinned configuration (a mapper ignoring its `Clock` while the bean is `Clock.systemUTC()`) when the clause was an inspection item: witness to the next task crossing the seam. If an over-claiming test was the only listed falsifier: REJECT.
4. **Survivor whose kill contradicts a pinned criterion.** If the only way to kill it is to change something a criterion pins (a fixture signature): no REJECT, record a plan-level gap and recommend the amendment (cheapest inside a rework round that runs anyway), else a follow-up and a final-brief item. A survivor killable in scope without touching a pin stays a REJECT. Verifiers label extra survivors "informational": judge each against the criterion text and file scope. Same for an inserted `catch` around a port call in a flow test with mocked ports when the criterion lists the allowed new tests (feed a must-fail swallow probe to the task owning atomicity), a test helper's default wiring only a deliberately failing test can kill while a C0 item bans `.fails`, and a clause whose falsifier my strategy put at qa-final (brief qa-final with the check plus a discriminating control).
5. **Strengthening-only survivors.** A mutation that can only add violations (ArchUnit `allowEmptyShould(true)` -> `(false)` on never-empty imports) does not weaken the guard: inspection-proven when the criterion pins the setting, even on money criteria.
6. **Edited killing assertion vs carry-forward.** An edit voids carried evidence unless it is a monotonic strengthening I verify in the helper (expected-violator list extended with old entries as an unchanged prefix, each asserted on its own, no count or exact-set check). Demand a probe only the new fixture can kill.
7. **Oracle helpers that call production code.** A test may compute an expected value from production code (the domain exception's message) when (a) the helper calls nothing of the class under test; (b) every contract field (code, title, field name, list, exception type) stays a literal; (c) the helper asserts its own precondition (`isNotNull`). A contract field computed from production code is a REJECT.
8. **Required forms stated as parentheticals.** A form requirement (an escape, a specific API) that reached the plan only in parentheses is no REJECT bar when the property it serves is proven on the gated bytes: follow-up plus hash baseline until merge. Fix at strategy time: imperatives with a check command ([[qa-directive-traps]] item 16). Same, minus "property proven", for a form living only in a binding strategy decision that never reached the card or falsifier list: ENDORSE, report the undisclosed deviation, log a residual. Prevention: copy every binding decision's form into the implementing task's falsifier list.
9. **Survivors equivalent on every reachable input.** A money-adjacent survivor (`toString()` for `toPlainString()`) is inspection-proven when an upstream invariant pinned by its own tests (scale-2 type, fixed-scale column) makes outputs identical, the strategy made the clause an inspection item, the listed falsifier kills, and a follow-up names the witness for when a later spec widens the domain.
   - Downstream validators are no invariant: "the domain rejects other values" fails when the check sits after the mutated hand-off (a mapper dropping the currency argument bypasses the EUR-only rule). Equivalent only if the input is already the validated type or guarded upstream (a check constraint). Look for a sibling test killing the same mutant in an older mapper.
   - Read paths that never restore carry corrupt stored values to the views, so "the aggregate keeps it consistent" is no equivalence argument. A view clause delegating to an accessor already pinned with a decorrelated witness gets rule 3 allowance plus follow-up; a mutant turning a named ProblemDetail rejection into silent success is a REJECT.
   - Pass-through survivors found late in an already-endorsed sibling: must-fail probe in the qa-final directive and a test-only fix task; never drop it because the sibling is merged. Found while reviewing an unrelated fix task: no RA of that task. Found in the still-open fix task for the same class and file scope and proven by a run: fold in as REJECT with a test-only RA if the orchestrator records the criteria extension.
   - Pass-through inventory: per handler, list the distinct values tests feed each contract field (`code`, `title`, `details`, ids). A field fed one value survives replacement by it, realistic when it is a natural default; grep the spec pack before calling a literal arbitrary. Single test constants let hard-code mutants survive in mappers (no REJECT; prevent via an implDirective data rule "every pass-through field fed two distinct values, asserted as literals"). A `valueOf(status)` hand-off killed by an unknown value still lets a `strip()` variant survive: inspection-proven when the writer stores `name()`.
10. **No red run.** Tests written first with a green first run are no gate finding outside an sdd-bugfix lead directive, provided every criterion clause bites on the gated bytes (must-fail probe, or I kill it by reading). When a bugfix's root-cause file is the test itself, check at which line each red fixed-bytes probe fails: neighbouring lines mean the rewritten assertion has no run evidence. Unlisted in the plan and exact by reading: ENDORSE, brief one qa-final probe per direction (Flyway history: an extra location holding a V file; a `SELECT 1` V file above `spring.flyway.target`). For "tests never see the seed" find the test-profile context as `applied N migrations` with no `with repeatable migration` line. Implementer red taken before editing pages proves the page side only: accept when the verifier's NC on the final bytes repeats the messages verbatim and explains every extra red.
11. **Implementer edits outside its file scope.** Mutating a production file to prove a fix kills a survivor is a process finding for the orchestrator, not a gate finding, if restored, hash-identical in the verifier's snapshot, runs did not overlap and gate evidence is the verifier's own. Implementer probe logs are never gate evidence: a verdict leaning on them, or overlapping runs, gets a CHALLENGE. Wording: [[qa-directive-traps]] item 17.
12. **A disclosed probe-restore slip** is no finding when (a) before and after snapshots are identical; (b) every gated file's mtime is earlier than snap-after and the referee start and its hash equals snap-before; (c) every probe run after the slip fails at a line the stray form cannot explain, or is equivalent. If (c) fails for a probe, CHALLENGE for a re-run. Prevention: [[qa-directive-traps]] item 3. An env-selected mutant schema (one file per class, `switch` on an env variable, `default` = original) is valid when a control run with the variable unset is green, I read every `case` against its named mutant, and each probe is its own `clean test` run with its own log, restored by `cp` and hash-checked (annotation mutants cannot be switched). Two sort probes giving the same permutation leave identical failure text: accept one run per distinct permutation plus the column-by-column argument on a pure pass-through asserted with `containsExactly`.
13. **A rework edit to an asserting line that follows a data edit** is no lens 6 REJECT when production is hash-identical, the element set and matcher are unchanged (the new expected value is the spec rule recomputed on new inputs), every probe the old line killed is still killed by some test, and the edit kills more than before. Check by reading which mutants only the edited test kills.
14. **A brief expectation refuted by evidence.** When a verifier shows an expected value in my directive came from a false premise, ENDORSE lowers no bar if no criterion pins the value, the binding property still holds and I confirm it myself (one read-only check such as `javap -c` plus reading the rule), and the verifier backs the refutation with a control (U+00A0 gives 202 where U+2003 gives 400). Fix the premise at finalize and correct my ledger and memory. If a criterion pins the refuted value, it is a product question. Same family (ENDORSE plus a plan-level amendment recommendation, no bar lowered):
   - A C0 warning-class example whose only fix breaks a pinned criterion (a logback status line from a spec-mandated empty pattern): exact-count acceptance is fine when stdout is tested unfiltered and the count bites both ways; product residual.
   - A criterion whose literal wording the orchestrator's own process breaks (plan.md bookkeeping commit vs "no file outside ci.yml"): ENDORSE when the protected property is proven; recommend the wording fix.
   - A must-fail probe that cannot run as written or is an equivalent mutant (confirm by `javap` plus a witness diff): the verifier's substitute is valid when it breaks only the property under test and fails at the scenario's state assertions. If the pin is my own rewrite, I rule it: ENDORSE plus an amendment with exact wording, provided the corrected probe dies.
   - The opposite: a fail-closed premise I wrote into an RA that the verifier refutes with builds while a closed grading rule I also wrote FAILs the task. The grading rule governs; reclassing refuted cases as residual narrows the bar after the fact, which only a human may do. AMEND the RA, own the premise in the ledger, give the human options with a structural guard.
   - A harness mandate (attribution footer's emoji under "PR body ASCII only") is accepted when the prose is ASCII and no criterion pins the body. A base merged mid-sweep adding a hit to a directory-wide grep is no finding when `git grep` on both bases attributes it and the file is outside the spec diff. A base moving AFTER a qa-final PASS is no CHALLENGE when `git log --stat <old>..<new>` touches no file of `git diff --name-only <old>...<tip>`: ENDORSE, hand the mergeability re-check to the orchestrator.
   - A card clause naming an analogue test that does not exist: ENDORSE when the verifier measured the property with a removed temporary test and the orchestrator ruled the clause; residual plus qa-final item. Prevent: grep every named analogue before it enters a falsifier list.
   - A bugfix NC "fails on exactly the tests of criteria 1 and 2": extra reds are fine if no pre-existing test is red and each fails at its first behavioural assertion; write NC criteria as "named shapes, no pre-existing test red".
   - At a fetch-joined `order by`, an `@OrderColumn` position is a flat child column reachable only as `index(l)`; its `asc` sort ties every root at position 0, so no data forces it: an inspection item.
15. **Oracle-hardening gaps outside the criteria.** When a verifier finds a self-written checker passes vacuously in a way no criterion covers (zero self-tests discovered still exits 0), do not REJECT the PASS: make it a criterion amendment for the next task owning the same files, with must-fail witnesses. Until then add a verifier-side guard: the test total is never below the last gated total and earlier test titles are a subset of the current ones. "N equals the grep count" misses a deleted test file and is false when loops register cases: never write it. Test-only gaps need a route, not a rework round: an untested extra guard in a file no later task owns: ENDORSE, route its test to the next task on the same seam by a fileScope line, must-fail there. A batch of checker-strictness survivors when the next task does not share the seam: an insertion-only scope amendment for the round that runs anyway, with exact fixtures and a base-file control. In the LAST task: ENDORSE, owner residual folded into the next spec reopening the module, a qa-final must-fail per entry, verbatim test-only RAs the orchestrator may bind. With parallel worktrees, split routed items by file so no two parallel tasks edit the same checker file.
16. **Regression-guard survivors in a file that freezes at this PASS.** A survivor narrowing a property class (a Unicode property replaced by categories) is no REJECT, even on a critical rule, when the verifier proved the current bytes on every member (exhaustive enumeration through the real function plus a real build), the file joins the freeze hash baseline at merge and another gate already rejects the reachable forms. Record a follow-up. Check whether a hygiene gate rejects the probe source (raw non-ASCII fails the ascii rule) before accepting a "reachable residual".
17. **Orchestrator-approved deviations on a refuted premise.** When the orchestrator approved a departure from a card bullet for a factual reason a verifier then refutes and every criterion still holds: ENDORSE, return the decision with the refuted premise and the cheapest restoring path (a later task's one-line fileScope amendment). Scope is the orchestrator's. Scratch-layer assertions pinning such a decision are re-pointed before qa-final re-runs them.
18. **Survivors killed by a gate grep.** Before judging an "informational survivor", check whether a common-directive gate check rejects the mutant (a clock grep that must print exactly one `Clock.system` line rejects `Clock.systemUTC()`). Then it is gate-proven while the grep runs in every later task and qa-final; feed a test-pinned follow-up only if high-risk under rule 3. Exception: when a criterion says the test asserts criterion N, N's gate-grep properties (ASCII only) are test items: fold them in as RAs when a rework round runs anyway.
19. **"Covered one layer down" survivors in an integration-test task.** A flow mutant surviving an IT counts as killed when its body equals a probe in the earlier gate's schema and the rule 1 carry holds (both hashes equal now, result line on disk): diff the mutant against the `.orig`, quote its result line. A hash change makes it a qa-final re-run item.
20. **A named read-only check the verifier skipped** (a hash baseline, an `ls -lT` listing) while a broader check already shows the property: I run it myself and record it, no CHALLENGE. CHALLENGE is for a missing check needing a test run, or self-contradicting evidence. Diff every reused mutant against its hash-checked `.orig` myself. Lens 2 ordering: agent frontmatter `updated` can be off by tens of minutes; order by `ls -lT` mtimes plus copy-aside hashes. A check only in a feed-forward never reaches verifiers (they run the task block): copy every FF check into the T<n> block.
21. **Boundary twin of a fixed survivor.** When a rework kills survivor X and the verifier reports X's boundary twin (`>` vs `>=`) as "informational", judge the twin under the same criterion as X. Spend the rework round on fully specified test-only RAs (state, act, every asserted value, the mutant each must kill) and fold in other cheap in-criterion survivors of the same files. For a boolean state flag the twin of a "reset" mutant is the "set" mutant; each flag value is its own region (parameterize). The line stops at the twin: an offset shift inside a region that already has a witness, or a one-sided spelling (`stripLeading`), is no failure when production holds no such guard; route the witness into the next task's data at the same seam. My RA skeleton should sit 2 or more inside the region so the `-1` twin dies too.
22. **A verification task that finds a product defect outside its fileScope** is ENDORSEd, not REJECTed, when the record discloses it truthfully, the verifier reproduced it and the orchestrator assigned a fix task. State that the ENDORSE certifies the verification, not the failing property; the fix task and qa-final close it live and refresh every record line and screenshot it makes stale. A qa-final report-only observation (a reload during a held order) is a Gate 2 residual, not a fix task, when it lies outside every criterion's scope, behaves the same on the base and its real fix needs a product decision: name the decision and options.
23. **Environment-only survivors and bounding the escalated round.** A survivor that differs only when a file descriptor itself fails, under a concurrent writer or a double fault, whose harm lies outside the criterion's protected property, is struck under AMEND to a follow-up plus a final gate grep (the `rm` twin of a killed `cp` restore failure stays, rule 18). Why: each round's new code yields a narrower mutant class. The escalated round gets a closed RA list, production hash-pinned, insertion-only tests, a re-run of only the batch whose cases changed, and FAIL grounds limited to unmet RAs, regressions, drift or a defect witness. An impl artifact stamped after the verdict is no lens 2 finding when every gated file's mtime predates the verifier's run start and its hash equals the verifier's final hash. Write "insertion only" bounds "modulo trailing whitespace" (`.editorconfig` trims it).
24. **Classing nits in authored docs and rehearsal rows.** A false statement in the task's own file is a FAIL when it can change what the reader does or concludes (provenance claim, code-naming rule, locale equivalence, a literal compared with output). A clerical pointer contradicted by its citing documents, an incomplete summary list whose omitted item carries its own label, or an omitted step whose row keeps a working judge is a correction follow-up, not a late-round REJECT. Ask the verifier to class each nit; check the environment the product really uses before accepting an environment nit (shell-form hooks start with `sh -c`); require known-false lines fixed by an appended correction.
25. **A live check whose data cannot discriminate.** A journey comparing page figures with the API proves nothing about "server figures, not the estimate" when seeded data makes both equal. ENDORSE when the verifier discloses it and names the discriminating unit witness, which I read; in a final brief ask for that witness by file:line. Isolation premises: never "one named container", never "full `docker ps -a` identical" (parallel cycles). Write: names-only listings before and after, own container absent after, every diff name quoted as foreign (reported, never touched), the shared container's `State.StartedAt` identical.
26. **"Same wording elsewhere" in a comment-fix task.** Tell a class claim (a code-formatted class named as the rule's holder, false) from a layer claim ("the flow owns it"), and grep earlier plans for a criterion pinning the wording. A pinned, true layer claim is no blast-radius gap: ask for a "checked, consistent" line in bug.md. For a pack-wording bug grep all of `docs/spec-pack/` myself; a hit outside the authorised lines is a question to the orchestrator plus a qa-final attribution item. Build a final-brief "expected hits" list by running the grep myself and attributing every hit.
27. **Probabilistic concurrency witnesses.** A latch-and-threads test against a removed `synchronized` is killed in some runs and survives in others. Count all runs across rounds, apply the pre-declared three-run rule literally, do the inspection myself (shared state private, touched only inside the guarded method). ENDORSE, pin the guard with a qa-final gate grep. Optional deterministic witness: a test `Clock` whose `instant()` records the maximum threads inside it while waiting on a latch nobody releases, asserted to be 1. Never spend a rework round on it.
28. **Constant-only production diffs.** A changed `static final` primitive or String literal is inlined at use sites: JaCoCo has no probe on that line, so "coverage not measured" is no lens 1 gap. Evidence: one must-fail probe per neighbour value (n-1, n+1, old value, unbounded) plus hand-off probes one layer down.
29. **Skipped dev-mode walk (verifier definition 6(b)) on a UI fix.** For a mapping-only change in an existing render path (no new component, hook, list or DOM) whose component test renders the real page under the setupTests console trap: ENDORSE and move the walk to qa-final as a required item (Vite dev, fresh context, `page.route` with the real server body, console dump), not a CHALLENGE. A new component or list is a CHALLENGE. `page.route` needs no backend.
