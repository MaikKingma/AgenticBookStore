When acceptance criteria are graded by a checker the team writes itself (structure, coverage, hygiene, contrast), the checker is production code AND the oracle for every later task: tier the checker tasks critical. Siblings: [[qa-docs-site-content]], [[qa-live-page-addition]], [[qa-ci-config-specs]].

1. **Input probes are not enough.** "An em dash in index makes check fail" proves wiring, not the rule's edges. Add mutation probes on the checker source (rule returns no errors, comparator ignores order, count guard removed, whole-file instead of section-scoped search) that `node --test` must kill. Prove test discovery: a throwaway failing test in the discovery pattern must turn `npm run check` red (catches `;` chaining and zero-test globs); `node --test` exits 0 with `tests 0`, so put a criterion on the harness task that check fails on zero executed tests. Lockfiles hold third-party names (`postcss-lab-function`), so a word ban must exempt the top-level lockfile by exact path.
2. **Freeze the oracle.** Content tasks hash every checker file against the last gated baseline (a hash chain), not only a fileScope rule. A later fix cycle makes old hash files stale: rebase on `git show <spec-base>:<f>`. A dropped feature may name an artefact the site never had: grep the checker for a pin and tell computed counts from fixture expectations. A pack-derived allow-list inherits pack text a decision left stale: pin it after the freeze.
3. **Frozen self-tests must not read the content tree.** "The real guide passes" tests that read live `docs/` freeze the content with the checker. Before the freeze baseline, grep checker tests for reads of the content dir and move them to a committed byte-equal snapshot. A later flag-removal task (marker ban) collides with the snapshot: make it an opt-in the CLI sets on its default root, scoped to `<root>/docs`.
4. **Coverage-manifest gaming.** Witnesses: a snippet only inside `{/* */}` or `<!-- -->` must not count; a command only in prose inline code must not count when `kind: command`; a snippet present but in another section must fail; a pack line plus an appended command must fail (whole-line equality, not `includes`: manifest command entries are substring matches, so `which jdtls-lsp` passes). Guard silent exclusion with an independent literal sweep (every code span and fenced line of the source ranges, diffed against manifest plus manual rows); exclusions need a named pin. Snippets shorter than 8 chars match anything. A source-text manifest forces Markdown-exact wording: hand implementers the forced forms at the freeze checkpoint. A rendered cross-check must delete whitespace, backticks and `|` on both sides. A deny term added in task N for text a later task removes turns N red: check every new ban against the remaining tasks' text.
5. **Plan-parser witnesses.** Reword only the continuation line of a wrapped source bullet or Goal (kills first-line parsing); drop backticks (kills markup-stripping normalisation); a heading with two parentheticals needs the last one; an in-section `(8 min)` must not be accepted as the level time; the source may quote the anchor phrase elsewhere (a table cell), so a count guard needs a sixth-block probe. H1 and heading rules skip fenced code (bash `# comment` lines are not headings).
10. **Shape rules are not count rules:** a rule validating a Checkpoint's shape passes a page with none. Put per-page block counts into the content verifiers' rendered assertions with one must-fail retitle mutant. Before sending an anchor or markup form in a directive, read the skeleton and the checker constant that pins it. Run any author alphabet over the grammar's pinned strings (a colon in exact track labels); exempt exact strings, never a character. A count of 0 is valid when every candidate is barred by the grammar; pin it by add-one.
