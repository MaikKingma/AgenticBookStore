Traps that recur across specs in this repo. Write them into every qaDirective that touches them.

1. **"Clean working tree" before the gate.** Nothing is committed before the QA gate, so the tree always holds the impl's uncommitted changes. Never ask for an empty `git status`. Ask for `git status --porcelain` plus `shasum -a 256` of the probe-touched files, identical before the first probe and after the last restore. Verifiers have read-only git: they restore with Edit, `cp` or rm, never checkout or stash.
   **Why:** a literal "clean tree" criterion cannot be met. Plan drafts also write it into impl criteria ("restored with `git checkout`"): impl agents have read-only git too. Flag it at Gate 1 with the snapshot rewrite.
   Same family: "no file outside <scope> changed on the task branch" is broken by the orchestrator's mandated plan.md `pr:` bookkeeping commit. Write "no product file outside <scope>" (diff minus `agent-os/`, `.claude/`).

2. **Path-reference ban vs `.gitignore`.** The team rule "no file references docs/spec-pack, agent-os, .claude, CLAUDE.md" (spec 09 strips them from `main`) collides with the root `.gitignore`, which keeps its `.claude/...` entries: every grep gate needs that exemption spelled out. In the spec PR diff on `factory`, agent files ride along (`.claude/agent-memory/**`, `agent-os/specs/**`), so whole-diff greps for qa-final run on product files only (diff minus `.claude/` and `agent-os/`); agent-file hits are findings for the orchestrator. The harness MEMORY.md index format uses em dashes.

3. **A probe must fail for the stated reason.** Make the verifier quote the failing assertion or exception line. A missing-migration entity without `@Id` fails as a mapping error, not schema validation; a compile error is never a negative control. Deleting a handler method a unit test calls directly is a compile error: write "advice live" probes as annotation removals (`@ExceptionHandler` dropped, method kept).
   Before listing a must-fail probe, check it is not an equivalent mutant: a view controller added on a path an annotated controller owns never runs (`ViewControllerRegistry` order 1 behind `RequestMappingHandlerMapping` order 0; a method mismatch answers 405 without fall-through). Write it as `registry.setOrder(-1)` plus the registration.
   Probe restores through the Edit tool can leave a stray form (the tool trims trailing whitespace in `old_string`/`new_string`), contaminating the next probe. Direct verifiers to check `shasum` against snap-before after every restore, quoted per probe. Better: restore by `cp` from the `.orig` copy (item 20), then `shasum`.

4. **ArchUnit vacuity (allowEmptyShould everywhere).**
   - Every rule passes on empty packages, so the production run needs negative controls: a violating class in a real layer package, and a root-package class touching domain.
   - The self-test's production sanity check must read `@AnalyzeClasses` reflectively (a hard-coded copy misses a package typo). String-typed predicates (annotation FQN, package names) are silently vacuous when misspelled: only a fixture-backed per-rule case catches that.
   - "At least one violator per rule" is too weak for a rule with several package strings (`jakarta.persistence..` plus `org.springframework.data..`): one violator per string. `areAnnotatedWith` matches direct annotations only; `areMetaAnnotatedWith` also matches direct ones: decide at strategy time.
   - Never write "failure details contain the expected FQN": details name origin AND target, and fixture chains across layers make a designated violator the target of a neighbour rule, so a one-token layer swap survives. Ask for an origin-anchored match (first `<...>` token starts with the FQN) plus `getDescription()` pinned per rule (also catches shared-instance stacking and allowlist or suffix widening).
   - Completeness by reflection over `@ArchTest` fields misses `@ArchTest` methods: add "declares no @ArchTest method". Layered descriptions render `where layer '<name>' may ...` and the layer definition lines also contain `layer '`: count or pin `where layer '`, never the bare token.
   - A parameter predicate ("any parameter is double or float") needs four position witnesses, each its own fixture class (the origin regex accepts any member of a class): lone parameter (kills `size() > 1 &&`), first of several (kills `skip(1)`), middle of three (kills last-only and first-only), last (kills first-only); keep multi-parameter fixtures too (a single-parameter fixture lets an exact-list `haveRawParameterTypes(double.class)` pass); include a method and a constructor. Pin all four in the Gate 1 fixture wording.
   - "Not reported" controls must be origin-anchored too: a control class that is the TARGET of another fixture's violation fails `noneMatch(detail.contains(FQN))` on correct code. When one fixture carries several witnesses (depth-1 and depth-2 nested types), anchor by member (`^Field <FQN.field>`). The production import is a free control for widened predicates when real code already uses the excluded shape.
   - A predicate walking the enclosing-class chain ("nested at any depth in a class named *X") needs a member-anchored witness per position of the matching class, not only per depth: direct enclosing only (kills top-only), middle only (kills direct-or-top), top only (kills direct-only), depth one past any cap you probe, a class named exactly `X` (kills a `.+X` regex), controls for letter case, a longer name and the class's own name. Each control asserts its field type first (an `Object`-retype probe proves it). A walk cap at or above the deepest fixture is unkillable: do not list it as must-fail.
   - A CompositeArchRule repeating one package list per half needs every occurrence falsified: a fixture per package per half, or a per-half description pin. A set comparison over the whole description hides a drop from one half.

5. **Framework warnings vs task sequencing.** "Green with a framework warning = FAIL" collides with skeleton-first specs: the first task's referee prints warnings later tasks fix. At strategy time give every expected warning an owning criterion. Known on this stack: Mockito inline-mock self-attach on JDK 25 (fixed by a Surefire `-javaagent` argLine), JPA open-in-view, Flyway "No migrations found", Maven `prefixes.txt` 401 warnings (from repositories in the pinned flyway-parent POM, not machine-local). Put a warning-inventory item in C0: every warning quoted and classified as fixable here (FAIL), owned by a named criterion, or unowned (flag it).
   **Why:** otherwise verifiers wave warnings through as "environmental" and no task fixes the unowned ones. A test provoking a constraint violation makes Hibernate log `HHH000247 ... SQLState: 23505` as WARN; the same holds for any server WARN a negative-path test provokes (Spring AI `ToolInputValidator ... required property 'query' not found`). Pre-classify at strategy time as accepted only at an exact count with its key, so a second, real one cannot hide behind it.
   Warnings emitted once per context (Spring AI's three BeanPostProcessorChecker lines per MCP-scanning context) scale with context count: write the expected count as a multiple of a per-context marker (`Registered tools: 4`), never "unchanged afterwards".
   The inventory grep is `warn|deprecat|self-attach` (Mockito's "self-attaching" line has no "warn"). In a final brief never write an allow-list from one test class's log: a full referee prints ~130 hits (deliberate error-path WARNs, npm `install-scripts`). The bar is a base referee in a throwaway worktree plus a normalised multiset diff (timestamps, PIDs, threads, `.m2` path): 0 added at the tip. JDK once-per-JVM notices (JDK 25 `sun.misc.Unsafe::objectFieldOffset` from byte-buddy) appear at the first test taking that path, so a new plain `@Mock` test class adds them: allow them only when a control (same run with the fix's production files reverted) prints them after the same `Running` line and a run without that class prints none.

6. **Frontmatter timestamps are hand-written.** Agents' `updated`/`created` values have run minutes ahead of the real write. Prove "the referee ran after the impl finished" with `stat` mtimes (impl artifact, last product file, Surefire XML) and direct verifiers to do the same.

7. **Scope argument instead of a directive item.** Verifiers skip global greps as "untouched by this diff". Accept only with a quoted scope proof plus my own cheap confirmation, and direct them to execute every global item literally. A task block naming a subset of the common items ("Greps on the file: C0-5a, 5b, 5k") reads as a replacement: write "in addition to all of C0-5".

8. **Probes that remove a file need `clean`.** `./mvnw test` without `clean` keeps a moved migration or deleted probe class in `target/`, so the probe passes falsely or fails for the previous one's reason. Write `clean test -Dtest=...` into every probe item. A restore by `cp -p` needs it too: the restored source is older than its class file, so the incremental compile skips it and the run tests stale bytecode (check `Compiling N source files` in each probe log). Surefire `-Dtest`: `+` joins methods of ONE class, classes need `,`; `A#m1+B#m2` silently runs only A; `A+B` runs ZERO tests with BUILD SUCCESS (grep my own directive for `+` before sending). Pin the expected `Tests run:` count of every selector. A class with JUnit `@Nested` classes prints `Tests run: 0` for the outer class and the outer-plus-nested sum on the last nested class: pin per-class counts from the Surefire XML testcases and pre-explain the 0 line in a final brief.

9. **Shared test-infrastructure hooks need a guard test, not a code-review fallback.** A "report whether removing `@BeforeEach` fails a test, else inspection" item leaves the hook unguarded, and once accepted at strategy time I cannot REJECT later. Demand a guard: a `@TestInstance(PER_CLASS)` subclass seeds a row in `@BeforeAll` and its test asserts the row is gone. FK-linked tables truncated in ONE statement do not need CASCADE, and CASCADE masks a partial table list: require an unlinked table.
   A Vitest console trap (`expect(calls).toEqual([])` in `afterEach`) is the same: its only effect is a failure, so deleting the expect, or collecting after `restoreAllMocks`, survives every committed test. Vitest flips `test.fails` AFTER `afterEach` and runs `onTestFailed` before the flip, so the guard is `it.fails` per console method with an `onTestFailed` capture of the error messages, plus a next test asserting the trap message. Write it WITH a named exemption from the C0 `.fails(` grep (otherwise the grep blocks it and the gap becomes a residual). The trap does NOT see jsdom's virtual console: `Not implemented:` (a submit without `preventDefault`) goes to raw stderr and the test passes. Guard that class with a `Not implemented` grep on a log capturing stderr, plus pins such as `defaultPrevented` from a `document` submit listener.

10. **Verifiers of one session share one scratchpad.** Generic evidence names (`referee.log`, `snap-before.txt`) get overwritten by the next task's verifier. Put "task-prefixed scratch file names, cited by absolute path" into C0; in reviews check the evidence file's mtime against the verdict. Task prefixes collide across specs in one session: prefix with the spec number too (`s03-t1-qa-...`), and for helper scripts in `.claude/comms/tmp` as well. The orchestrator's verifier prompt can override C0-1 with a short prefix: in each review copy the hash baseline into the ledger and ask for the spec-prefixed form next time. `rg` is not on PATH inside `bash <script>` runs (exit 127): direct every `rg` item to run in the Bash tool itself. Never write `rg -E`/`-niE` (`-E` is `--encoding`: exit 2, empty stdout); alternation needs no flag; "nothing" means exit 1 with the control exit 0, and exit 2 is a failed gate.

11. **Annotation greps match Javadoc.** `grep '@'` hits `{@code ...}`. Use `grep -nE '^\s*@|^\s*import '` and read the files; the class-file check (`javap -v`, no `Runtime*Annotations`) misses SOURCE-retention annotations. `\s` works in macOS `grep -E` but silently matches nothing in `git grep -E`: write `[[:space:]]` in any `git grep` item with a control that bites; `\b` fails the same way (use `-P`). Put patterns in single quotes (in double quotes `[&\\]` collapses to `[&\]` and macOS grep swallows the next alternatives). Log and source greps: no bare numbers (`401` matched Maven metadata and timestamps), no short unanchored words (`topp` matched "stopping"): write every term grep with `-w`, dry-run the literal C0 text on the base log and tree, and make each script grep print `rc=$?` next to its expected rc. macOS `grep` has no `-P`: a non-ASCII check in a script is `LC_ALL=C grep -c $'[\x80-\xff]'` with a positive control that prints (a handed-over script's `grep -P` exited 2 and the dry run read the usage error as "nothing"). Typed directly into the Bash tool `$'...'` arrives unexpanded: there use `git grep --no-index -c -P '[^\x00-\x7F]' -- <files>` (also reads ignored files).

12. **CI run ids in a qa-final brief.** Ids handed over by the orchestrator can belong to a task branch, not the spec tip. Never write run ids; write `gh run list --commit <full 40-char sha>` (a short sha returns `[]` without error) and `gh run view <id> --json headSha`. The `pull_request` run's `HEAD is now at <sha> Merge <tip> into <base>` line proves the merged tree. PR body checks: the attribution footer holds U+1F916, so write "body prose ASCII, the prescribed footer excepted".

13. **Base moved during the cycle.** An owner commit on the base breaks `merge-base --is-ancestor`. The fix is a merge into the spec branch (never rebase or force-push). Re-run the tip-identity items (referee and counts, hash checker, greps, git facts, PR readiness, CI on the tip). Carry the rest forward by patch identity, not name-status (a base delta with product files fails a "no product file" rule literally): `git diff OLDBASE...OLDTIP -- P` equals `git diff NEWBASE...NEWTIP -- P`, and `git diff OLDTIP NEWTIP -- P` equals `git diff OLDBASE NEWBASE -- P` (the merge took the base bytes), each with a control that can fail; plus the base delta disjoint from the spec's files and from the live checks' request paths, and inserted base tests that write nothing for an order-independence carry. Re-derive every directory-wide grep's expected output on the new base and attribute each new hit with `git grep` on both bases. Fast carry per path: blob identity `OLDTIP:f == OLDBASE:f` and `NEWTIP:f == NEWBASE:f`; for a file both sides touched compare patch-ids of `git diff -U0` (with context the ids differ); for a conflict-resolved doc a whitespace-insensitive token diff (`tr -s '[:space:]' '\n'`) plus hashes of the untouched head and tail. Unscoped gates catch base noise (a skip-construct `-G` hits a curated memory note, a substring env-var gate hits a superstring): scope with the product pathspec and `-w`. Put a base-ref check (`ls-remote origin refs/heads/<base>`) at the start and before PR readiness. A mid-cycle merge also stales every cited pack line in directives, scratch layers and manifest labels: before the next verifier runs, map old to new from `git diff -U0 <spec tip> <merged>` per pack file and re-point each range (heading anchors survive, line labels do not). A frozen-hash chain over pages also needs "the merge changes nothing under the site folder" checked on the merge commit. The finalize commit moves the tip again: repeat the tip checks before the human merge.

14. **Integration integrity at the final review.** Record each task's sha256 baselines in the ledger matrices; at final-review hash the gated files at the spec tip and compare: one command proves squash and base merges altered nothing a gate reviewed.
   Verifiers write baselines in mixed forms (absolute and relative paths, `git status` header lines) and rework rounds supersede entries. So C0-1 must ask for repo-relative `shasum` lines only; every round (docs-only included) writes its own `-r<k>-hashes.txt`. In the brief, name the authoritative file per task, state the exact count of expected superseded FAILED lines, and dry-run the check yourself (filter `^[0-9a-f]{64}  `, strip the absolute prefix). In the same script compare the sorted union of baseline paths with the product files of the spec diff (minus `.claude/`, `agent-os/`): an empty `diff` proves every shipped file passed exactly one gate. Hash committed bytes at qa-final, never the working tree (inside the fresh clone, `git show <tip>:<f>` piped to `shasum`, or a `git archive <tip>` extraction when git writes are barred).
   Planned test names in a shape.md scenario map go stale in most tasks: require each implementer to update its rows (or declare the outbox map the record) and dry-run a `void <name>(` grep before the brief, with digits in the name regex (`[A-Za-z]+` skipped every `...To409`).
   Write the dry-run checker as an argument-driven script (root, tip, base, SP) in SP and hand it to qa-final with expected output lines. Verifier scripts a brief reuses (replay drivers, mutant makers, start scripts) hard-code the worktree path and task-prefixed names: direct qa-final to copy each to a final-prefixed name with a quoted `diff`, or a rerun overwrites gated per-task evidence. Every script section must print a count or an assertion with its expected value (a last check `git diff --name-only A B > /dev/null` checked nothing); write intersections as `comm -12` of two sorted lists plus `wc -l` (expect 0) and a control that prints.
   Free negative control: the same command with the last task's parent commit as tip must exit 1 with exactly that task's lines FAILED. A passing hash check also carries production mutation probes (ArchUnit P-prod included when the import uses `DoNotIncludeTests`), so qa-final can run with zero repo edits. When a gate wrote no hash file, its probe snapshot is a valid baseline only through a per-task path allowlist in the checker; a line superseded by a mid-spec base merge becomes a pseudo-baseline from the amendment's recorded hash, or from a later task's start snapshot whose directive pinned the file unchanged against its PR base, plus a patch-identity check of the earlier task's `+` lines. Dry-run any "every fixture file is read by a test" focus item before briefing it: request halves of captured error pairs are often unread.

15. **Test data that cannot falsify the criterion.** Moved to [[qa-test-data-falsifiers]] (combined filters, order claims, sorts and tiebreaks, pass-through and default values, clocks, regex witnesses, UUIDs). Read it before writing any falsifier list.

16. **Backslash-u escapes do not survive tool parameters.** A Java escape for U+2003 typed into a Write or Edit parameter lands on disk as the literal character, a double backslash as two backslashes. Writing the backslash as its own escape (`u005C`, then `u2003`) lands the ASCII form. Read output shows a literal U+2003 as a plain space: only `od -c` or `rg '\x{2003}'` tells the forms apart.
   **How to apply:** state a required form as an imperative in the plan text, not a parenthetical. The decided form is a code-point constant (`Character.toString(0x2003)`), checked by `rg -n '[^\x00-\x7F]' <file>` printing nothing plus a positive control file. In reviews check the form with `od -c`, never by reading.
   The reverse also fails: Edit cannot match a line holding literal U+2003 in `old_string`, so an implementer fell back to `perl -i`. When a plan asks to replace literal non-ASCII text, name an allowed method in the implDirective (Write of the whole file after Read, or a sanctioned one-line script followed by a diff check).

17. **Implementers probing production in rework.** A test-only implementer whose round failed on a surviving mutation tends to re-create the mutant in the production file, even inside its own fileScope and even after declining in round 0; integration-test implementers do it in round 0 on production outside their scope. Put into every test-only task's implDirective: "Never edit a file outside your fileScope, not even temporarily; mutation probes on production code are the verifier's job (describe the mutant in your outbox)." Judging rule: [[review-calibration]] item 11.
   Before feeding that sentence forward, read the task's implDirective: a test-only bugfix whose red run needs a production probe (a probe clock in a config class) has a plan-mandated implementer edit. Word it "except the probe(s) the plan names, SHA'd copy, one run each, restored byte-identical".

18. **Request collections (`http/*.http`) differ from the E2E inputs.** The file's sample values (hyphenated ISBN on a successful add, lowercase genre, `q` combined with a filter) are often not what the integration tests send, so "proven by E2E" does not cover the file. Diff the file's inputs against the E2E calls and name each uncovered combination as a smoke item. The smoke must replay the file's own bytes (bodies cut with `sed -n`, sent with `curl --data @file`), never re-typed requests. Preferred form: a `python3 -I` driver that parses the file into its `###` blocks (method, URL, headers, body line range, ids from `client.global.set` handlers) and writes one evidence file with a CHECK line per expectation. A JSON witness body cannot carry a raw tab (`\t` escape, check on the decoded value). `ijhttp` is usually absent: the `> {% %}` handler syntax stays an inspection-only residual. Smoke expectations come from controller annotations or asserting tests, never from the impl artifact's request table (it wrote 201 for a 202 add). Request comments stating results (a total, stock left, a status) and header claims about data or folder ("every ISBN in this folder is unseeded", "each file once per database") are claims: write each into the directive per statement across all files, or verifiers file them as advisory. A comment-fix criterion worded "line N reads X" silently deletes every other sentence on that line: write "the sentence S becomes X", and check whether a later count task loses or gains files. When a collection's inputs change, grep other tasks' tests for constants naming them (a census constant went stale). A replay driver is itself a falsifier needing negative controls: mutated copies of the file in SP (EAN swapped for another availability, boundary value moved, capture handler removed, query changed), each driver run exit 1 with its reason (ask for it). A swap value must reach the property: one already used earlier in the file fails at the add with a 409; pick a census-checked value absent from the file and the remote catalogue (the remote then refuses it, so an earlier log witness of the same cause fails first: write "fails at the pending check or an earlier check with the same cause, never at the add").
   Before writing a field expectation on a live remote read, read the remote's response record: the distributor stores `retailerReference` but never echoes it and offers no order list. A disclosed recording forwarder (base URL pointed at it, status and body relayed verbatim) is accepted evidence for outbound bodies and call counts; it leaves the default base URL and direct wire framing (chunked bodies) unexercised, so name one forwarder-free run for qa-final.
   With `spring-boot-docker-compose` on the classpath, `spring-boot:run` starts `compose.yaml` and stops it with `stop`, not `down`: a stopped leftover container returns old rows, so "exact search result on a fresh database" fails for the wrong reason. In the smoke preflight check `docker compose ... ps -a` and `down` any leftover first. Use the smoke to close inspection-only residuals cheaply (constraint names via `pg_constraint`, untested query parameters, null-list guards).
   PostgreSQL 18 catalogues NOT NULL as `pg_constraint` rows (contype `n`, `<table>_<column>_not_null`): an "exactly these constraint names" query needs `and contype <> 'n'`; the `n` rows are a free nullability witness. A "no content type" live probe needs `curl -H 'Content-Type:'` plus `-v` proof (plain `curl -d` sends form-urlencoded). A live app answers malformed JSON with Boot's error JSON (`timestamp, status, error, path`), not MockMvc's empty body: word accepted defaults per layer.
   Brief expectations that are counts (files per kind, test classes per annotation) come from a dry-run command, never mental arithmetic: ArchUnit classes hold `@ArchTest`, not `@Test` (use `@(Test|ArchTest)`); count subclasses with `grep -rln "extends <Base>"`. Quote each count as a `grep -c`/`wc -l` result, not by reading a listing (a brief said 35 OK where the checker printed 36, and 44 files where the diff had 37). An "empty snapshot expected" is false when my own memory edit sits in the tree: write memory before the dry run, or name my agent files as expected.
   The same for every C0 grep a brief calls "empty": dry-run each one, not a subset, and when carrying a C0 block into a new spec also run each grep against the lead's design calls (a wall-clock test grep would have flagged the design's `LocalDate.now(clock)`). A grep pinning one spelling while a guard item demands a second read of the same thing is passed by an equivalent spelling (`LocalDate.ofInstant(clock.instant(), zone)`): grep the read itself (`now(`, `ofInstant(`, `clock.instant()`) and list expected statements by file. A fix cycle merged mid-spec shifts every C0 baseline (test totals, warning counts, grep outputs, hashes): re-record on the post-merge tip before the next task. The whole-tree non-ASCII grep hits the intentional Arabic-Indic digit witnesses in `domain/IsbnTest.java`: write it as "exactly these pre-existing lines, fileScope files empty". Warning baselines come from a log grep, never an impl count.

19. **Shared test base changes and failure devices.** Adding an `@Import` or `@MockitoSpyBean` to the integration base changes the context key; if any full-context class does not extend the base, the Started count jumps by one: check `extends` on every `@SpringBootTest` class at strategy time. A test-only failure device (rollback thrower, spy `doThrow`) needs its own non-vacuity probe: swap in the weak device (plain `@EventListener` thrower without `@Order`) or break the `@Transactional` boundary, and the scenario must fail.
   Never write the boundary probe as "remove the class-level `@Transactional`": it also keeps the session open for lazy loads (`BookJPA.authors`), so every request dies with LazyInitializationException before any write and cannot tell "rolled back" from "never written". Write `@Transactional(noRollbackFor = RuntimeException.class)`; a `REQUIRES_NEW` on one save works only when its rows reference already committed data. Under that probe a BEFORE_COMMIT listener thrower still rolls back (Spring rolls back on a commit-phase exception), so the device scenario needs its own probes: toggle ignored, plain `@EventListener`, recorder on AFTER_COMPLETION.
   After-commit listener feeding a REQUIRES_NEW delegate: a business failure before publish (409) proves no phase; the must-fail set is REQUIRED delegate and AFTER_ROLLBACK (killed by the visible side effect) plus AFTER_COMPLETION (killed by publish-then-rollback via `failBeforeCommit`). A plain `@EventListener` probe blocks on the row lock the outer transaction holds (exit 124): always informational, with a budget. `NOT_SUPPORTED` and `fallbackExecution = true` survive every IT; only reflection pins kill them. An escaped listener exception is logged by `TransactionSynchronizationUtils` as a fixed ERROR line ("afterCompletion threw exception"), a blank line, then `<Type>: <message>`: ask for one pattern `ERROR .*afterCompletion threw exception\R+<Type>: <literal>` plus `containsOnlyOnce` (it also kills a `noRollbackFor` delegate, whose next line is UnexpectedRollbackException).

20. **Rework diffs need the gated bytes on disk.** Snapshots hold only hashes and untracked files have no git copy, so a rework verifier must reconstruct the earlier test file. Put into C0: "at snap-before, `cp` each fileScope test file to SP as `<prefix>-<File>.orig`; a rework round diffs the current file against that copy". The hash match proves any reconstruction, which is valid but expensive.

21. **Boot initialises logback once per JVM.** `LogbackLoggingSystem.initialize` returns early when logback is already initialised (Boot 4.1.2). An in-process `SpringApplicationBuilder` test (STDIO profile) in the shared Surefire fork keeps the console appender of an earlier cached context, and logback writes through the swapped `System.out`: the outcome depends on class order. Demand green runs with `-Dsurefire.runOrder=alphabetical` and `reversealphabetical` plus the class alone, and a non-empty precondition on any "every captured line" assertion. Surefire XML `<system-out>` holds the same console bytes: it attributes Started lines but never recovers silenced ones.
   Never predict which class runs first: Surefire sorts by fully qualified path, so a top-level `nl.x.HealthEndpointTest` (upper-case `H`) sorts BEFORE lower-case subpackages and runs LAST under `reversealphabetical`. Dry-run the order from a previous log's `Running` lines; to make one class start a shared context write `-Dtest='A,B' -Dsurefire.runOrder=alphabetical` with A first by FQN.
   The Spring AI STDIO recipe's empty `logging.pattern.console` makes logback print `|-ERROR in ch.qos.logback.classic.PatternLayout("") - Empty or null pattern.` on stderr at every logging init: Boot 4.1.2 always starts the console encoder, and `logging.threshold.console: OFF` filters events only (a lead premise saying otherwise was false). Pre-classify the line at strategy time (exact text, count = STDIO starts proven by the STDIO log's Started lines, stderr only), or have the spec drop the empty pattern. The exact count also guards the test's logging preparation (a leaked property doubles it, a skipped `cleanUp()` zeroes it). Harness restores (system properties, `System.out`) show only in cross-class counts.
   A README criterion "every command was run" must exclude commands writing the user's tool configuration (`claude mcp add`): check them against `--help` plus the live-proven URL and arguments; prove the client connection with a headless `claude -p --mcp-config <tmp> --strict-mcp-config --output-format stream-json` run (init event: server connected, tool list; a tool_use event). Pre-authorize a `--model <name>` retry for a 429 on the default model (a flag, no config write) and require the model id in the record.
