Write these into the directive of any task or spec whose evidence is a GitHub Actions run. Siblings: [[qa-final-brief-integrity]], [[qa-docs-checker-oracle]].

1. **Job summaries are not readable from the CLI.** `gh run view --log` lacks them, `.../jobs/<id>/summary_raw` answers 404, there is no REST endpoint, and they are hidden from logged-out viewers (anonymous playwright-cli rendering cannot work). A criterion on summary content needs a signed-in channel decided at Gate 1: the owner connects Claude in Chrome (`/chrome`), or a human capture is planned (copied text plus a screenshot showing the URL). Add `gh api .../check-runs/<job_id>/annotations` for per-test messages. If no channel is certain, offer the agent-checkable narrowed form (per-module log lines equal to the console totals, annotations, artifact, the red job) and mark the summary unverified; step log lines and `checks: write` check runs are not substitutes.
2. **Baselines and timing.** Job-duration noise (verify 41 to 62 s) exceeds single-digit-second gains, so "faster" criteria gate on mechanism (log line counts per run) plus a low-noise per-run metric, with baselines recomputed by the same script; never write a baseline number from research prose (a minimum was quoted as the median). Before fixing a baseline run set for a timing gate check the runs are the same suite (per-module `Tests run:` totals); add a same-suite control run (the previous task's green run). Research counts of log events need the exact text the tool prints (setup-java prints `maven cache is not found`) and a restatable run set, else "not recomputed".
4. **Log greps.** The harness refuses `rg -F` on `${{ }}` strings: direct byte-compares into a `python3 -I` script with a one-space negative control. The warning grep for CI logs includes Maven/JVM lines (`\[WARNING\]|WARNING: | WARN `) compared by count with a baseline job log, not only `##[warning]`. Greps for a `run:` step's output anchor on the Actions timestamp prefix (`Z <text>`): the step header echoes the script source, inflating a plain count. A "runs in the background" claim is proven by the step's run-JSON duration (0 s) against the work's own duration.
5. **Hang path.** A job timeout, a manual cancel and a supersede all make `cancelled()` true; only a step `timeout-minutes` below the job's ends as failure: gate on the step-timeout annotation plus the absence of the job-timeout one. A hung test writes no `TEST-*.xml`, so never gate a hang on the junit report. Red/green probe pairs: green differs from the gated head only by the probe test. A red recipe that lowers the job timeout must not be re-run literally on the fix: name the green-after run as the "must not reproduce" re-run and gate on `git diff --exit-code <green head> <tip> -- <workflow>`.
7. **Linux-only red on a CI step green on macOS:** suspect a Node CLI that calls `process.exit` right after `console.error`/`console.log`: over a Linux pipe the queued tail is lost (exit status kept), macOS never loses it. Directive: reproduce in a Linux container on the CI Node version, N runs before and after (23/200 vs 0/320), plus a witness on the real pipe that dies on a tail cut. A test-side fix reads the child's output through files (`stdio: ['ignore', fd, fd]`); the real fix is `process.exitCode = 1`, pinned by a static no-`process.exit(` test.
8. **`actions/cache` evidence:** gate on the post step's `Cache saved with key:` line plus `Path Validation Error` count 0, never on step success. A cache path literal in a card must be a directory the job itself creates or an explicit tool setting (`npm_config_cache`); a guessed tool default saved nothing. A pull_request run's caches are scoped to its merge ref, so a later PR only restores what a push run on its base branch saved: ask for that push run's save lines plus the later run's restore lines, and whether the hit is on the primary key or a restore-key.
9. **Deploy gates the owner arms** (a repo variable, Pages, an environment) can flip between the final brief and the sweep. Write side-effect items as "quote the state at the head and compare it with the approval record", never as fixed 404 / no-variable expectations. Armed is no PR defect, but Gate 2 must say the merge itself publishes (a release created with `--target $GITHUB_SHA` tags the merge commit once) and list post-merge checks: push run jobs at attempt 1, site 200, release asset, archive root.
