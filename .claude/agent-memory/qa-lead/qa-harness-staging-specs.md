Traps for any spec that stages files for other branches (reference solutions under `docs/spec-pack/level-branches/`) or proves behaviour with `claude -p` runs. Harness probe techniques live in the senior-research-agent memory. Sibling: [[qa-rehearsal-rows]].

1. **Root ignore patterns bite at any depth.** The root `.gitignore` has `notes/`, `*.log`, `target/`, `.env*`, `dist/`: a planned `S/notes/x.md` or an evidence `*-debug.log` is silently never committed (passes locally, missing from the PR). At strategy time run `git check-ignore -v --no-index` on every planned fileScope folder and evidence name and put "`git status --porcelain --ignored -- S` shows no `!!`" into the common block.
3. **Re-run budget for headless scenario tasks.** Verifiers re-run every zero-token check (sandbox build and verify, bash harnesses, `claude -p "/context"`, `/mcp` init, generator inits, validators) and audit expensive sessions from jsonl, transcript and kept sandboxes; one capped spot re-run (`--max-budget-usd`, `--max-turns`) per task. Demand an implDirective to keep the run sandboxes until the gate, or the audit has nothing to judge.
4. **Isolation and user-scope evidence per run.** Init event (`apiKeySource`, skills, agents, mcp_servers, plugins) plus sha256 of the user settings and plugin registry files before and after. A probe once wrote user settings through `claude plugin marketplace add`: ban `claude plugin`, `claude mcp add`, `--bare` in every script.
8. **"Refs unchanged" in a shared repo.** Parallel spec runs move `sdd/*` refs and worktree HEADs during any verifier run, so a whole-repo `for-each-ref` before/after diff is never clean. Write "no ref the scripts can name exists" (branch and tag names from the step library) plus the suite's own ref checks on TMPDIR repos; a moved `sdd/<other spec>` ref is then attributable. Once the base tag is published, compare built trees on the REAL tag: a simulate from a later source drifts by source-only changes.
9. **When agents may not run Claude Code at all** (owner decision mid-cycle), re-plan verification three ways: (a) zero-token behaviour still executed (bash harnesses, curl JSON-RPC `initialize`/`tools/list` for MCP, generator inits, validators, glob tests of rule `paths`, `./mvnw verify`); (b) static consistency by the verifier's OWN token inventory (paths, commands, skills, hooks, settings keys, server and tool names, ports) resolved on the built tree and spelled the same in spec, guide sources and code, with a misspelling negative control; (c) owner rehearsal rows with exact setup, prompt, expected observation and fallback. Isolation checks reading `~/.claude` become n/a. Without (a) verifiers drift into pure reading; without (c) Gate 2 reads unproven scenarios as passed. Static matching of permission rules is consistency, not behaviour: rows carry position variants a prefix rule misses (`git commit -m x -n`, `git -C . push`, `cat .env` via Bash).
10. **Gate regexes need the caller's real input form.** A hook grep `"command"...:"[^"]*git[[:space:]]+commit` was probed for every whitespace member over three rounds, yet every positive fixture started with `git`, so the deleted prefix (`"git`, a start-anchored hook) passed 68/68 and lets `git add -A && git commit` (how Claude usually commits) through. At strategy time list the chained form as a must-block case and a word-internal `gitcommit` as must-pass, and probe each quantified part widened AND deleted. Found in a bounded round with the task open: REJECT, closed test-only RA (protected property; not the narrowing loop of [[review-calibration]] rule 6). Bound "insert these lines after line N" as `diff --minimal` plus a head/block/tail split check.
