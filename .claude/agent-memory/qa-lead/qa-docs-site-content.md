2. **Docusaurus link checks:** the hash-router build skips SSG and link checks (exit 0 on broken links), so only the browser build is evidence. External links are never checked: inventory them at strategy time; refs a later publish creates get a deploy-gate check, every other URL one request in qa-final.
3. **Markup and axe traps:** `{#id}` heading ids do not compile under `future.v4` (use `{/* #id */}`); `- [ ]` task lists render bare disabled checkboxes that fail axe `label` (critical). Say whether "axe" means color-contrast only or the full ruleset, and give every framework violation an owning task (a local rehype plugin sits in the config, outside content and checker scopes). Line-level H1 rules miss JSX `<h1>` and H1s nested in a blockquote or list: pair with a rendered `h1` count per page.
4. **Rehype label plugins and built-HTML guards:** a text walk over `element` nodes drops inline MDX JSX text (`<kbd>`); name the witness or judge reachability through other frozen rules. A built-HTML guard passes vacuously with zero matches and a wrong default dir; when earlier CLI tests are pinned an in-checker floor breaks them, so require a quoted exact tail line (`N html files, M checkboxes`) in every later verifier. Rules on one default-dir switch collide: settle the design before the later task.
5. **Regex scanners of MDX:** each fresh-probe round finds a construct where scanner and MDX disagree about code, comments or tags. Neither a false span NOR a missed span is safe (blanked text, or a literal `</TabItem>` or `{/*` handed to the tag reader: fail-open); "end the paragraph early" is NOT fail-closed (CommonMark continues a paragraph at an ordered marker other than 1, an empty item, a `<tag>` or `{expr}` followed by text, a `|` line without a delimiter row). Cheap nets: an orphan closing tag and an unclosed or nested comment opener never build, so report them. For a rule whose truth is the rendered page, check the build in CI (`check:built`) instead of hardening the source model, and pair source coverage with a rendered textContent cross-check.
6. **Semantic source reviews of content pages:** verifiers search only the main source file and flag sourced clauses as embellishments: direct a whole-pack search first; a usage instruction derived from a cited mechanism is faithful, a tool-behaviour claim never is. Facilitator-only ranges overlap participant facts: bar facilitator-only content, accept a fact a participant line repeats. A trim-for-fit card's oracle is a word-sequence diff vs the previous bytes; a literal ban needs replacement wording that keeps the referent. Print: `page.pdf` is margin 0, a dialog about 10 mm; check both.
8. **Framework-derived and repo-relative text:** Docusaurus builds `<meta name="description">` from the first paragraph and dropped text between two colons of a pinned Goal line; no source rule sees it. Grep built descriptions of every page at strategy time; the fix is a quoted `description:` frontmatter. A class a pack prompt names may be missing only because the spec branch lags the integration branch: check `origin/factory` first.
9. **Derived prompts for pack scenarios:** when the pack gives GIVEN/WHEN/THEN but no prompt words, a fenced prompt is a valid forced form only if it restates the WHEN clause and adds no output, path, tool or flag, and the Expected line is the THEN clause verbatim. A GIVEN no page provides is stated as a precondition, never an invented setup step. Check deny-rule scenarios against the tool the rule names (a `Read()` deny does not cover a Bash read): a rehearsal item, not a page finding.
