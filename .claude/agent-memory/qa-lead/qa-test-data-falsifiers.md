Check the data of every listed test, not only its name, and write the witnesses into the qaDirective falsifier list at strategy time. Siblings: [[qa-passthrough-state-falsifiers]], [[qa-input-format-falsifiers]], [[qa-frontend-falsifiers]]. Survivor judging: [[review-survivor-rules]].

- **Combined filters:** each criterion needs a row that only it excludes (if every author match shares the genre, a dropped genre filter passes). **Order claims** ("422 before 409", "discontinued before range") need a case where both failures are present. A round trip through one mapper misses a symmetric column swap: demand one raw JDBC read of the stored row.
- **Sort and cap tests** need rows inserted out of the expected order, for every key of a multi-key sort, tiebreak included. Two errors on one field supplied in message order let a field-only sort pass. An order-preserving claim ("author order kept") needs unsorted input or an added `sorted()` survives; check pinned example values in criteria ("Jane Austen, Mary Shelley" is alphabetical).
  - Never write "neither id nor available order" (implementers avoid exactly the named columns and leave another ascending): write "sorted in no column, in either direction", which needs three rows or more (two rows are sorted one way in every column), plus one row on the producer's filter boundary so an added stricter re-filter fails.
  - "Column" means every attribute of the ordered element and its entity that the code holds in scope, not only the asserted record's fields: say so in C0-16 and list reachable attributes per sort site. Check shared fixture constants once (BOOK_1..3 had ISBNs descending in id order, so every id-order test was monotone in isbn and isbn sorts survived at four sites) and tabulate a shared constant in EVERY order the tests assert over it.
  - Exemptions per test: a column the producer's filter makes constant (`lowStock` in a low-stock list) or every write path keeps constant (currency EUR) is exempt over a real producer, never by "the domain rejects it on restore" when the read path does not restore. Elements holding a child list need a bound in C0-16: own components and accessors count; child attributes via a positional pick only when the sort already holds them flat (fetch join).
  - UUID columns: Java `UUID.compareTo` is signed on the high 64 bits, PostgreSQL `uuid` order is unsigned bytewise (ids 8 to f differ): name the comparator in every column-sequence argument and treat only a run as evidence. Cheapest fix: test ids starting 0 to 7 plus a reversal probe. Over a real producer ids are app-generated, so id-only sort mutants die only by chance (23/24 at four rows): name the slice test with fixed ids as their owner.
  - A tiebreak in `order by` on PostgreSQL cannot always be forced by data: insert the tie pair in reverse id order and pre-declare "must fail; if it survives three runs, inspection item". A tiebreak REPLACED by another column (`s.onHand`) survives when tie rows ascend in every column: demand per tie group an order reversed to every substitutable column, a substitution probe per key position, and three rows with a nullable column's null in the middle. With a fetch join the child columns are substitutable too. An index on the sort columns can supply the tiebreak: pre-declare inspection plus a final hash check of the query file.
- **"Each row once" over a collection join:** Hibernate 7 removes duplicate root entities in memory, so an exact-list test at a large limit cannot see a `left join` without distinct. The falsifier needs a SQL limit cutting into the duplicated rows (a book with two matching authors sorted first, a second match, limit 2). On PostgreSQL, removing an HQL `escape '\'` clause is equivalent (backslash is the default LIKE escape): inspection only.
- **Rounding** needs both 10.005 and 10.015. A check-digit formula `(10 - s % 10) % 10` needs a valid case with check digit 0. **Annotation probes:** removing a method-level `@Transactional` leaves a class-level one in force: remove both.
- **A guard's falsifier** needs input passing every later check once the guard is gone. An "ASCII digits only" test with U+0668 at the check-digit position is rejected by the checksum arithmetic, so the `Character.isDigit` mutant survives; working witness: U+0661 replacing a 5 at a weight-1 position (`0x661 - '0' - 5 = 1580`, 0 mod 10). Write "a non-ASCII digit the naive checksum still accepts".
- **"Uses the given clock"** needs a clock fixed in a past year (2000-06-15) and a value only the real clock accepts (year 2027); a clock fixed in the current year equals `Clock.systemUTC()`. Lead cards keep picking dates near the run date: rewrite every fixed date into a past year at strategy time (year rules: 2001 accepted, 2002 rejected). An override control (test `@Primary` fixed clock) needs a production-side probe clock whose DATE differs from the fixed clock's; add a post-fix run with the production clock fixed in a past year.
- **Profile-split config:** `Environment.getProperty` of a YAML list key returns null: assert the resolved bean, and read the main yml with `YamlPropertySourceLoader` so the DEFAULT profile is falsified. Re-run idempotence needs content equality AFTER edits in every seeded table (`DO UPDATE SET c = excluded.c` is equivalent on an unmodified DB); close untouched columns with an anchored gate grep (`^ON CONFLICT DO NOTHING` = `^INSERT` count, `DO UPDATE` 0). Rewriting a census as an exact map over a FILTERED subset drops its all-rows clauses for filtered-out rows: list each old clause and where it lands.
