Siblings: [[qa-directive-traps]], [[qa-bugfix-and-live-runs]] (bugfix final brief), [[qa-ci-config-specs]].

1. **CI run ids in a qa-final brief.** Ids handed over by the orchestrator can belong to a task branch, not the spec tip. Never write run ids; write `gh run list --commit <full 40-char sha>` (a short sha returns `[]` without error) and `gh run view <id> --json headSha`. The `pull_request` run's `HEAD is now at <sha> Merge <tip> into <base>` line proves the merged tree. PR body checks: the attribution footer holds U+1F916, so write "body prose ASCII, the prescribed footer excepted".

2. **Base moved during the cycle.** An owner commit on the base breaks `merge-base --is-ancestor`. The fix is a merge into the spec branch (never rebase or force-push). Re-run the tip-identity items (referee and counts, hash checker, greps, git facts, PR readiness, CI on the tip). Carry the rest forward by patch identity, not name-status (a base delta with product files fails a "no product file" rule literally):
   - `git diff OLDBASE...OLDTIP -- P` equals `git diff NEWBASE...NEWTIP -- P`, and `git diff OLDTIP NEWTIP -- P` equals `git diff OLDBASE NEWBASE -- P` (the merge took the base bytes), each with a control that can fail; plus the base delta disjoint from the spec's files and from the live checks' request paths, and inserted base tests that write nothing for an order-independence carry.
   - Fast carry per path: blob identity `OLDTIP:f == OLDBASE:f` and `NEWTIP:f == NEWBASE:f`; for a file both sides touched compare patch-ids of `git diff -U0` (with context the ids differ); for a conflict-resolved doc a whitespace-insensitive token diff (`tr -s '[:space:]' '\n'`) plus hashes of the untouched head and tail.
   - Put a base-ref check (`ls-remote origin refs/heads/<base>`) at the start and before PR readiness. The finalize commit moves the tip again: repeat the tip checks before the human merge.
   - A mid-cycle merge stales every cited pack line in directives, scratch layers and manifest labels: before the next verifier runs, map old to new from `git diff -U0 <spec tip> <merged>` per pack file and re-point each range (heading anchors survive, line labels do not). A frozen-hash chain over pages also needs "the merge changes nothing under the site folder" checked on the merge commit.

3. **Integration integrity at the final review.** Record each task's sha256 baselines in the ledger matrices; at final-review hash the gated files at the spec tip and compare: one command proves squash and base merges altered nothing a gate reviewed.
   - Verifiers write baselines in mixed forms (absolute and relative paths, `git status` header lines) and rework rounds supersede entries. So C0-1 asks for repo-relative `shasum` lines only; every round (docs-only included) writes its own `-r<k>-hashes.txt`. In the brief, name the authoritative file per task, state the exact count of expected superseded FAILED lines, and dry-run the check yourself (filter `^[0-9a-f]{64}  `, strip the absolute prefix).
   - In the same script compare the sorted union of baseline paths with the product files of the spec diff (minus `.claude/`, `agent-os/`): an empty `diff` proves every shipped file passed exactly one gate. Hash committed bytes at qa-final, never the working tree (in the fresh clone `git show <tip>:<f>` piped to `shasum`, or a `git archive <tip>` extraction when git writes are barred).
   - Free negative control: the same command with the last task's parent commit as tip must exit 1 with exactly that task's lines FAILED. A passing hash check also carries production mutation probes (ArchUnit P-prod included when the import uses `DoNotIncludeTests`), so qa-final can run with zero repo edits.

4. **Script hygiene for the brief.** Write the dry-run checker as an argument-driven script (root, tip, base, SP) and hand it to qa-final with expected output lines. Verifier scripts a brief reuses (replay drivers, mutant makers, start scripts) hard-code the worktree path and task-prefixed names: direct qa-final to copy each to a final-prefixed name with a quoted `diff`, or a rerun overwrites gated per-task evidence. Every script section prints a count or an assertion with its expected value; write intersections as `comm -12` of two sorted lists plus `wc -l` (expect 0) and a control that prints.
   - Planned test names in a shape.md scenario map go stale in most tasks: require each implementer to update its rows (or declare the outbox map the record) and dry-run a `void <name>(` grep before the brief, with digits in the name regex (`[A-Za-z]+` skipped every `...To409`).
   - Brief expectations that are counts (files per kind, test classes per annotation) come from a dry-run command, never mental arithmetic: ArchUnit classes hold `@ArchTest`, not `@Test` (use `@(Test|ArchTest)`); count subclasses with `grep -rln "extends <Base>"`. An "empty snapshot expected" is false when my own memory edit sits in the tree: write memory before the dry run, or name my agent files as expected.
   - Every C0 grep a brief calls "empty" is dry-run, not a subset; when carrying a C0 block into a new spec also run each grep against the lead's design calls (a wall-clock test grep would have flagged `LocalDate.now(clock)`). A grep pinning one spelling is passed by an equivalent spelling (`LocalDate.ofInstant(clock.instant(), zone)`): grep the read itself and list expected statements by file. A fix cycle merged mid-spec shifts every C0 baseline: re-record on the post-merge tip before the next task.
