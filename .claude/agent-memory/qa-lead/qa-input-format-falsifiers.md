Siblings: [[qa-test-data-falsifiers]], [[qa-passthrough-state-falsifiers]]. Escape-form handling: [[qa-directive-traps]] (backslash-u item).

- **`strip()` vs `trim()`** needs a non-ASCII whitespace witness: U+2003 from `Character.toString(0x2003)`; U+00A0 is no witness (`Character.isWhitespace` excludes it). `Locale.ROOT` casing needs a run with `-DargLine="-Duser.language=tr -Duser.country=TR"`; `toLowerCase(Locale.ROOT)` turns U+0130 into two chars (the one length-growth witness). Ask for both at strategy time or they end up inspection-only.
  - Padding witnesses ("surrounding chars in the set `trim()` strips"): a witness char the pattern's core class already accepts proves nothing about the pad class (U+2003 alone is a valid address for `[^@\x00-\x20]+`). Working pair: U+001F padding accepted (inside the trim set, outside `\s`) and U+2003 next to an ASCII space rejected on each side. Run every witness against the decided pattern by reading before writing it.
  - "Length in UTF-16 chars" on a trimmed value cannot be a `@Pattern` (regex counts code points, `@Size` sees the raw value): plan a custom constraint at Gate 1 or it costs a blocked round.
  - Framework-behaviour premises in plan prose are claims: verify against the pinned jar (`javap -c`) or a jshell script in SP. Hibernate Validator 9.x `@NotBlank` calls `String.isBlank()` (U+2003 blank, U+00A0 passes); `@Pattern` uses `Matcher.matches()`, `@Size` counts `length()`, both null-valid; `\s` without `UNICODE_CHARACTER_CLASS` is ASCII-only. An explicit `ResponseEntity` content type skips Accept negotiation, so removing it survives every test without an Accept header: list `Accept: application/problem+json` as the falsifier of any "error body is application/json" criterion.
- **Regex witnesses:** a regex whose class or quantifier repeats needs one rejecting witness per position (like ArchUnit package strings): `[^@\s]+@[^@\s]+\.[^@\s]+` needs a space in each of the three parts and an empty local, domain and top-level part. A negated class with a range (`[^@\x00-\x20]`) holds three properties per position: the excluded literal, the upper end (rejected space plus accepted `!`) and the lower end (a tab) per part. A numeric-string price `-?\d+(\.\d+)?` needs `+5`, a trailing space (a 500 from `new BigDecimal`), a non-ASCII digit from code points (the `\p{Nd}` mutant gives 202) and accepting rows past every plausible cap (`12.345`, `123456.789`).
- **"A body missing a required key"** is one case per key (a single-key test lets every other key's check be dropped); null and empty lists are two cases. Also: a null or broken element alone, first, last and in the middle; a float in EVERY integer component (cents and quantity); every optional key absent with its decided default (else the receiver flip `x.equals("CONST")` survives and lets an NPE escape); a negative in every value assumed unsigned.
- **HTTP client timeouts** (loopback JDK `HttpServer`, port 0): the handler returns a VALID body after its sleep, so a missing timeout gives a success; connect and read timeouts differ and connect is longer than the sleep (kills swapped arguments); elapsed has a lower bound (kills a zero or unit-truncated timeout failing at once) and an upper bound below the sleep; plus a no-sleep positive control through the same public constructor. Connect timeout itself stays inspection-only. Live: make the remote fail every call (chaos failure-rate 1.0) and expect the local answer; for the read-timeout default use chaos latency above the timeout and check `time_total` inside [timeout, latency); one row-count query after all failure phases proves "nothing saved".
- **Log-escape sets named by a JDK predicate** ("every `Character.isISOControl` char plus U+2028/U+2029"): list the witnesses at strategy time or hand-rolled ranges survive as inspection items: every `\R` member (LF, VT, FF, CR, U+0085, U+2028, U+2029) and the predicate's edges (NUL, U+001F, U+007F, U+0080, U+009F), one hex digit that is a letter (lowercase-hex probe) and one leading-zero code (width probe). A new exception constructor that must leave a pass-through untouched (`details` empty) needs that field asserted in the new test, else "details filled from the cause" survives.
