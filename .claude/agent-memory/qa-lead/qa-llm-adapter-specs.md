Siblings: [[qa-llm-failure-and-prompts]], [[qa-directive-traps]], [[qa-test-data-falsifiers]].

1. **Keyed referee as the offline proof.** "Tests stay offline even with the key exported" is only proven by running the referee a second time with a fake key exported (`BOOKSTORE_AI_API_KEY=probe-not-a-key bash with-budget.sh ...`, a literal env prefix is allowed by the shell guard): same totals and Started count, zero `401|UnknownHost|...` lines. Surefire forks inherit the shell environment unless the pom sets `environmentVariables`; check that premise. It also catches unit tests that read the process environment, which no single plain run can show.
2. **No-context config tests read the real environment.** A `StandardEnvironment` includes `systemEnvironment`, so a yml/EPP test "key empty without the variable" goes red in a shell that exports it. Rewrite at Gate 1: build the environment without system sources (or `MockEnvironment`) and feed the variable through a `MapPropertySource`.
4. **Framework-default-equivalent mutants.** Spring AI auto-config supplies a `MessageWindowChatMemory` (20, in memory) `@ConditionalOnMissingBean`, and 20 is the builder default: removing our bean or `.maxMessages(20)` changes no test. Pin the bean's origin (`getBeanDefinition(name).getFactoryBeanName()`) and treat the window literal as inspection. Same family: an EPP that `addLast`s a property behind an "unset" guard: each single mutant (`addFirst`, guard removed) is equivalent, only the pair is must-fail. Look for library defaults before listing a mutant as must-fail.
6. **The tool-calling double trap.** A `ChatModel` double whose `getOptions()` is not `ToolCallingChatOptions` drops tools silently (empty reply, tool never called). Make it a must-fail probe on the double itself and require an in-test negative control that differs only in `getOptions()`. A client built without tools passes tool-calling options with null callbacks: the double must handle that (else a `defaultTools`-dropped mutant dies only by NPE), and it must record a call that fails for lack of a step.
7. **Adapter layer rules cut off domain data.** An inbound adapter allowed only `domaininteraction` cannot read a domain enum (`Genre.values()`); a card saying "lists every Genre name" must take them from the use-case exception's `details`. Witness with made-up names so a hard-coded list fails. Grep the layer rules before accepting such text.
8. **Client-mirrored contracts.** A JS client counts UTF-16 units: test the server limit with a supplementary character (two units), a non-ASCII BMP character (kills byte length) and a trailing space (kills `strip()`). Copy the client's exact `Accept` header (from the client source on the base branch) into at least one error case per status, because ProblemDetail content negotiation depends on it.
10. **Pipeline position is invisible to direct-call unit tests.** An `EnvironmentPostProcessor` that reads a config-file value (the offline switch) is wrong if it runs before `ConfigDataEnvironmentPostProcessor` (`ORDER` = HIGHEST + 10 in Boot 4.1.2): the key reads null and the app stays offline even with a key. Direct-call unit tests and a blank test-profile key are green in both orders, so an added `@Order(HIGHEST_PRECEDENCE)` survives everything. Falsifier: in the shared full context the switch's property source sits after every `application*.yml` config source (index comparison, non-vacuity on both names; compare only names starting `Config resource`, since Boot appends `applicationInfo` after every EPP). The key blank guard needs the U+2003 witness too.
