Siblings: [[review-calibration]] (rework and evidence), [[review-scope-rulings]]. Witness lists that prevent survivors: [[qa-test-data-falsifiers]].

1. **Null guards count as validation branches.** In domain and domaininteraction code, an `Objects.requireNonNull` or any throwing null check needs a test that fails when it is removed, unless removal is equivalent (a later statement throws the same type on the same input: `List.copyOf(null)`). Feed forward to impl directives.

2. **REJECT threshold for surviving mutations.** On money, ISBN or numbering, persistence, transaction and cross-module contract criteria, a survivor I can show from the code is a REJECT. On a low-risk criterion, a survivor that only distinguishes decided wording (`strip()` vs `trim()`, `Locale.ROOT`) with no listed falsifier and the decided form in the code is inspection-proven: record it, feed forward a witness. Why: the strategy's falsifier list is the advance bar; a cosmetic distinction in the last rework round moves it. Prevent by naming the witness at strategy time. The same allowance (inspection, test-only follow-up, qa-final probe, no last-round REJECT) covers:

3. **Survivor whose kill contradicts a pinned criterion.** If the only way to kill it is to change something a criterion pins (a fixture signature): no REJECT, record a plan-level gap and recommend the amendment (cheapest inside a rework round that runs anyway), else a follow-up and a final-brief item. A survivor killable in scope without touching a pin stays a REJECT; judge each "informational" survivor against the criterion text and file scope. Same for an inserted `catch` around a port call in a flow test with mocked ports when the criterion lists the allowed new tests (feed a must-fail swallow probe to the task owning atomicity), and a clause whose falsifier my strategy put at qa-final (brief qa-final with the check plus a discriminating control).

4. **Strengthening-only survivors.** A mutation that can only add violations (ArchUnit `allowEmptyShould(true)` -> `(false)` on never-empty imports) does not weaken the guard: inspection-proven when the criterion pins the setting, even on money criteria.

5. **Oracle helpers that call production code.** A test may compute an expected value from production code (the domain exception's message) when (a) the helper calls nothing of the class under test; (b) every contract field (code, title, field name, list, exception type) stays a literal; (c) the helper asserts its own precondition (`isNotNull`). A contract field computed from production code is a REJECT.

6. **Survivors equivalent on every reachable input.** A money-adjacent survivor (`toString()` for `toPlainString()`) is inspection-proven when an upstream invariant pinned by its own tests (scale-2 type, fixed-scale column) makes outputs identical, the strategy made the clause an inspection item, the listed falsifier kills, and a follow-up names the witness for when a later spec widens the domain.
   - Pass-through inventory: per handler, list the distinct values tests feed each contract field (`code`, `title`, `details`, ids). A field fed one value survives replacement by it; grep the spec pack before calling a literal arbitrary. Single test constants let hard-code mutants survive in mappers (no REJECT; prevent via an implDirective data rule "every pass-through field fed two distinct values, asserted as literals"). A pass-through survivor found late in an endorsed sibling: must-fail probe in the qa-final directive plus a test-only fix task, never dropped because the sibling is merged.

7. **Regression-guard survivors in a file that freezes at this PASS.** A survivor narrowing a property class (a Unicode property replaced by categories) is no REJECT, even on a critical rule, when the verifier proved the current bytes on every member (exhaustive enumeration through the real function plus a real build), the file joins the freeze hash baseline at merge and another gate already rejects the reachable forms: record a follow-up.

8. **Survivors killed by a gate grep.** Before judging an "informational survivor", check whether a common-directive gate check rejects the mutant (a clock grep that must print exactly one `Clock.system` line rejects `Clock.systemUTC()`). Then it is gate-proven while the grep runs in every later task and qa-final; feed a test-pinned follow-up only if high-risk under rule 2. Exception: when a criterion says the test asserts criterion N, N's gate-grep properties (ASCII only) are test items: fold them in as RAs when a rework round runs anyway.


10. **Boundary twin of a fixed survivor.** When a rework kills survivor X and the verifier reports X's boundary twin (`>` vs `>=`) as "informational", judge the twin under the same criterion as X. Spend the rework round on fully specified test-only RAs (state, act, every asserted value, the mutant each must kill), 2 or more inside the region so the `-1` twin dies too. For a boolean flag the twin of a "reset" mutant is the "set" mutant (parameterize). The line stops at the twin: an offset shift inside a region that already has a witness, or a one-sided spelling (`stripLeading`), is no failure when production holds no such guard; route the witness into the next task's data at the same seam.

11. **Oracle-hardening gaps outside the criteria.** When a verifier finds a self-written checker passes vacuously in a way no criterion covers (zero self-tests discovered still exits 0), do not REJECT the PASS: make it a criterion amendment for the next task owning the same files, with must-fail witnesses. Until then add a verifier-side guard: the test total is never below the last gated total and earlier test titles are a subset of the current ones. "N equals the grep count" misses a deleted test file and is false when loops register cases: never write it.
    - Test-only gaps need a route, not a rework round: an untested extra guard in a file no later task owns: ENDORSE, route its test to the next task on the same seam by a fileScope line. Checker-strictness survivors when the next task does not share the seam: an insertion-only scope amendment for the round that runs anyway. In the LAST task: ENDORSE, residual folded into the next spec reopening the module, a qa-final must-fail per entry. With parallel worktrees split routed items by file.
