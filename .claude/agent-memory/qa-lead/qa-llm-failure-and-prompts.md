Siblings: [[qa-llm-adapter-specs]], [[qa-passthrough-state-falsifiers]].

1. **Tool adapters with a catch-all error helper.** Two blind spots recur:
   - A mutant (a cap of 11, an eager lookup) can be "killed" only because an unstubbed mock returns null, the NPE becomes the generic text, and that text fails the test. The kill is real but fragile: demand lenient stubs on the boundary row so the asserting line kills it.
   - A parse guard in front of a library parser (`length != 36` before `UUID.fromString`) hides the parser's catch: every row fails the guard first. Ask for a row that passes the guard and fails the parser (36 characters, not hex).
2. **Failure translation and memory restore at the chat boundary.** The use-case exception's cause has no consumer (`AssistantExceptionHandler` reads message, title, code, details only), so a dropped-cause mutant survives every web and IT test; a "WARN without throwable" mutant dies only by NPE unless the test asserts `getThrowableProxy()` isNotNull first; `catch (Throwable)` for `RuntimeException` has no test. If the decision is binding, list the witnesses up front: a direct `commands.chat(...)` call with `hasCauseReference`, and a gate grep on the catch types. Snapshot plus `clear`/`add` restore can erase a concurrent turn on the same id: price it as a residual. Once failures answer 503 `assistant-unavailable`, an escaped live call in an offline test also answers 503: offline assertions check the code, never the status alone. The Anthropic client wraps every `IOException` (timeouts) in `AnthropicIoException`; 401/429 are `AnthropicServiceException`, all `RuntimeException`.
3. **Provider-shape defects need a stub contract test of the real model client.** Model doubles never emit provider blocks (signed thinking), so a library replay bug shows only live. The stub answers on the request field the way the API does (thinking block only when `thinking.type` is not `disabled`); after a config fix the request-field assertion is the discriminator, replay-shape assertions carry the red shape (check red fidelity against the provider's error text); demand a guard test for `defaultOptions` merge side effects (model, `max_tokens`, sampling params) killed by override mutants. Live acceptance stays a keyed re-check. A loopback stub answering 500 sees 3 requests per chat (the client retries twice) but the app logs 1 WARN.
4. **Test contexts against exported variables.** Env vars outrank `application-test.yml`. Pin a blank key plus a loopback base URL (`http://127.0.0.1:9`) in the test base's `@TestPropertySource`; never `spring.ai.model.chat=none` there (the EPP then skips and the switch's full-boot witness goes red). Falsifiers: first source holding each key indexed before `systemEnvironment` (filter `configurationProperties`), exact URL value. Proof the URL binds: an information run with the model exported, per-host `Failed to connect` counts. Spring AI 2.0.2 has one URL property; `AnthropicSetup` reads `ANTHROPIC_BASE_URL` only when it is null.
5. **Prompt and tool-text fixes.** Pin each rule by meaning-bearing `contains` phrases, the tool description and `@ToolParam` text with `isEqualTo` (schema `properties.<p>.description`). Survivors are usually restatements or motivation sentences: no RA when the remaining pinned text still carries the rule and it is pinned where the model reads it at call time; gate-grep them at qa-final. A readable list in the prompt ("science fiction") invites that form as a tool argument: check the parser's accepted forms (`Genre.parse`: case, `-`, `_`, no space) and that the tool path really calls it. Behaviour stays live-only: sample a live check 3 times.
