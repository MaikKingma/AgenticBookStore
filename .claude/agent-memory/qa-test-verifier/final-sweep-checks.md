Rule: verify every PR-readiness fact against the live remote yourself. Never copy a sha or run id from the brief.
**Why:** the owner can commit straight to `factory` while a spec cycle runs. The spec branch then no longer contains its base, and `gh pr view` still reports MERGEABLE/CLEAN with a stale `baseRefOid`. Briefs can also name CI run ids that belong to the last task branch (`headBranch: sdd/<slug>/T<n>`), not to the spec tip.
**How to apply:**
- Base check: `git ls-remote origin refs/heads/<base> refs/heads/<spec>` first, then `git merge-base --is-ancestor`. Exit 1 means "base moved, rebase required", a FAIL. CLAUDE.md forbids force-push, so the remedy to name is a merge of the base into the spec branch.
- CI: `gh run list --commit <tip sha> --json databaseId,event,headSha,conclusion` gives the real tip runs. In the `pull_request` run log, `HEAD is now at <sha> Merge <tip> into <base>` shows which base the merged tree was built on: risk evidence, never a replacement for the ancestor check.
- In a scratch clone, run `./mvnw` from a script that `cd`s into the clone; calling `<clone>/mvnw` from the project root resolves the main checkout's `.mvn`.
- Surefire-vs-source class lists: ArchitectureTest holds `@ArchTest` fields and no `@Test`, so list `@(Test|ArchTest)` holders. A tr_TR run proves its argLine took effect when the PostgreSQL detail line prints in Turkish.

Rule (bugfix-cycle qa-final): run the per-task negative control in throwaway worktrees as a three-step ladder, then prove the cross-task paths in a scratch worktree at the tip.
**Why:** a regression test that turns green when the OTHER task's fix lands does not pin its own defect; only applying the fixes one at a time shows it, and a single base-vs-tip run cannot.
**How to apply:**
- `git worktree add --detach .claude/worktrees/<name> <base>`, then `git -C <wt> checkout <tip> -- <test files>` (only there). Steps: base, then `cp` the other task's production file, then `cp` your own. Expect red, red, green, and `shasum` the files in every run. Run `clean test` from a script that `cd`s into the worktree. Remove worktrees with `--force`, then `rmdir` the `.claude/worktrees` dir that `worktree add` created inside the agent worktree.
- Simpler ladder when the brief allows: one detached worktree per task AT THE TIP, revert only that task's production files with `git -C <wt> show <base>:<path> > <file>`, run the union of all tasks' regression classes (exact red set = own tests only, other tasks green = cross control), restore with `show HEAD:`, porcelain empty.
- The IT `problem()` helper asserts the status before it reads the body, but RestTestClient prints the response to the log: `grep '"status":400' <log>` gives the field and message. Scratch IT methods: `place(...).expectBody(JSON_OBJECT).returnResult()` with `getStatus()`/`getResponseBody()` records a scenario without asserting; a `System.out.println("TAG " + problem)` per method makes the log quotable.
- Frontend ladder: each `negctl-<task>` worktree needs its own Node (`./mvnw -q -pl frontend generate-resources` from a script that `cd`s there). Compare red sets mechanically: extract the verbose failed-test lines and their arrow first-line lines, strip the `NNms` suffix, `diff` R vs X (exit 0 = identical).
- Surefire `runOrder=reversealphabetical` sorts by fully qualified name, and an upper-case class in the root package sorts BEFORE lower-case subpackages, so reverse runs it last. To prove a shared context starts from a given class, run `-Dtest=A,B -Dsurefire.runOrder=alphabetical` and count `Started`.
- Per-task hash baselines into one integrity check: a python script reads the gate files in task order, keeps only `^[0-9a-f]{64}  ` lines, drops agreed paths, keeps the LAST line per path and prints every supersede (old -> new hash, by which gate); then `shasum -a 256 -c` in the `git archive <tip>` extraction and a `diff` of the sorted path union against the spec diff's name list proves "reconciled by name".
- Warning inventory (against a reference referee log or a base referee): a case-insensitive `warn` grep hits about 130 lines per referee (app WARN logs that ACL/data/web tests provoke on purpose, Spring AI BeanPostProcessorChecker, npm `install-scripts` printed as `[ERROR]`), far beyond a directive's short "pre-existing" list. Prove ownership instead of arguing: run the base referee (`git archive <base>` into the scratchpad, a script that `cd`s there and runs `./mvnw -f <dir>/pom.xml clean verify`), grep both logs per module section, classify by category in a python script and `diff` the sorted multisets after normalising timestamps, PIDs, thread names (`[...-exec-N]`), `Time elapsed: X s`, logback `HH:MM:SS,mmm` prefixes, UUIDs (random book ids show up as added AND removed) and the `.m2` path; "0 added at TIP" closes it. Count green Surefire summary lines separately (an `error` grep matches `Errors: 0`). JVM-once notices (`WARNING: A terminally deprecated method in sun.misc.Unsafe`) print in the fork of the first test that takes a new library path, so they show as "added" when a cycle adds such a test: attribute by the `Running <class>` line above and by a control run with the base production file. Jars from `spring-boot:repackage` carry the reproducible 1980 mtime: cite the `Building jar` log line, never `stat`.

Rule (re-running earlier verifiers' scratch scripts on a final head): copy each to a new name, edit, `diff` old vs new, and compare the new tail with the old log (same kill table, same counts).
**Why:** three silent traps. A copy keeps its CLI guard `if (process.argv[1].endsWith('<old name>'))`, so the renamed copy runs nothing and exits 0. A script whose BASE is `origin/<spec branch>` compares the head with itself after the merges: pin the task PR base sha (`git rev-parse <task merge>^1`). A script that reads files and runs `git -C R` breaks on a `git archive` tree: add `GW = process.env.QA_GIT_ROOT ?? R` for git.
**How to apply:** grep every copy for `argv[1].endsWith`, `origin/`, `HEAD:`, ports, `slice(` and line-number literals before running. When a pin is re-pointed after a deletion, scope each new negative token to the section the deletion touched (a page-wide `not verified yet` hit an unrelated sentence). Keep each pass's log under its own name.

## Coverage from the CLI and impl heartbeat stamps
Rule: measure coverage from the command line; never add JaCoCo to a POM (plans forbid POM changes).
**Why:** the bookstore POM has no JaCoCo and its surefire config sets no `argLine`, so `prepare-agent` injects the agent cleanly. Java 25 needs JaCoCo 0.8.14 or later.
**How to apply:**
- `./mvnw -pl bookstore org.jacoco:jacoco-maven-plugin:0.8.14:prepare-agent verify org.jacoco:jacoco-maven-plugin:0.8.14:report -l <scratch>/jacoco.log`, then grep `bookstore/target/site/jacoco/jacoco.csv` for the changed classes (instr, branch, line: missed/covered). Run the plain `./mvnw -pl bookstore verify` too as the gate run (the referee's `clean` removes the report).
- When a stat-based order proof pins the referee's Surefire XML and jar (qa-final), run JaCoCo on a `git archive <tip>` extraction (`-pl bookstore -am`, script that `cd`s there) so the worktree target stays the referee's.
- For a constraint-only change (annotations on a record), line coverage is vacuous: prove each kept or removed annotation with a probe.

Rule: treat an impl artifact's `updated` as a claim; compare it with the file's mtime.
**Why:** an impl artifact once carried an `updated` stamp minutes in the future (estimated, not taken from `date -u`). It passes the literal heartbeat gate but hides a dead agent from the 15-minute rule.
**How to apply:** `stat -f "%Sm" -t "%Y-%m-%dT%H:%M:%S%z" <artifact>` (convert local time) against `date -u`. A future stamp is a process note, not a FAIL, unless the gate's stated conditions fail. The same trap hits the verifier's own artifact: take every `updated` from a fresh `date -u` call right before the bump.
