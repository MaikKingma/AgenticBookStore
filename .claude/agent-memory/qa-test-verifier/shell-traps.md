description: zsh, ugrep, BSD grep, rg, Edit/Write and worktree-guard traps hit while running QA commands in this repo (globbing, find parentheses, empty-looking results, pinned PATH, LANG)
metadata:
  type: feedback
---
Rule: quote every glob-bearing argument; the Bash tool runs zsh, which fails on unmatched globs.
**Why:** `--include=*.java` and unescaped `( ... )` in `find` abort with "no matches found" before the command runs, which can look like an empty, passing result.
**How to apply:**
- Write `"--include=*.java"` and `find ... \( -name a -o -name b \)`. Repo paths contain spaces: always double-quote absolute paths. Unquoted URLs with `?` in curl fail in zsh too.
- The Bash tool's cwd is the main checkout, not the worktree: relative `rg`/`shasum -c`/`git` paths fail "No such file" or read the wrong tree. A path built from the repo root without the `.claude/worktrees/<id>` segment still exists (the main checkout), so a `printf >` there succeeds silently outside the worktree.
- `./mvnw ... -l <scratch>/referee.log` keeps the referee console out of context; grep the log for the reactor summary, `Tests run:`, `Creating container for image` and `Started [A-Za-z.$]+ in ` (nested test classes). Summary greps over `npm run check` logs: anchor on `^ok   (coverage|content)|ℹ (tests|pass|fail) `, a bare `^ok ` dumps 100+ lines.
- `echo ==== label` fails in zsh ("= not found", `=cmd` expansion) and aborts the rest of that Bash line, so a following grep silently never runs. Quote separators and re-check that every grep in a chained line printed.
- `git grep -E` does not understand `\s` or `\b`: `git grep -c -E '^\s*@ArchTest'` exits 1 on a file with 20 of them. A `\s`/`\b` inside a readiness grep (`.only`, skip, Disabled) is silently vacuous. Use `[[:space:]]`, drop anchors, write `(test|it|describe)\.only\(` (plain `\.only\(` hits `author.only()`), and prove the pattern bites with `git -C <scratch> grep --no-index -n -E P <control-file>`.
- `grep` is ugrep: a missing path gives exit 2 with a warning while matches in the other paths still print; re-run on existing paths so "empty" means exit 1. Term-absence greps without `-w` hit substrings (`top-?p` matches "stopping"). A Maven log holding a raw NUL makes ugrep print `Binary file ... matches`: use `grep -a`.
- In the Bash tool a `grep`/`rg` with no match shows "completed with no output", not "Exit code 1" (`git grep`, `lsof`, `cmp` do show it). A negative control that cannot match looks the same: give every empty grep a positive control.
- Inside `bash script.sh`, `grep` is BSD grep: `-P` prints a usage error and the count comes out empty, which looks like a clean ASCII check. `rg` is a zsh shell function, not a binary on PATH: inside a script it gives exit 127. Run non-ASCII checks (`rg -c "[^\x00-\x7F]"`, with a printf-built control) directly in the Bash tool, or define `rg() { ( exec -a rg "${CLAUDE_CODE_EXECPATH:-$HOME/.local/bin/claude}" "$@" ); }` in the script and print `rg --version`. In rg, `-h` is `--help` and `-E` means encoding (exit 2, looks like "no output"): use `rg -ni "a|b"`.
- In a script, `echo "a $(cmd1) b $([ $? -eq 0 ] ...)"` reads the `$?` of `cmd1`: capture `rc=$?` on its own line.
- Never guess heartbeat or message timestamps: take `date -u` each time. `stat` mtimes print local time, convert before comparing with UTC stamps.
- `git show <rev>:<path> --output=<file>` and `git diff --output=<file>` printed to stdout and left an empty file: use a plain `> <file>` redirect, then `wc -c`.
- The Edit tool trims trailing whitespace in `old_string`/`new_string`: a probe ending in `, ` restores without the space and the restore then fails "String to replace not found". Anchor probe edits on text that does not end in a space, and compare hashes with the before-snapshot after the last restore.
- The Write tool turns U+2003 into a plain space (`a<U+2003>b` landed as `61 20 62`) and trims a file holding only U+2003, so a non-ASCII positive control silently fails: build it with `printf 'a\xe2\x80\x83b\n' > <file>`, check with `od -An -tx1`, then `rg -c`. The em dash survives. The reverse happens too: a backslash-u escape typed into Write/Edit lands as the real character; describe escapes in words and `rg -c` every written file.
- Worktree-isolation guard refusals ("cannot be shown not to run git" / "too complex"): `bash <script> git -C <other repo> ...` (git in argv), a bare `bash --version`, `bash ~/.claude/scripts/with-budget.sh 900 bash <script>` typed directly (put the budget call inside a wrapper script), `$HOME` or `$VAR` arguments, `echo`/`git` after `;`, backslash-escaped spaces in a path (double quotes work). Direct `git -C <scratch clone> ...` calls and `bash <abs script in the worktree>` are allowed; keep git out of script args.
- Mutant generators: `grep -cF -- "$OLD"` with a newline in `$OLD` treats it as two patterns and the empty one can match every line. Count with `OLD=... perl -0ne '$c = () = /\Q$ENV{OLD}\E/g; print $c'` and replace with `perl -0pe 's/\Q$ENV{OLD}\E/$ENV{NEW}/'`.
- Hash baselines are `shasum -a 256` (64 hex); plain `shasum` is sha1 and never matches. A snapshot file mixing porcelain and hash lines: `grep " <path>$"` also matches the status line (false MISMATCH); filter `grep -E '^[0-9a-f]{64}  '` first.
- macOS `mktemp -d` without a template ignores TMPDIR (lands in `/var/folders/...`, outside the scratchpad): always `mktemp -d "${TMPDIR:-/tmp}/x.XXXXXX"`; for a README run with bare `mktemp -d`, list and delete its folders afterwards and report it. The JVM ignores TMPDIR too: export `JAVA_TOOL_OPTIONS=-Djava.io.tmpdir=<scratch dir>` for `./mvnw` runs (Surefire forks inherit it).
- macOS `cmp -n N old new` printed "EOF on old" (exit 1) although new starts with old. Prove append-only with `python3 -I` (`new.startswith(old)`) or `head -c N new | cmp - old`, with a one-byte-flipped control. BSD `sed -i.bak` plus `rm *.bak` is refused by the rm guard: rewrite with python.
- Probe runs go faster with two scripts in `.claude/comms/tmp/`: a probe runner (maven `-Dtest`, summary grep) and a restore script that `cp`s the `.orig` byte copy back and prints `shasum` beside the snap-before line.
- A script that exports `PATH=<pinned node>:/usr/bin:/bin` loses `lsof` (in `/usr/sbin`): "command not found" looks like "port free". Run port checks directly in the Bash tool.
- Never name a script variable `LANG` or `LC_*`: it is already exported, so assigning a path makes every later `node` exit 139 and `perl` warn. Every probe then shows `exit=139`, which reads like a checker crash. Use a distinct name.
- macOS `/bin/bash` is 3.2: `declare -A` and `${!arr[@]}` fail in a runner script; use a `case` function mapping names to paths.
- Waiting for a background batch: a foreground `bash <wait script>` with a `sleep 10` loop (about 3 minutes per call); bare `sleep` is blocked and a Monitor alone ends nothing for a subagent. A `run_in_background` command that itself backgrounds `java -jar &` exits at once and the jars keep running: stop them by PID file, then `lsof` the ports.
- Output floods: `git ls-files --stage -- "*package-info.java"` is a literal-prefix pathspec and dumps the whole tree (use `rg -c "" <dir> --glob "package-info.java"`); `jar tf` of a boot jar prints ~400 lines (pipe through `rg`).
