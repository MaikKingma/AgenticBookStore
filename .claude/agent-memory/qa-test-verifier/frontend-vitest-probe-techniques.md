Rule: run Vitest with the verbose reporter yourself; the Maven `npm test` run hides what the verbose run shows.
**Why:** the default reporter under Maven printed no `stderr |` block for a passing test, while `--reporter=verbose` printed one (a guard test that logged through a call-through `vi.spyOn(console, ...)`). A green Maven log proves nothing about console hygiene.
**How to apply:**
- Script in `.claude/comms/tmp/`: `export PATH="<FE>/node:/usr/bin:/bin:..."` then `exec node/node node_modules/vitest/vitest.mjs run --reporter=verbose --reporter=json --outputFile=<SP file> <test files>`; call it as `bash with-budget.sh 180 bash <script> > log 2>&1` (no `cd`, no env prefixes with paths holding spaces; the worktree guard refuses compound commands).
- Count `grep -c 'stderr |'` and `grep -cE 'Warning:|act\(|Not implemented'`. A spy without `mockImplementation` always passes through to the real console.
- Probe runner: one `python3 -I` file with a dict of probes (file/old/new edits plus test files), asserts each `old` occurs exactly once, restores from a `.orig` copy after each run, prints sha equality. `vitest` transpiles only, so probes must change runtime behaviour.
- Guard-of-the-guard gap: a console trap whose `expect` sits in `afterEach` cannot be asserted by a committed test in a small file scope. Probe by deleting that `expect` AND adding `console.error('probe')` to a test: it stays green (survivor); report it and keep a `console.error`/`console.warn` probe in every later task's list.
- Temporary witnesses: a hook no committed test can assert (default `onTestFinished` wiring, `.fails` banned) gets a temporary `src/.../<id>-witness.test.ts` created by the probe runner: it must fail on the real code, pass under the mutant, then be deleted (snapshot proves it). Prove a Required Action is sufficient the same way: witness with the exact assertions green on real code, survivors aliased as `W-<id>` probes all die, delete the file, take snap-after. Or `cp` the whole test file to a temp `src/.../QaWitness*.test.tsx`, make the one-line fixture change, then `mv` it out (runner env `QA_TEST`/`QA_TAG` reuses the mutants).
- Rework rounds: do NOT reuse the previous runner as is (it restores from the old `.orig` and would silently revert a reworked TEST file): load the old probe module with `importlib` (its `__main__` guard keeps it inert), point `orig_of` at fresh copies, alias probes `r2-<id>`, add mutants for the new rows. "Tests only, nothing weakened": keep the old `.orig` byte copies, confirm sha equals the old hash lines, `diff .orig current` shows only `>` lines, `shasum -c` names exactly the changed files. A corrupt-input fix row (`[null]`) also needs the SIBLING mutant "skip the bad element, keep the rest" (survives while the new row has no valid sibling line).
- CSS contract tests (hand-rolled parser plus fixture strings): probe three families. (1) value mutants (token hex, contrast terms, threshold) die on calibration literals; (2) rule-deletion mutants survive when only colour pairs are scanned: list which classes a test really names; (3) new-file mutants (a probe `.css` under a new `src/components/` dir, runner creates and `rmdir`s it) prove the scan covers later files. Binary fixtures (woff2): overwrite with HTML bytes, restore from `.orig`. Colour swaps must use a pair that really fails (teal on mist passes 4.5:1, so it is a legal mutant, not a gap).
- Vitest 5 empties every CSS import including `?raw`; tests read CSS via `node:fs`. An `it.fails` guard is probed by deleting the trap's final `expect` (both fixtures report "Expect test to fail").
- Compile-only files (`types.ts`): `tsc -p tsconfig.app.json --noEmit` on a mutated field; only fields a typed fixture uses die (`authors`, `price`, unions); `shippedAt` nullability and `details` element type survive unless a fixture is annotated: inspection-only.
