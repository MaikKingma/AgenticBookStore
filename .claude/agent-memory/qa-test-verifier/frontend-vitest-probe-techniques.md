Rule: run Vitest with the verbose reporter yourself; the Maven `npm test` run hides what the verbose run shows.

**Why:** the default reporter under Maven printed no `stderr |` block for a passing test, while `--reporter=verbose` printed one (a guard test that logged on purpose through a call-through `vi.spyOn(console, ...)`). A green Maven log proves nothing about console hygiene.
**How to apply:**
- A script in `.claude/comms/tmp/` with `export PATH="<FE>/node:/usr/bin:/bin:..."` then `exec node/node node_modules/vitest/vitest.mjs run --reporter=verbose --reporter=json --outputFile=<SP file> <test files>`; call it as `bash with-budget.sh 180 bash <script> > log 2>&1` (no `cd`, no env prefixes with paths that hold spaces; the worktree guard refuses compound commands).
- Count `grep -c 'stderr |'`, and `grep -cE 'Warning:|act\(|Not implemented'`. A spy without `mockImplementation` always passes through to the real console.
- The JSON outputFile is overwritten by every run; copy it before an extra witness run if you cite it.
- Probe runner: one `python3 -I` file holding a dict of probes (list of file/old/new edits plus test files), asserts each `old` occurs exactly once, restores from a `.orig` copy after each run and prints sha equality. `vitest` transpiles only, so probes must change runtime behaviour.
- Guard-of-the-guard gap: a console trap whose `expect` lives in `afterEach` cannot be asserted by a committed test inside a small file scope. Probe by deleting that `expect` AND adding `console.error('probe')` to a test: it stays green (survivor). Report it as a ledger note and keep a `console.error`/`console.warn` probe in every later task's list.
- Dev-server check: start `node/npm run dev` in a script (subshell, `&`, write the pid), sleep, `curl`, kill the `lsof -tiTCP:<port> -sTCP:LISTEN` pid plus the wrapper pid, then `lsof` again; the same command with `PATH=/usr/bin:/bin` gives `env: node: No such file or directory` exit 127.
- `rm -rf frontend/node_modules` before the first `-f frontend/pom.xml clean verify` makes `npm ci` run from scratch (log shows `added N packages`); `clean` deletes only `dist`, and a failed build leaves no `dist`, so rebuild with `-DskipTests` before testing that `clean` removes it.

- CSS contract tests (hand-rolled parser plus fixture strings): probe three families, not one. (1) value mutants (token hex, contrast formula terms, threshold) die on the calibration literals; (2) rule-deletion mutants (delete a whole class rule) survive when only colour pairs are scanned, so list which classes a test really names before believing "pinned class names"; (3) new-file mutants (a probe `.css` under a new `src/components/` dir; the runner must create and `rmdir` it) prove the scan covers files added later. Binary fixtures (woff2) are probed by overwriting with HTML bytes and restoring from the `.orig`.
- Fixture strings in a test file trip the repo's own literal greps (for example `style={{ color: 'red' }}` against the inline-style grep, an absolute URL against the CDN grep). Run every C0 grep over the test files too and expect fixtures to be built from parts.
- Vitest 5 empties every CSS import including `?raw`; tests read CSS with `node:fs`. A `it.fails` guard is probed by deleting the trap's final `expect` (both fixtures report "Expect test to fail" and the recorder test fails).
- Rework rounds re-run every global grep over the whole tree, not only the one the last FAIL named: a reworded or new test title can trip a different literal grep (a title naming `@fontsource/...` hit the case-insensitive CDN grep while the inline-style grep was clean).
- Class-contract tests ("each contract class has a rule"): probe with a regex rename of every class in turn (`\.name(?![\w-])` to `.namezz`, all occurrences) plus a rename of only the base rule when a longer class shares the prefix; deleting only a base block survives whenever `.x a` or `.x:hover` rules remain (the check matches any selector), so report that as a design limit, not a defect. A hard-coded class list can shrink silently unless its length is asserted.
- Re-run the referee after any extra probe round: the "referee last" rule is about the newest restore, so a late probe batch costs one more 25 s run.
- Pass-through order claims (API client lists, ProblemDetail `details`): for every attribute of the fixture, probe a stable `[...list].sort(...)` on that attribute in BOTH directions, applied after the fetch, and run it on the whole suite. Add one ascending control mutant that must die, which proves that the mutant reaches the assertion. Fixtures that look unordered often are not: a field with two values over three elements (`SHIPPED, PLACED, PLACED`, `customerEmail` twice) is non-strictly sorted, and so is a natural default plus one other (`EUR, EUR, USD`). Read every column before believing "not sorted". A two-element "in request order" claim can never satisfy a three-element rule.
- Find order fixtures by structure, not by test title: every array inside any `toEqual`/`toStrictEqual` pass-through counts. That includes arrays embedded in a view (`authors: string[]`, order `lines`), arrays in a SENT payload asserted "unchanged", and a test helper's call log (`mock.calls`). A title-only scan missed three such fixtures in a first round, and the miss cost a rework round. A generated sweep (attribute x direction x string/number compare, about 70 mutants at about 2 s each on one file) backs the table cheaply.
- String-array fixtures (author names, tags): also probe DERIVED keys (sort by last word, by length). Real-world data is often ordered by them by coincidence: the credit order of a famous book can be alphabetical by surname with ascending name lengths, so a "credit order" claim survives a surname sort. C0-16 binds only attributes the code holds, so report such survivors as informational and suggest a fixture whose derived keys are unordered too.
- The tool-reported clock can drift from your own estimate; take every heartbeat `updated` from `date -u`, never from a guess, or the artifact shows a future time.
- Compile-only files (`types.ts`): probe with `tsc -p tsconfig.app.json --noEmit` on a mutated field. Only fields that a typed fixture uses die (`authors`, `price`, unions); `shippedAt` nullability and the `details` element type survive unless a fixture is annotated with the type, so report them as inspection-only.
- A hook that no committed test can assert (a default `onTestFinished` wiring, with `.fails` banned by C0-3): let the probe runner create a temporary `src/.../<id>-witness.test.ts`, run it on the real code (it must fail) and under the mutant (it must pass), then delete it. The snapshot proves the deletion.
- Router and form probes that found real gaps where the implementer's own list was clean: (1) a "last `return notFound`" branch of a hand-rolled route parser (valid id after an unknown first segment, `#/basket/x`) is unexecuted when every UNKNOWN entry is caught earlier by an empty-segment rule; probe by returning a known page from that branch. (2) A display decision "shown as sent" needs a fixture value that a plausible transform changes (underscore genre vs `.replace('_', ' ')`); single-word upper-case values survive it. (3) Remove `event.preventDefault()` from a form `onSubmit`: the test stays green and jsdom prints `Not implemented: HTMLFormElement's requestSubmit()` straight to stderr, bypassing a `console.error` spy trap, so only a `defaultPrevented` assertion or the stderr grep guards it.
- Sort sweeps on heterogeneous detail objects (`{foo}`, `{code, note}`, `{zebra, apple}`) give sparse-key survivors (a one-key sort compares `undefined` strings); judge them by the killed flat-value, length, reverse and entry-order sweeps instead.
- Rework rounds: do NOT reuse the round-1 probe runner as is, because it restores from the round-1 `.orig` copies and a probe that touches a reworked TEST file would silently revert it. Load the old probe module with `importlib` (its `__main__` guard keeps it inert), point `orig_of` at fresh round-2 copies, alias every probe as `r2-<id>` and add new mutants for the new rows (sibling first segments, late `setTimeout(preventDefault)`). A document-level `submit` listener is a sound "was it cancelled" witness (React listens on the root, so the document listener sees the final `defaultPrevented`).

- State hooks and money strings (T7 basket, detail page): (1) "shown as sent" and "handed over as sent" for a decimal string need a fixture with a trailing zero (`"12.50"`); `Number(price)` or `String(Number(price))` survives every `19.99`/`7.99` fixture, in the display AND in the page-to-store call (probe both sites). Check the displayed texts a test really asserts, not the fixtures it defines. (2) Sort-sweep mutants on a reducer or hook state: wrap the sort so it returns the SAME array when nothing moves (`s.every((l, i) => l === xs[i]) ? xs : s`), otherwise identity assertions (`toBe(linesBefore)`) kill the mutant for the wrong reason; sweep three sites (reducer output, hydration, exposed value) and compare numbers as strings too (`[3, 10, 1]` is strictly descending as text). (3) A reducer that re-decides what the callback already decided has a refusal branch that only two dispatches in one `act()` reach; prove it with a temporary witness test (must pass on real code, fail under the mutant) and report the committed-suite survivor. (4) Corrupt-storage guards: probe the `null` list element separately from a number element (`typeof null === 'object'`).
- Rework-round proof of "tests only, nothing weakened": keep the round-1 `.orig` byte copies, confirm their sha equals the round-1 hash lines, then `diff .orig current` must show only `>` lines; `shasum -c` on the round-1 hash file names exactly the changed files. A fix row for a corrupt-input guard (`[null]`) is not the end: add the SIBLING mutant "skip the bad element, keep the rest" (`if (entry === null) continue`), which survives while the new row has no valid sibling lines; the mixed-list table (valid, bad, valid) needs the same bad value.
- A long probe batch run in the background mutates `src/` for its whole duration: do not run greps, tabulation or vitest meanwhile; wait with a script that loops `sleep` and greps the output file for the runner's `exit` line (a bare foreground `sleep` is blocked).
- Page-level falsifiers (checkout, order list): (1) tabulate DERIVED displayed columns too, not only fixture fields: a basket whose ids, titles, prices and quantities all zigzag still showed line totals "15.98", "37.50", "4.35", ascending as text, so a sort by line-total text survived (informational under C0-16, which binds held attributes). (2) A sort mutant at one display site can survive a mixed-value fixture when a sibling component reads the unsorted array (estimated total from `lines[0]`) and the test asserts no row order there; check which fixture really asserts order before calling a survivor a gap. (3) "Keyed on status, not code" probes work best as a page-level alternative render (`problem.status === 409 ? <own list> : <Alert>`) killed by an empty-details same-status witness (`queryByRole('list')` null). (4) A local-time `Date` mutant of an instant formatter dies here only because the machine zone is CET/CEST; cite zone independence from the C0-6a grep, never from that kill.
- Probe summaries over about 30 KB are cut by the Bash tool: compact them with a small script to one line per probe (id, verdict, first failing test, first assertion line) and read that in slices.
- Text-input limit pages (chat message, 1000 chars): tests with `'a'.repeat(1001)` leave three mutants alive that a trim-aware plausible edit produces: limit counted on `draft.trim().length` (in the guard, in the `tooLong` flag, in the counter text) and `[...draft].length` (code points). Probe all of them and close with a witness holding edge whitespace at the boundary (1000 chars plus a trailing or leading space is too long; 999 plus a space is not) and an astral character (`String.fromCodePoint(0x1f4d6)` = 2 UTF-16 units, as the server's `@Size` counts). A list keyed by message text survives every test that never sends the same text twice (duplicate-key warning is the only witness): probe `key={message.text}`.
- Re-verifying the limit-witness rework: also probe ONE-SIDED trims (`trimStart().length`, `trimEnd().length` at the guard, the flag and the counter), which only die when the fixtures hold both `999 + ' '` and `' ' + 999`, and `key={author + text}` / `key={text.length}`, which a duplicate-pair fixture kills through the console trap. A `preventDefault` witness on the empty form leaves "cancel only when not pending" alive; that path is unreachable in a browser (readOnly field, disabled button), so judge it informational. A deliberate duplicate pair fails C0-16's distinct-element form by design: tabulate it (constant derived columns such as word count are equivalent mutants) and cite the earlier distinct fixture for the order claim.
- Prove a Required Action is sufficient before issuing it: write a temporary `src/.../<id>-witness.test.tsx` with the exact assertions, run it on the real code (must pass), alias the survivors as `W-<id>` probes whose test list is the witness, run them (must all die), then delete the file and take the snap-after. A CSS probe that swaps a colour must use a pair that really fails (teal `#014046` on mist passes 4.5:1, so it is a legal mutant, not a gap; use blue, snow or navy-on-navy).
- CSS text-pin tests (one rule, matched by exact selector list): the families that die are declaration removed, wrong value, selector narrowed, rule moved into `@media`. Probe also a LATER rule with another selector that re-sets the property (`.x td { overflow-wrap: anywhere }` appended): it survives, because jsdom has no cascade, so only the live layout check guards it; report as informational. A mutant that inserts a declaration BEFORE the existing one in the same block is equivalent (last declaration wins); replace the existing value instead.
- A mutant that changes JSX tags must change the closing tag too, or esbuild reports `Transform failed` and the kill is a syntax error, not evidence; re-run it.
- In-flight flag moved into a context provider (a ref guard plus `placing` state plus a request that outlives the page): probe the SUCCESS branch reset as well as the error branch. Deleting `sending.current = false` from the 202 branch survived every test that places one order, because no test sends a second order after an accepted one (every later order is then silently dropped); error-branch and state-reset mutants die on existing alert tests. Prove the action with a temporary hook witness (renderHook + `BasketProvider`, two `placeOrder` calls, POST count 2), run on real code then under the mutant, then `mv` it out of `src/`. A module-level guard in the page is behaviourally identical in a browser; only a provider-level same-tick hook test separates it.
- Re-verification of a test-only rework: reuse a round-0 probe runner that calls `main()` at import time by `exec`-ing its source with the trailing `main()` cut and the log-name pattern replaced (a new scratch tag like `rw1`, because a prompt-suggested `r1` may already name round-0 hash snapshots); it is valid only while the production `.orig` copies still hash equal to the current files, so check that first. Rework closes by `shasum -c <last round hash file>` naming exactly the changed test file.
- Added-lines grep technique: run the repo's literal grep patterns in a python script over the touched files only and report just the hits whose text is among the `git diff <base> -U0` added lines, plus total hit count; far less noise than a whole-tree grep and still falsifiable.
- A negative control script restores through `trap restore EXIT` and also calls `restore` explicitly; record `shasum` before, during and after plus `git status --porcelain -- <files>` before and after.
