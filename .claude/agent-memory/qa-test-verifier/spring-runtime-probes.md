Rule: run every probe as `./mvnw -B -ntp -pl bookstore clean test -Dtest=<Class> -l <scratch log>`, always with `clean`.

**Why:** Maven never deletes stale files from `target/`. If you move a migration out of `db/migration`, the old copy is still in `target/classes`, so the probe passes falsely. A removed probe file (a test `application.yml`, a temporary entity) also leaks into the next probe.
**How to apply:**
- Docker-down without stopping the daemon: `DOCKER_HOST=unix:///nonexistent.sock` plus `-DargLine=-Duser.home=<empty scratch dir>`. `DOCKER_HOST` alone falls back to the Docker Desktop socket under the home dir.
- Missing-migration probe: use an entity with `@Id` and a protected no-arg constructor in `nl.openvalue.bookstore.data`. If the `data` package does not exist yet, `rmdir` it after the restore, otherwise the snapshot `find` differs.
- Cleaner mutations: removing the empty-list guard produces `TRUNCATE TABLE  RESTART IDENTITY CASCADE` grammar errors that are raised from the base-class `@BeforeEach`. Read the stack frames to see which hook ran the branch.
- Removing `@BeforeEach` from the integration base keeps the suite green, because the cleaner test calls `clean()` directly. Report it and do not count it as a killed mutation.
- Live `spring-boot:run`: start it through a script in `.claude/comms/tmp/` that redirects to a scratch log (the forked app does not write to `-l`). Wait with an until-loop script for "Started|FAILED|BUILD FAILURE". Stop it by killing the java PID from lsof. Exit 143 is the expected SIGTERM.
- Web-slice advice probes: a sort "by A then B" needs its own tiebreak probe (drop only `thenComparing`). A test whose input already arrives in B order lets the field-only sort survive; prove the fix with a temporary witness class (fails on the mutant, passes on real code), then rm it under the snapshot rule.
- Advice handlers: besides status, title, code, probe each handler's `details` argument separately (pass `List.of()` instead of `exception.details()`). Tests that only throw exceptions with empty details let that survive for the 404 and 409 handlers; the witness is a temporary web-slice test that builds the exception with the four-argument constructor (details non-empty) and asserts `$.details[0]...`; run it on real code, on each mutant, then `rm`.
- Forwarding handlers (`return exception.getBody()` for an `ErrorResponseException`, a details list built from a nested
  exception's message that names a configured limit): slice tests run with the production defaults, and the unit test
  of the producer stops at the exception, so a handler that hard-codes the default text survives everything. Probe it
  (`ProblemDetail.forStatusAndDetail(<status>, "<default text>")`); the witness passes a non-default exception through
  the handler (direct call or standalone MockMvc with the advice).
- Nested `@WebMvcTest` classes: Surefire puts their testcases in the outer class's XML and the summary names only the
  outer helper (`AssistantCommandsTest.problem:549`); take method names from the `<<< FAILURE!` lines of the log.
- Handler pass-through fix tasks enumerate handlers by the plan's list; count the DISTINCT codes the tests feed each handler yourself, including the sibling 503 (`UnavailableException`) handlers. Probe each with its code and title hard-coded (title-only variant too, to prove `$.title` is load-bearing); a handler fed one code only survives.
- PostgreSQL 18 catalogues NOT NULL constraints in `pg_constraint` (contype `n`, names `<table>_<col>_not_null`). A "constraint names" check must add `and contype <> 'n'`, and show `select contype, count(*) ... group by contype` to explain the extra rows.
- Live app vs MockMvc: a malformed JSON body gives Boot's `/error` JSON (`timestamp, status, error, path`, application/json) plus a `DefaultHandlerExceptionResolver` WARN in the app log; MockMvc shows an empty body. Classify that WARN as provoked by the malformed-body request, not as product code.
- Before trusting a spec claim about what a Jakarta constraint accepts, `javap -c` the validator class from the jar in `BOOT-INF/lib`. Hibernate Validator 9.x `NotBlankValidator` calls `String.isBlank()`, so any `Character.isWhitespace` character (U+2003, for example) is blank and gives 400. U+00A0 is not whitespace and passes. Send both as live controls; a "trims only up to U+0020" premise is false.
- A length rule written as a regex (`.{0,N}`, `@Pattern`) counts code points, but `@Size` and `String.length()` count UTF-16 chars. When a payload replaces `@Size` with a regex, send 122 x U+1F600 + `@example.com` (256 chars, 134 code points) as a witness: it gets past the payload and comes back as the domain's 422. Check the regex quickly in a single-file `java X.java` harness first.
- Payload-constraint fixes: run each variant as one script (copy the temp witness classes in, copy the variant over, one `clean test`, copy `.fixed` back, `mv` the witnesses out, compare the sha256). Also run the witnesses on the base; that shows whether a witness failure is new with the task.
- A curl `-i` response file read in Python text mode turns CRLF into LF, so `split("\r\n\r\n")` finds nothing and the parsed id is empty. Open the file with `newline=""`. Before a replay chains ids, check that the first parsed id is non-empty, because empty ids send later requests to `/books/` and still return plausible 404s.
- "Stored, not echoed" request fields (the response omits them by contract): MockMvc cannot see them, so probe the controller passing `null` instead. Witness: a temporary class in the same `@WebMvcTest` + `@Import(Service)` slice that `@Autowired`s the real service and reads the stored record after the 201.
- A probe that adds a record component breaks every constructor call (compile error, no evidence). To add a JSON key, add a `public String getX()` method to the record instead; Jackson serialises it.
- An advice made to extend `ResponseEntityExceptionHandler` while it handles `HttpMessageNotReadableException` itself fails context start ("Ambiguous @ExceptionHandler method mapped"), so every slice test errors. Quote that line, and say the type-mismatch test sees no response at all.
- Witness runs through the probe runner reuse `<id>.log` (CONTROL, the survivor id) and overwrite the batch logs. Give witness runs their own ids or a log suffix.
- Unscoped path-guarded advice that rethrows (405/415): probe set is guard -> always-API, guard removed per handler method, headers dropped, Accept collapsed to one type, content type removed / problem+json, status hard-coded, message without the method. The rethrow-same-exception claim is proven by one mutant that throws a NEW exception of the same type: the module log must then show `Failure in @ExceptionHandler` (baseline count 0). A guard on a handler type that no non-API route can raise (415 outside /api in the distributor: /mcp answers 400, actuator health 405) survives and is unobservable over HTTP; say so, suggest a direct unit test, do not FAIL.
- Spring Framework 7: `HttpHeaders` is no longer a `Map` (no `containsKey`/`put`); mutants use `getFirst`, `addAll(HttpHeaders)`, `setAccept`. A mutant that fails to compile gives no kill evidence: read the first lines of each probe log before tabulating.
- Shared `@Primary` fixed-clock test config (RANDOM_PORT): a thread-split probe clock in the production config cannot prove the fixed bean reaches the server, because both sides read the fixed bean. Add a control with the production clock fixed in a far year (must stay green). Dropping `@Primary` still compiles and starts: injection falls back to the bean NAME `clock`, so only a date assertion catches it. Removing the `@Import` from one class of the shared pair adds one `Started` line; count with `grep -c ' : Started '`. Check real-clock coincidences on the run day: a working-day literal can match the real date by chance, so find the assertion that actually bites (drop the import and the date pin) and name it.
- EnvironmentPostProcessor plus `@ConditionalOnProperty` (offline-mode switch): probe the `spring.factories` line (deleted, and moved to the old `org.springframework.boot.env.EnvironmentPostProcessor` key). On Boot 4.1.2 the old key gives a context failure, `is not assignable to factory type`, so it is killed. Also probe `addFirst` alone and the "unset" guard alone: source-list equality and last-source assertions kill each one separately. Probe `havingValue` dropped and `matchIfMissing=true` on an `ApplicationContextRunner` test. For an `isBlank()` guard, probe `trim().isEmpty()` too. ASCII witnesses (`"   "`, `"\t\n"`) let it survive, and only a `Character.toString(0x2003)` key kills it. `strip().isEmpty()` is equivalent to `isBlank()`. EPP order witness (property-source index): Boot appends `applicationInfo` and `Management Server` after every post-processor, so "after every source containing `application`" is red on correct code; compare against sources starting with `Config resource`. A test-side probe with the literal filter prints the real source list in its failure message. `@Order(HIGHEST_PRECEDENCE)` then fails only that witness: the blank-key test profile hides it.
- Keyed-referee greps for "no real API call" that contain a bare status code (`401`) match millisecond timestamps (`13:20:29.401`) and Maven repository metadata 401s from transitive parent POMs. Grep for named classes and hosts instead, and quote the 401 lines with their machine-local source (`grep -rl <repo id> ~/.m2/repository/... "--include=*.pom"`).
- View-controller config (`WebMvcConfigurer.addViewControllers`): a redirect view controller added on a path an annotated controller owns (`/books`) survives every test, because view controllers sit at order 1 and `RequestMappingHandlerMapping` at order 0 (`javap -p -c` of `ViewControllerRegistry.<init>` and `WebMvcConfigurationSupport`). Judge it equivalent with a temporary witness test that dumps status, Location, content type, Allow and body length for 6 methods x several paths, run on real code, the mutant and the mutant plus `registry.setOrder(-1000)`: identical diff for the survivor, visible diff for the ordered variant (the ordered variants are the killable form, probe those). `rm` the witness and prove it with a `grep -c`.

## MVC interceptor and validated config record

Rule: probe an interceptor feature by family (comparison, order, bounds, path pattern, wiring, advice) and add a temporary witness test for every survivor before calling it a gap.

**Why:** the unit test with fake clock/random/sleeper kills the logic mutants, but the production wiring (real sleeper, registered path set, advice content type) survives unless a slice test measures it.
**How to apply:**
- Path pattern probes: `/**`, `/api/*`, no `addPathPatterns`, `/api/titles/**`, and an enumerated list that omits one controller. Only a slice test with a non-`/api` 404 path (plus a prefix lookalike such as `/apiary`) and a two-segment `/api` path kills the first three; the enumerated list survives unless a test goes through every controller.
- A `/**` interceptor surfaces in MockMvc as `ServletException: Request processing failed: <ChaosException>` on an unmapped path (the scoped advice does not apply), not as a status: the kill reason to quote.
- Record validation: probe each check removed and each bound shifted one step on both sides (`<` vs `<=`, `-0.02`, `1.01`) and a NaN-accepting rewrite; `@DefaultValue` on primitive components is behaviour-equivalent when removed.
- Real-sleep wiring: mutants `Thread.sleep(0L)`, sleep body removed and sleeper `millis -> { }` all survive a fake-sleeper unit test. Witness: slice with `latency-ms=200`, time one call with `System.nanoTime()`, assert `>= 200` (lower bound, not flaky); green on real code, red on all three.
- Advice content type: a preset `.contentType(...)` skips Accept negotiation, so only a request with `Accept: application/problem+json` kills its removal; also probe the handler written without the shared `envelope(...)` helper.
- Slice context faults show as `ApplicationContext failure threshold (1) exceeded` on every later test: quote the first cause (`grep -o "No qualifying bean of type ..."`), not the repeated lines.
- "Exact, no double rounding" claims (BigDecimal request fields): `0.9999` and `500.0000000001` are distinct doubles, so a mutant checking `quantity.doubleValue()` with `q == Math.rint(q)` plus `intValue()` survives them. Only fractions below the double ulp at the bound (`500.00000000000001`, `1.0000000000000001`) kill it (201 with quantity 500 vs 400).
- A witness method with several lines stops at the first failing line, so a mutant run proves only that line. To prove each line, run the mutant again against a test copy with the earlier lines removed (`grep -v` into scratch, restore both files by hash).
- Per-draw random wiring: an `isInstanceOf(ThreadLocalRandom)` test cannot tell `ThreadLocalRandom::current` from a once-captured `ThreadLocalRandom.current()`; read the wiring line, and use a `RandomGenerator::getDefault` mutant as the kill witness.
- Waiting for a background batch: a foreground `bash <script>` with a bounded `until grep -q DONE` loop (under 600 s) works; Monitor tools do not keep a subagent alive.
