Rule: build your own token inventory before reading the implementer's table, then diff the two; prove each zero-token claim with your own script and a negative control.

**Why:** a table that says "every token" is only as complete as its author's list. The first T3 round missed two tokens that sit in prose, not in backticks ("PostgreSQL in Docker", "React storefront").
**How to apply:**
- Inventory script (`python3 -I`): backtick spans, plain `docs/` paths and glob lines of each staged file with file:line, auto-resolved with `git ls-tree` and `git grep` on the built sandbox; then read the staged text once more for unquoted facts (versions, ports, library, stack words), JSON keys and string values, bold UI terms and URLs the pack cites. Control: an in-memory copy with two misspelled tokens must report `grep-files 0` or `ABSENT`. Also grep the WHOLE pack for other spellings of a command; a second spelling in another spec is a product finding.
- Glob test: write your own (regex translator plus git `:(glob)` pathspec, frontmatter read by the script itself). Besides in-script widened globs, run a FILE-level control: `git clone` the sandbox into scratch, edit one rule's `paths`, and expect exit 1.
- Row check script: join the pack prompt lines (strip `> `, one space) and compare with the checklist literal and the guide line; copy the pack scenario block by line range and compare byte for byte; each GIVEN/WHEN/THEN fragment must appear in the checklist table. Typo controls must come out False (print which index you mutate: a control on a line without the replaced word proves nothing).
- Cheap claim audit and evidence files: list the implementer's scratchpad folder (`ls` only; a leftover `auth-probe.sh` and a jsonl contradicted "no transcript exists"; compare file times with the decision commit, wording defect not a rerun). `diff` evidence files against the raw copies, grep two raw lines per file; non-ASCII `rg -c "[^\x00-\x7F]"` (rg may be missing inside scripts: use python bytes) with a printf-built control; home-prefix, owner-handle and scratchpad-prefix grep with a positive control.
- Re-verification round: carry old runs over by hash (staged files vs the old sandbox via a script with a DIFF control, untouched evidence files by `shasum -a 256`). When the base ref moved, `git diff --stat old new -- . ":(exclude)<stripped dir>"` empty plus the same diff on the stripped file as positive control proves the stand-in tree is unchanged. A pinned guide branch: `git diff --stat oldsha branch -- guide/docs`.
- A rework that "replaces an evidence file by a fresh run" is the moment hygiene regresses: the raw sandbox output prints absolute scratchpad paths that the r0 file had replaced by placeholders. Re-run the C0-10 grep over the whole records folder every round, with a positive control (the grep must hit the raw run).
- README rework: `diff` the previous round's sandbox README against the new one (only the lines the Required Actions name, word for word). "For every file except X" scoping prefixes: prove each scoped sentence with counts (role tallies over the glob, `grep -c <ean>` in the .http file with a `GET ` positive control).
- Quote-lookup pass (catches altered literal quotes): per LINE (a regex over a whole section mis-pairs quotes) take every double-quoted string of 15+ chars, normalise whitespace, look it up in the union of pack, plan, guide pages (`git show <spec-11 branch>:<path>` inside the script), fetched docs pages (strip tags with `html.unescape`, also compare with whitespace removed; elided quotes: verify both ends) and staged files, leaving the files under test OUT of the union. Control: a mutated quote must be NOT FOUND. Whole-block byte compares missed a one-word insertion ("and") inside a prose cell.
- Per-OS rows ("the same as the macOS row"): re-check every OS-specific command against the tool's per-OS paths (jdtls data folder: Library/Caches on macOS, .cache on Linux, read from the wrapper source). Count upstream line citations yourself with `sed -n` (a neighbouring `elif` can sit inside the range). Path-prefix slicing makes a "mirror" check lie (fixtures under `nl/openvalue/archfixtures`: 35 fake counterexamples): print full offender paths before judging.
- "Insertion only" on an evidence file: keep the r0 raw copy or hash it against the r0 baseline, delete the claimed ranges from a copy of the new file, `cmp`, and read the first differing byte with `od -c`. A prefix-hash search (head -c N, python sha256 over every prefix length) proves a pure append; non-append insertions need the token-level greedy subsequence (`\w+|\s+|[^\w\s]`, plus a changed-number control: char-level difflib can hide one). The editorconfig trim hides a stripped trailing space, so compare again with trailing whitespace stripped.
- Lifecycle premises in rehearsal rows (which request starts the language server, when a plugin or MCP server loads): a row that measures from "the first request" rests on a trigger nobody sourced. Fetch the docs page for the component AND the tools-reference page, grep the trigger sentence, and dry-run the row for both outcomes: each needs an observation, a stopwatch start and a failure judgement.
- Fallback that flips a staged file or manifest row (J15 style): prove each branch on COPIES of the staging tree with a 2x2 (edit present or absent, outcome A or B), editing the copy's manifest AND its staged file (else "not named by any manifest row"); an "edit X is needed" sentence is often true for only one outcome (`replace` on a missing target dies, `add` on an existing one dies). Use python for row edits (BSD sed cannot put a tab in a replacement).
- Hooks docs: a field documented as "blocks when a hook fails" can widen what blocks (the changelog said "exits with an unexpected code"). Read the changelog entry and the exit-code section, then check pack comments such as "any other non-zero code does NOT block" against it; verbatim text is a product finding, not a rework target.
- False-universal search over a cheat sheet or skill reference file ("X has/is/does Y", "every ..."): enumerate EVERY generic sentence yourself, then count instances on the base ref with a python script (`git show`/`git ls-tree`, strip comments AND string literals before name matching). Judge by unit (per public method, package, file); a trace row to the standard does not make a descriptive sentence true; an author's "failures: 0" can still skip whole sentences, so diff its claim list against yours. A bullet list under "Rules that apply to every use case" is itself a universal; prescriptive bullets make it tolerable, note role-specific rules as a nit.
- Re-audit after a "make it prescriptive" rework: (1) rebuild the claim census per package from imports AND fully qualified names, comments/strings stripped; (2) census every money-like field with its type per package; (3) audit the author's per-unit table with your own unit splitter (first 25 chars, line within 4, dropped-unit control); (4) low-overlap citations are usually multi-line claims or headings: print the cited lines; (5) a negative `git grep` needs a positive control on the same pathspec.
- Rehearsal-row dry run (git rows): clone with the row's OWN recipe (`git clone --branch <real branch name>` from a repo that has that branch; a stand-in on `main` made a literal `git status -sb` line wrong), execute every undo sequence of a variant and run the NEXT variant (`git reset --hard <sha>` after a commit drops a staged-only change: use `--soft`), and check what the undo leaves behind (a `remote set-url` to a scratch bare repo survives `clean -fdx`).
- Literal expected output in a row (`Permission denied`) depends on the shell that runs the command: run it under sh, bash, zsh and dash (zsh prints lowercase `permission denied`); a hedged "should" plus "quote what you see" is acceptable, a literal match is not.
- Directive-driven row checks that are easy to miss: every commit-hook row runs plain and chained and lists the quoted-path bypass; every "expects a block for exit 1 / timeout" needs an observation or an openly "documented expectation" in a row, not only in the record's table; harness cases named "could not start mvnw" test the build inside the hook, not a hook that cannot start.
- Framework generator re-runs (Spec Kit `specify init`, OpenSpec, Agent OS) under `env -i` with isolated HOME/XDG/uv dirs: the init fails ("claude not found", exit 1) unless a `claude` file is on PATH, so put a stub script (exit 97, logs any call) in a scratch bin dir and show the log file never appears (shutil.which only). Without a Python 3.11+ on PATH uv downloads a managed CPython (about 2400 paths) into XDG_DATA_HOME, so compare user-level path lists by group, not total; read `cut -f1-4` manifests with all columns (5th is mode). Row literals ("prints 29 lines"): run the row's own command verbatim and compare; plain `git status --short` folds a new folder to one line (10 vs 29), my r0 used a variant and missed it. Never repeat a record's "skill :98-105 says X" without reading those lines (it was false).
