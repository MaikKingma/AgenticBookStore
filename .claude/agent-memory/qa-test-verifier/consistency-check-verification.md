  type: feedback

Rule: build your own token inventory before reading the implementer's table, then diff the two; prove each zero-token claim with your own script and a negative control.

**Why:** a table that says "every token" is only as complete as its author's list. The first T3 round missed two tokens that sit in prose, not in backticks ("PostgreSQL in Docker", "React storefront").
**How to apply:**
- Inventory script (`python3 -I`): backtick spans, plain `docs/` paths and glob lines of each staged file with file:line, auto-resolved with `git ls-tree` and `git grep` on the built sandbox; then read the staged text once more for unquoted facts (versions, ports, library, stack words). Control: an in-memory copy with two misspelled tokens must report `grep-files 0` or `ABSENT`.
- Glob test: write your own (regex translator plus git `:(glob)` pathspec, frontmatter read by the script itself). Besides in-script widened globs, run a FILE-level control: `git clone` the sandbox into scratch, edit one rule's `paths`, and expect exit 1.
- Row check script: join the pack prompt lines (strip `> `, one space) and compare with the checklist literal and the guide line; copy the pack scenario block by line range and compare byte for byte; each GIVEN/WHEN/THEN fragment must appear in the checklist table. Typo controls must come out False (a first control that edits a line without the replaced word silently proves nothing: print which index you mutate).
- Cheap claim audit: list the implementer's scratchpad folder (`ls` only). A leftover `auth-probe.sh` and a jsonl under a probe HOME contradicted a record sentence "no transcript exists". Compare file times with the commit time of the decision (D14) before judging; wording defect, not a rerun.
- Evidence files: `diff` them against the raw scratchpad copies and grep two raw lines per file; `rg -c "[^\x00-\x7F]"` with a printf-built control; `grep -rn '<home-prefix>/|<owner-handle>|<scratchpad-prefix>'` with a `~/.claude` positive control.
- Re-verification round: carry old runs over by hash (staged files vs the old sandbox via a script with a DIFF control, untouched evidence files by `shasum -a 256`). When the base ref moved, `git diff --stat old new -- . ":(exclude)<stripped dir>"` empty plus the same diff on the stripped file as positive control proves the stand-in tree is unchanged. A pinned guide branch: `git diff --stat oldsha branch -- guide/docs`.
- A rework that "replaces an evidence file by a fresh run" is the moment hygiene regresses: the raw sandbox output prints absolute scratchpad paths (owner handle and session id inside the folder name) that the r0 file had replaced by placeholders. Re-run the C0-10 grep over the whole records folder every round, not only on the file the Required Actions name, and keep a positive control (the grep must hit the raw run).
- Doc-only README rework: `diff` the previous round's sandbox README against the new one (kept per round in the scratchpad); the diff must show only the lines the Required Actions name, each word for word.
- "For every file except X" scoping prefixes in a README: prove each scoped sentence against the data it still covers with counts (role and currency tallies over the glob, `grep -c <ean>` in the .http file with a `GET ` positive control), and diff the last accepted sandbox README against the new one so only the prefixed lines show.
- Quote-lookup pass (catches altered literal quotes): per LINE (a regex over a whole section mis-pairs quotes) take every double-quoted string of 15+ chars in the rows and the record, normalise whitespace, and look it up in the union of pack, plan, guide pages (`git show <spec-11 branch>:<path>` from inside the python script), fetched docs pages (tags stripped) and staged files. Control: a mutated quote must be NOT FOUND. Byte-comparing whole quote blocks and fragment checks both missed a one-word insertion ("and") in a "Plan:" quote that sat inside a prose cell.
- Own inventory beyond backticks: JSON keys and string values of the staged files, bold UI terms, and URLs the pack itself cites; diff them against the record by literal grep (control: misspelled copy). Also grep the WHOLE pack (not only the specs the record names) for other spellings of a command; a second spelling in another spec is a product finding.
- A row that says "the same as <macOS row>" for Linux or WSL: re-check every OS-specific command in the macOS row against the tool's per-OS paths (jdtls data folder is under Library/Caches on macOS and .cache on Linux, read from the wrapper source). A copied command is vacuous on the other OS.
- Zero-model MCP proof recipe: python `http.client` POST `initialize` with `Accept: application/json, text/event-stream`, read `Mcp-Session-Id`, POST `notifications/initialized` (202), then `tools/list` (answers as SSE: parse the `data:` line); controls compare the set with a misspelled and a reduced copy.
- "Insertion only" claim on an evidence file: keep the r0 raw copy (hash it against the r0 baseline), delete the claimed line ranges from a copy of the new file, `cmp` against r0, and read the first differing byte with `od -c`. A prefix-hash search (head -n N) fails when the insertions are not a pure append, and a stripped trailing space only shows at the byte level.
- Quote lookup against fetched docs pages: strip tags with `html.unescape` first, then also compare with all whitespace removed; page markup splits code spans (`${VAR:-default}`) so a plain text grep on the HTML says 0 while the sentence is there. Elided quotes ("a ... b"): verify both ends separately in the source line.
- Upstream line citations (e.g. a wrapper's per-OS branches): count the lines yourself with `sed -n` before judging a range; a neighbouring `elif` (Termux) can sit inside the range you thought was the Linux branch.
- Lifecycle premises in rehearsal rows (which request starts the language server, when a plugin or MCP server loads): a row that measures from "the first request" rests on a trigger nobody sourced. Fetch the docs page for the component AND the tools-reference page, grep the trigger sentence, and dry-run the row for both outcomes (trigger fires or not): each needs an observation, a stopwatch start and a failure judgement. Keep the baseline of the previous round: with only a hash, rebuild it (older copy plus the inserted line, compare hash), then diff "new minus added lines" against it and again with trailing whitespace stripped (the editorconfig trim hides one space at the old last line).
- Fallback notes that flip a staged file (drop a row, drop keys): prove them on a scratch COPY of the staging tree (edit the copy's manifest AND remove its staged file, or the build fails for the wrong reason: "not named by any manifest row"). A later `replace` row on that target then dies "target does not exist"; the note must name the op flip to `add`.
- Hooks docs: a field documented as "blocks when a hook fails" can widen what blocks (the changelog said "exits with an unexpected code"). Read the changelog entry and the exit-code section, then check pack comments such as "any other non-zero code does NOT block" against it; verbatim text is a product finding, not a rework target.
- Doc-edit round (checklist rows): token-level greedy subsequence (`\w+|\s+|[^\w\s]`) proves insertion only; a char-level subsequence or difflib "insert only" can hide a changed number, so keep a changed-number control. Line-cited traces: a 7-line shifted-citation control must lose overlap on most rows.
- False-universal search over a cheat sheet or skill reference file (rule-of-thumb sentences "X has/is/does Y", "every ..."): enumerate EVERY generic sentence yourself (not the author's list), then count instances on the base ref with a python script (`git show`/`git ls-tree`, strip comments AND string literals before name matching, or prose in javadoc/strings gives false hits). Judge by unit: per public method (a flow's read methods are use cases), per package (adapters may carry prices as Strings), per file. Sentences copied from the standard still need counterexamples checked; a trace row to the standard does not make a descriptive sentence true. An author's own search that reports "failures: 0" can still skip whole sentences: diff its claim list against yours.
- Path-prefix slicing bugs make a "mirror" check lie: fixtures lived at `nl/openvalue/archfixtures`, a length-sliced prefix produced 35 fake counterexamples. Print full offender paths before judging.
- Re-audit after a "make it prescriptive" rework: (1) rebuild the claim census per package from imports AND fully qualified names with comments/strings stripped (project deps, external roots, who uses each framework prefix); (2) census every money-like field with its type per package, so a "carry X as T" rule is checked against all layers, not one regex; (3) audit the author's per-unit table with your own unit splitter: every one of your units must be covered by a table unit (first 25 chars, line within 4), with a dropped-unit control; (4) low-overlap citations are usually multi-line claims or headings: print the cited lines before judging; (5) a negative `git grep` needs a positive control on the same pathspec (`-c` on a token that must exist).
- Heading trap: a bullet list under "Rules that apply to every use case" is itself a universal over its bullets; prescriptive bullets make it tolerable, but note role-specific rules under it as a nit.
