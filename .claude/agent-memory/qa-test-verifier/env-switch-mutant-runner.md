---
name: env-switch-mutant-runner
description: Run many mutation probes cheaply with one schema-mutant file per production class selected by an env variable, plus a runner script that restores by cp and compares hashes
metadata:
  type: feedback
---

Rule: when a probe list has 20+ mutants on a few small classes, write one "mutant schema" copy of each class in the scratchpad that switches on `System.getenv("QA_PROBE")` (unset = original behaviour), and drive it with a runner script in `.claude/comms/tmp/`.

**Why:** one Edit per mutant costs a tool call per probe plus a restore. A WebMvcTest-sized run is about 4 s with `clean`, so 50 probes finish in about 4 minutes in the background, and the env variable reaches the forked Surefire JVM unchanged.
**How to apply:**
- Per probe the script does: `cp` mutant over the production file, `QA_PROBE=<id> bash with-budget.sh 300 ./mvnw -pl <module> clean test -Dtest=<Class>`, `cp` the FF7 `.orig` back, `shasum` all touched files and compare with the snap-before, then append one result line (id, rc, hash flag, summary line, failing test lines).
- When a later round reuses round 1 `.orig` copies, make the runner abort unless every `.orig` is hash-equal to the live production file. A stale `.orig` would otherwise silently restore old bytes.
- Prove the schema first with a CONTROL run (all mutants in place, variable unset): same green count as the real code. A killed probe then also proves the variable reaches the JVM.
- Compare hashes only against the `^[0-9a-f]{64}` lines of the snapshot; the `git status` lines in the same file also match a filename grep and gave false mismatches.
- Parameterized tests: grep the failing `[n]` index per probe (for example `grep -oE 'With400\(String\)\[[0-9]\]'`) to show which input killed which mutant.
- Do not edit a running script (bash reads it incrementally); stop the background task with TaskStop, fix, restart.
- Keep two or three plain Edit probes for things a schema cannot express (annotation attribute removed, `@ExceptionHandler` removed).
- Run the final referee after the last probe, even if the last probe restored identical bytes; the order proof stays clean.
- Take the `.orig` copies and restore with `cp -p`: product mtimes stay the implementer's, so the C0 order proof (impl artifact, newest product file, snap-after, Surefire XML) still reads correctly.
- Probe target classes get mutant bytecode in `target/classes`; run `javap` inspections only after the referee rebuild, never between probes.
- FF8 "one sort probe per distinct permutation": first list, for each column and both directions, which row permutation its sort gives. Probe one representative per distinct result. Then add a reversal probe for any non-identity permutation no column gives (for 3 rows there are 5). Use stable `Comparator` sorts on the view record in the schema. A column that is constant because of a domain invariant (for example a single-currency `Money`) is exempt; cite the invariant's file:line.
- Shared translator (one private static translator called from many sites): give the schema's translator a `site` string argument. Each catch then rethrows when `P("F19<type>")` or `P("F19<type>@<site>")` is set, which yields the global and the per-call-site probes from one file. Column-sort families fit one switch on a prefix (`QA_PROBE=SV-onhand-desc`, parsed into a comparator). Add a new probe family in a schema2 copy with its own runner, never by editing the schema while a batch reads it. A flow-test run with `clean` takes about 4 s, so 140 probes finish in about 9 minutes.
- Alternative when mutants touch annotations, `@Query` strings or SQL migrations (no env switch possible): write a `python3 -I` generator in the scratchpad that builds one full mutant file per probe from the `.orig` by exact replacement and aborts unless each old string occurs exactly once. A positional-args filter lets you add probes later without rewriting files the running batch may read. The runner then installs `mut-<id>--<File>` files and saves a `diff` per probe.
- Prefix-parsed families swallow every id that shares the prefix: `EV-rev` under an `EV-<col>-<dir>` parser hits the comparator's `default -> throw`, so the run fails and looks like a kill. Give one-off probes an id outside every parsed prefix (`EVREV`), or make the parser ignore unknown columns, and keep a CONTROL in each schema batch.
- Witness columns include joined ones: fixed fixture constants (for example ISBNs of BOOK_1..3) can be monotone in the asserted order in every test that uses them. Probe sorts by any column the mutated method can reach (a loaded DTO map, order line snapshots), not only the asserted record's fields.
- Before writing families, inventory every order the code produces: each `sort(` call (in every command, not only the one the plan names), each collected list (errors, events), each loop over a map, and each child list of a saved aggregate. Give every site its own family over every column of the element, its joined entity and the loaded pre-mutation DTO values. A site without a family is the gap a reviewer finds first.
- Tabulate with a `python3 -I` script whose data rows are literal snippets it first asserts occur in the live test file; one monotone input column a locked asserting line forces is acceptable only with a run showing its sort probe killed by another test.
- Watch the result file with a Monitor `until`-style script that prints new lines and exits at the expected count. Background probe runs then report as they land.

- Bean-validation payload probes (WebMvcTest, about 4 s each with `clean`, 60 probes in about 5 minutes): the generator in the bullet above fits. For a repeated regex class (`[^@\x00-\x20]` three times) probe per position and per side of the bound: space rejected (`\x20` to `\x1F`), `!` accepted (`\x20` to `\x21`), control char accepted (`\x00` to `\x0A`), `@` removed, `+` to `*`. Tests that feed the accepted side only in the first class leave the other positions alive.
- A deprecation warning that moved an annotation position (HV000271, `@Valid` on a container): reproduce it as a probe that restores the old position and `grep -c` the probe's own log, so the "warning gone" claim rests on your evidence, not the implementer's log.

- Web-slice query adapters (about 4 s per `-Dtest=<Slice>` run, 115 probes in about 10 minutes): the generator-plus-runner pair above, with a Monitor script that exits at the `DONE` line. Sort families inject `.sorted(Comparator.comparing((Dto o) -> key))` (+ `.reversed()`, nulls-first/last for nullable columns, `collectingAndThen(toList, reverse|rotate)`) at each stream site, one per DTO attribute and derived value. Check `Money` for single-currency exemptions before calling a constant-column survivor a gap (`domain/Money.java` accepts EUR only, so currency sorts are equivalent).
- A direct handler test and a MockMvc test kill different handler mutants: a blank `" "` detail or a hard-coded field survives MockMvc `isNotEmpty()` and needs the direct `isNotBlank()` or a second field value. Keep both and probe each.

- Pure-logic services (search/filter/sort/paging, working-day loops) in the distributor: the generator style fits best (`id`, `file`, list of exact old/new pairs, abort unless each old occurs once). Cover per filter the variants first-only, last-only, allMatch, case-sensitive on each side separately, and "OR" per pair; for paging add `to` plus/minus 1 and an int-overflow offset. `offset >= size` vs `>` is an equivalent mutant (`subList(n,n)` is empty). A runner env `QA_EXTRA_CLASS` adds a second test class to one probe.
- Clock-consumer probes (FF3): run the C0 clock grep WITH the mutant installed in a small script (install, grep, `cp -p` restore, hash). `LocalDate.now()`/`Clock.system*` mutants are gate-killed; a UTC-date variant (`ofInstant(..., UTC)`, `withZone(UTC)`) evades the grep and only the zone test kills it.
