Rule: when a probe list has 20+ mutants on a few small classes, write one "mutant schema" copy of each class in the scratchpad that switches on `System.getenv("QA_PROBE")` (unset = original behaviour), and drive it with a runner script in `.claude/comms/tmp/`.
**Why:** one Edit per mutant costs a tool call per probe plus a restore. A WebMvcTest-sized run is about 4 s with `clean`, so 50 probes finish in minutes in the background, and the env variable reaches the forked Surefire JVM unchanged.
**How to apply:**
- Per probe the script does: `cp` mutant over the production file, `QA_PROBE=<id> bash with-budget.sh 300 ./mvnw -pl <module> clean test -Dtest=<Class>`, `cp -p` the `.orig` back, `shasum` all touched files and compare with the snap-before, then append one result line (id, rc, hash flag, summary line, failing test lines). `cp -p` keeps product mtimes the implementer's, so the order proof (impl artifact, newest product file, snap-after, Surefire XML) still reads correctly.
- Prove the schema first with a CONTROL run (all mutants in place, variable unset): same green count as the real code. A killed probe then also proves the variable reaches the JVM. Parameterized tests: grep the failing `[n]` index per probe to show which input killed which mutant.
- Do not edit a running script (bash reads it incrementally); stop the background task with TaskStop, fix, restart. Add a new probe family in a schema2 copy with its own runner. Keep two or three plain Edit probes for things a schema cannot express (annotation attribute removed, `@ExceptionHandler` removed). Run the final referee after the last probe.
- Trap: after a `cp -p` restore the source is OLDER than the probe's class, so a Maven run without `clean` prints `Nothing to compile` and tests the mutant/base bytecode (a negative control's green re-run then looks red). Every run after a swap or restore uses `clean`, including the first gate or JaCoCo run after a batch; grep `Compiling|Nothing to compile` as proof. Directive-given commands (the reverse-order run) are often written without `clean`: add it.
- "One sort probe per distinct permutation": first list, for each column and both directions, which row permutation its sort gives. Probe one representative per distinct result, then a reversal probe for any non-identity permutation no column gives (for 3 rows there are 5). Use stable `Comparator` sorts on the view record in the schema. A column constant because of a domain invariant (single-currency `Money`: `domain/Money.java` accepts EUR only) is exempt; cite file:line.
- Shared translator (one private static translator called from many sites): give the schema's translator a `site` string argument. Each catch then rethrows when `P("F19<type>")` or `P("F19<type>@<site>")` is set, giving the global and per-call-site probes from one file. Column-sort families fit one switch on a prefix (`QA_PROBE=SV-onhand-desc`, parsed into a comparator).
- Alternative when mutants touch annotations, `@Query` strings or SQL migrations (no env switch possible): a `python3 -I` generator builds one full mutant file per probe from the `.orig` by exact replacement and aborts unless each old string occurs exactly once; a positional-args filter lets you add probes later without rewriting files a running batch reads. The runner installs `mut-<id>--<File>` files and saves a `diff` per probe.
- Prefix-parsed families swallow every id that shares the prefix: `EV-rev` under an `EV-<col>-<dir>` parser hits the comparator's `default -> throw`, so the run fails and looks like a kill. Give one-off probes an id outside every parsed prefix (`EVREV`), and keep a CONTROL in each schema batch.
- Before writing families, inventory every order the code produces: each `sort(` call (in every command, not only the one the plan names), each collected list (errors, events), each loop over a map, each child list of a saved aggregate. Give every site its own family over every column of the element, its joined entity and the loaded pre-mutation DTO values. A site without a family is the gap a reviewer finds first.
- Web-slice query adapters: sort families inject `.sorted(Comparator.comparing((Dto o) -> key))` (+ `.reversed()`, nulls-first/last for nullable columns, `collectingAndThen(toList, reverse|rotate)`) at each stream site, one per DTO attribute and derived value. Use a foreground wait script that exits at the `DONE` line ([[shell-traps]]).
- Bean-validation payload probes (WebMvcTest): for a repeated regex class (`[^@\x00-\x20]` three times) probe per position and per side of the bound: space rejected (`\x20` to `\x1F`), `!` accepted (`\x20` to `\x21`), control char accepted (`\x00` to `\x0A`), `@` removed, `+` to `*`. Tests that feed the accepted side only in the first class leave the other positions alive.
- "Padding = exactly the trim() set" needs a witness in EACH rule that carries padding: when the length rule is a validator and padding lives only in the shape `@Pattern`, the strip-set padding variant (`[\x00-\x20\p{javaWhitespace}]*`) survives a lone-U+2003 test (U+2003 is already a legal core char). Its killer is U+2003 next to an ASCII space (`em + " <addr>"`, `"<addr> " + em`): 400 real, 202 mutant.
- Pass-through string fields (an ISBN, a code): probe case mutants in BOTH directions (`toLowerCase`, `toUpperCase`) plus `strip`, `trim`, hyphen removal and digits-only. Digit-only or all-lowercase witnesses kill one direction only; an ISBN-10 with check character `X` is the natural upper-case witness. Compare witness ids with the real producer's format (the distributor's restock ids are lowercase `UUID.randomUUID()` strings, so all-uppercase test ids let `toUpperCase` survive every copy path) and read the kill reason: a case mutant "killed" only by a null-id row's NPE is no case witness. For a `@Pattern` regex literal fixed by an AC, probe `[+-]?`, trailing `\s*`, `\p{Nd}`, `\d{1,2}` decimals and a digit-count cap (informational unless an AC pins behaviour).
- Pure-logic services (search/filter/sort/paging, working-day loops): generator style (`id`, `file`, list of exact old/new pairs). Cover per filter first-only, last-only, allMatch, case-sensitive on each side separately, and "OR" per pair; for paging add `to` plus/minus 1 and an int-overflow offset. `offset >= size` vs `>` is an equivalent mutant (`subList(n,n)` is empty). A runner env `QA_EXTRA_CLASS` adds a second test class to one probe.
- Clock-consumer probes: run the C0 clock grep WITH the mutant installed in a small script (install, grep, `cp -p` restore, hash). `LocalDate.now()`/`Clock.system*` mutants are gate-killed; a UTC-date variant (`ofInstant(..., UTC)`, `withZone(UTC)`) evades the grep and only the zone test kills it. Tests can pass a "time only in the base" grep by spelling: `LocalDate.ofInstant(clock.instant(), clock.getZone())` is `LocalDate.now(clock)`. Also grep `ofInstant(` in tests and judge the argument.
- Identity-equality checks (`x.equals(y)` guard in a flow): the op set per position is `a.op(b)` and `b.op(a)` for startsWith, endsWith AND contains, plus strip, stripLeading, stripTrailing, trim, a stripLeading().stripTrailing() chain, strip-then-op variants, either-direction ORs, equalsIgnoreCase (equivalent for digit-only values), length-only, hyphen removal; include the reversed-receiver sibling of EVERY one-sided check in round 1. Witness rows: different whole value, raw/hyphenated form, null, longer with expected as prefix, trailing space, leading extension, truncated answer. Prove a proposed missing row with a temporary test patched from the `.orig` (perl exact replace), run vs fix and the survivors, restore by `cp -p`, compare hashes.

Rule: build seed-data mutants with one `python3 -I` generator that loads the `.orig` copy, mutates the parsed objects and re-serialises in the file's own layout, and first asserts that re-serialising the UNMUTATED data is byte-identical to the original.
**Why:** without the identity assert, a formatting difference (spacing, key order, trailing newline) makes every data probe differ in many places, so a kill can come from layout instead of the intended value.
**How to apply:**
- One-object-per-line arrays: `"[\n" + ",\n".join(json.dumps(o) for o in items) + "\n]\n"` reproduced the file exactly; check yours with the assert. Non-ASCII probes need `ensure_ascii=False` and a UTF-8 write, or the probe silently tests nothing.
- Count guards: probe each count at minimum minus one (must fail) AND all counts at exactly the minimum in one combined must-pass probe (kills `>` written for `>=`). Reduce counts by flipping extras to a neutral value that keeps every other invariant (IN_STOCK needs quantity above 0; removing a subject code must not empty the list or drop the last use of a labelled code).
- Line-ending neutrality: a must-pass probe with CRLF copies of every seed file; prove the mutant really holds `\r\n` with `od -c` before trusting the green run.
- Run the same runner as code probes and add a CONTROL that installs the original bytes through it. Read the seed for analysis scripts from the `.orig` copies while probes run; the live file is a mutant half of the time.
- SQL seed with a repeatable Flyway migration (idempotent `INSERT ... ON CONFLICT DO NOTHING`): build an independent census as a `python3 -I` SQL parser (distributor files as oracle) plus ~50 one-rule negative-control copies (each must exit 1 with its own `FAIL <rule>`; anchor on a unique neighbour string because titles and ISBNs recur in order lines).
- "Developer edits survive a rerun" tests are only as strong as the columns they edit: probe `DO UPDATE SET <col> = excluded.<col>` once per table and per column the test does NOT touch. A delete followed by re-insert cannot tell DO NOTHING from DO UPDATE. A target-less `ON CONFLICT DO NOTHING` swallows every unique violation, so a "duplicate" mutant dies on a different assertion than expected (an FK violation in `@BeforeAll`): read the failing message before attributing the kill. A price with one decimal (`23.5`) is an equivalent mutant (`numeric(10,2)` pads).
- Seed GROWTH (rows appended to existing statements): prove "old rows unchanged" with a `python3 -I` diff script (old non-comment lines a byte-exact ordered subsequence of the new file; only the last row of each grown VALUES list may gain a comma; new-only lines allowed directly before that statement's `ON CONFLICT`; untouched statements compared as one byte tail) plus ~12 one-change controls. A paired genre swap (old row to X, new row to Y) survives the census and only this script kills it. Derive per-statement new-row counts in the script and assert them: prose counts drift ("66 author rows" was 65).
- `-Dtest=A+B` runs ZERO tests in this Surefire (BUILD SUCCESS, no `Running` line); use `A,B`. It writes no `timestamp` attribute in the XML: take class order from the log's `Running` lines and XML mtimes. A hand-timed `date +%s` around the referee runs ~12 s above Maven's "Total time": quote both. `pg_dump` 18 prints a random `\restrict <token>` line per dump: filter `^\\(un)?restrict ` before hashing two dumps for a "restart leaves data unchanged" proof.
