Rule: with 20+ mutants on a few small classes, write one "mutant schema" copy of each class in the scratchpad that switches on `System.getenv("QA_PROBE")` (unset = original behaviour) and drive it with a runner script in `.claude/comms/tmp/`.
**Why:** one Edit per mutant costs a tool call plus a restore; a WebMvcTest-sized run is about 4 s with `clean`, so 50 probes finish in minutes in the background, and the env variable reaches the forked Surefire JVM unchanged.
**How to apply:**
- Per probe: `cp` mutant over the production file, `QA_PROBE=<id> bash with-budget.sh 300 ./mvnw -pl <module> clean test -Dtest=<Class>`, `cp -p` the `.orig` back, `shasum` all touched files against the snap-before, append one result line (id, rc, hash flag, summary line, failing tests). `cp -p` keeps product mtimes, so the order proof (impl artifact, newest product file, snap-after, Surefire XML) still reads correctly.
- Prove the schema first with a CONTROL run (all mutants in place, variable unset): same green count as real code; a killed probe then also proves the variable reaches the JVM. Parameterized tests: grep the failing `[n]` index per probe to show which input killed which mutant.
- Do not edit a running script (bash reads it incrementally): TaskStop, fix, restart; add a new family in a schema2 copy with its own runner. Keep two or three plain Edit probes for what a schema cannot express (annotation attribute removed, `@ExceptionHandler` removed). Run the final referee after the last probe.
- Trap: after a `cp -p` restore the source is OLDER than the probe's class, so Maven without `clean` prints `Nothing to compile` and tests the mutant bytecode (a negative control's green re-run looks red). Every run after a swap or restore uses `clean` (grep `Compiling|Nothing to compile` as proof); directive-given commands are often written without `clean`: add it.
- Without an env switch (annotations, `@Query`, SQL migrations): a `python3 -I` generator builds one full mutant file per probe from the `.orig` by exact replacement, aborting unless each old string occurs exactly once; a positional-args filter lets you add probes later without rewriting files a running batch reads; the runner installs `mut-<id>--<File>` and saves a `diff` per probe.
- Prefix-parsed families swallow every id sharing the prefix: `EV-rev` under an `EV-<col>-<dir>` parser hits `default -> throw`, so the run fails and looks like a kill. Give one-off probes an id outside every parsed prefix, and keep a CONTROL per batch.
- Before writing families, inventory every order the code produces: each `sort(` call (in every command, not only the planned one), each collected list (errors, events), each loop over a map, each child list of a saved aggregate; give each site a family over every column of the element, its joined entity and the loaded pre-mutation DTO values. A site without a family is the gap a reviewer finds first.
- "One sort probe per distinct permutation": list for each column and direction the row permutation it gives, probe one representative per distinct result, then a reversal probe for any non-identity permutation no column gives. Columns constant by a domain invariant (single-currency `Money`) are exempt: cite file:line. Web-slice query adapters: inject `.sorted(Comparator.comparing(...))` (+ `.reversed()`, nulls-first/last, `collectingAndThen(toList, reverse|rotate)`) at each stream site.
- Identity-equality guard (`x.equals(y)`): per position `a.op(b)` and `b.op(a)` for startsWith, endsWith, contains, plus strip variants, trim, either-direction ORs, equalsIgnoreCase (equivalent for digit-only), length-only, hyphen removal; include the reversed-receiver twin of EVERY one-sided check in round 1. Witness rows: different whole value, hyphenated form, null, longer value with expected as prefix, trailing space, leading extension, truncated answer. Prove a missing row with a temporary test patched from `.orig` (perl exact replace), run vs fix and survivors, restore by `cp -p`, compare hashes.
