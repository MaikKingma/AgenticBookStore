Rule: probe the Node harness with one fs-based runner script, not shell edits.
**Why:** a runner that edits in place, runs, records the exit code and restores from `cp -p` byte copies keeps probes honest and fast (`npm run check` about 1 s, a Docusaurus build about 2 s); hash equality with the snap-before file proves the restore.
**How to apply:**
- Runner in `.claude/comms/tmp/` as an ASCII `.mjs` (forbidden characters via `String.fromCodePoint`). Ops: write, append, replaceOnce with an exact-occurrence guard (a stale `from` string shows as SETUP ERROR, not a kill). Restore touched files, delete created ones, compare product hashes at the end. `cpSync` loses mtime: finish with `touch -r <orig copy> <file>` when evidence timing matters.
- Mutants run `node --test "scripts/**/*.test.mjs"` through `spawnSync` with the glob unexpanded; collect `✖` lines (skip the summary `✖ failing tests:`). `npm run check` is `node --test` THEN `node scripts/check.mjs`; run the layers separately, because fixtures reading the real CSS fail first and mask whether the checker itself catches the defect. Check equivalent survivors (removing a `sort()` is unobservable on APFS).
- Node 26 type stripping cannot import `docusaurus.offline.config.ts` (extensionless import): copy both to the scratchpad, symlink `node_modules`, rewrite that import to `.ts`, flatten-diff.
- Anti-vacuity gaps: a glob matching nothing exits 0 (`tests 0`); emptied test files count as passing; probe a literal-text rule against code blocks, inline code and a NUL-byte file. Invalid `package.json` makes `npm` refuse every script. Never run `npm --prefix guide exec -- node ...` (fetched node@27 alpha, 0 tests): run node from a script that `cd`s into guide/.
- Offline matcher: WebKit's pageerror is `XMLHttpRequest cannot load file: //...` with no `Error: ` prefix; match `^(Error: )?XMLHttpRequest cannot load file:.* due to access control checks\.$`. Playwright Firefox `context.route` never sees `file://`, so "aborted 0" proves nothing until `fetch('https://example.com/x')` moves the abort counter 0 -> 1 in every engine.

Rule: for a checker with pure rule modules, mutate the WIRING (`runChecks`, site-rules glue, CLI default root, option names), not only the rule functions.
**Why:** a rule module at 100 % coverage with every unit mutant killed can still be dropped by the pipeline (errors discarded, report lines not printed, option off, wrong root). Deleting one entry of a declarative table (contrast pairs, anchors) survives unless a test pins the table.
**How to apply:**
- Minimum list: one mutant per `report(...)`, per `errors:` spread, per `lines.push(...)`, warning instead of error, ban not called, first or last page dropped, wrong root, predicate substring or startsWith, no sort, message without page; plus a generated "remove one entry of every table" probe (and a "lower the pin with the removal" control that must still fail by name).
- Reinsertion probe: put the banned token before `## Level cleared when`, never at the end (an appended comment breaks structure rules). Keep byte copies OUTSIDE `docs/`. With a marker back, `npm run check` fails first in node:test; the ban's own stderr line shows only from `node scripts/check.mjs`. Quote both. A positional root skips an opt-in rule by design.
- Follow-up gate: prove each new witness as a PAIR in a scratch copy: old mutants with the previous gate's test file must SURVIVE, with the new file DIE. Pin error line numbers too (off-by-one survived). Deleting a required new sentence survives every automated gate: say manual-only.

Rule: for a Markdown/MDX structure checker, probe the syntax variants the renderer accepts, then confirm survivors in the built HTML.
**Why:** a column-0 `^#` H1 rule passed `   # Foo` and setext `Foo` / `===`, which Docusaurus rendered as the page `<h1>`; a box parser accepting "any fenced block under the label" accepted a bogus extra block.
**How to apply:**
- Witnesses: ATX with 1 to 3 spaces, setext, four-colon `::::type Title`, second fenced block per label, text after a bare label, CRLF, marker inside a fence, indented opener. JSX `<h1>` in MDX is invisible to Markdown rules: route to the rendered "exactly one H1" check.
- Offline config (hash router) renders no route at build time: bad props, broken anchors and absolute route links pass `build:offline`; only the Pages build guards them. Use an anchor id whose slug differs from the auto slug for link probes. Built HTML is minified and Prism splits tokens: grep for a word, not a command line.
- Span/comment scanners: an unclosed opener in inline code (`` `{/*` ``) blanks the rest of the page; an inline `` `</TabItem>` `` ends an item for a regex tag walker (fail-open). Mutant families: closer of a longer run, carry reset on blank line, escaped backtick, span across a blank line. Classify survivors by direction: fail-open are required pins, fail-closed recommended. Span oracle without a build: `mdast-util-from-markdown` + gfm extensions from `guide/node_modules` (absolute import from a scratch script).

Rule: for a built-HTML tab reader or built-HTML command extraction, probe the HTML Docusaurus really emits.
**Why:** `<Tabs lazy>` renders only the selected panel (more tabs than panels), so a `!==` -> `<` mutant survives unless pinned; built HTML has unquoted attributes (`id=far-behind`), no `</p>`, code lines as `<div class=token-line>` with Prism spans; a reader written for quoted attributes finds nothing.
**How to apply:** probe pages in a scratch copy: label case, `values` prop, `default`, `queryString`, `lazy`, nested Tabs, details, table cell, admonition, `<pre><code>`, entities, NBSP. Scan `<(p|pre|h2)\b` openers, split `pre` on the token-line class, decode entities last, match ids as `id="?x[\s">]`; feed commands to `bash -c` straight from `guide/build`. Offline build writes only index.html: `check:built` on it is vacuous. Invisible-character stripping: offer `/\p{Default_Ignorable_Code_Point}/gu` and verify over all code points raw and as `&#x..;`.

Rule: for a rehype/remark plugin, probe through the real pipeline in a scratch copy with structural controls.
**Why:** hand-built hast fixtures cannot show what MDX emits (`<kbd>` is an `mdxJsxTextElement`, invisible to a walk over `type === 'element'`).
**How to apply:** scratch copy via `rsync -a --exclude node_modules --exclude build --exclude build-offline --exclude .docusaurus guide <dir>/`, symlink `node_modules`, add a probe page, build both configs, read attributes back with `grep -o`. Negative controls as copies: delete the registration line. A first-match `perl -pi` on built HTML must target the element, not the filename (preload links share it).

Rule: for content-page tasks bind pages to the frozen oracle with page mutants in a scratch copy plus a rendered cross-check.
**Why:** a green `npm run check` does not show each rule binds the real pages; only one exact edit per rule on the real text does, and the kill line must name the rule.
**How to apply:**
- Scratch = `rsync guide` plus `docs/spec-pack`, symlinked node_modules; one `replaceOnce` per mutant, `node scripts/check.mjs`, restore. A reinserted skeleton marker exits 0 until a marker ban exists. A broken contractual anchor: `npm run build` exits 1 "broken anchors".
- Own `semChecks(sourceText)` layer (pack-line equality, whole-line fenced commands, checkpoint lines, no PowerShell tokens in any fence): checker survivors that it kills are residuals for qa-final. Confirm a kill is for the stated reason.
- Pack coverage manifests: do your own section-aware sweep (three buckets per literal: in its section, only elsewhere, nowhere); the implementer's substring self-test is section- and page-blind. One mutant per pinned literal in a `test()` that asserts several; A/B the SWEEP_EXCLUDED keys.
- Rendered cross-check: tab panel n pairs with tab n; `pre.textContent` has no newlines (join `.token-line`s); offline hrefs are `#/route#anchor`. Leakage rule: add an 8-word shingle overlap with an appended-line control. A command participants must run: re-fetch the official page (`curl -sL <url>.md`) and quote the line.
- Insertion-only or deletion-only tasks: `diff -U0` has no deleted line, reversal in memory equals `git show <base>:<path>` (`Buffer.compare`), base build from `git archive <base> guide` compared per page (stripped text plus meta description; `diff -rq` of build trees is noise).
- Re-verification carry-forward: `git rev-parse <r1>:guide/docs` vs `HEAD:guide/docs`; CI zips differ by timestamp, so `gh run download` each, unzip, `diff -rq`. `gh run view <id> --json jobs,headSha,event,conclusion` binds CI evidence to the head sha.

Rule: for component, navbar, palette, focus-ring and table-region tasks, split mutants by who can see them and give every CSS or keyboard claim a negative control.
**Why:** `colors.mjs` exempts `custom.css`, so 6 of 6 CSS mutants passed `npm run check`; TSX mutants (`<=` for `<`, aria-hidden dropped) pass hand-written fixtures and die only in a real build plus `check:built`; the palette sweep reads custom.css once at start, so an in-place mutant poisons concurrent runs.
**How to apply:**
- Rule/CSS mutants in place; TSX mutants and palette batches in a scratch copy (tar minus node_modules/build, `docs` symlinked beside `guide/`), `npm run build` then `check-built.mjs`, about 5 s each. A mutant inserted at a comment inside the dark block makes a nested `@media`: anchor on a top-level comment. CSS mutants edit the `html[data-theme='dark']` block by offset. Classify survivors: equivalent, contract-neutral, rendered-only (rig only).
- Rig console classifier: keep 700 chars of message (end-anchored regexes miss a 200-char cut); classify by engine, build and phase; WebKit offline logs the CORS pair plus XHR pageerror per chunk; the abort-control fetch is classified by URL. Firefox dev console logs thousands of `timeStamp` events; the React DevTools info line is the positive control in Chromium and Firefox only. Dev mode is one `docusaurus start --port N --no-open --host localhost` per task; `lsof` free afterwards. The colour toggle cycles system -> light -> dark.
- WebKit swallows the first key after `page.screenshot()` or Tab: ArrowRight check before any screenshot, 350 ms after Tab, `scrollLeft = 0` plus 1500 ms before ring shots; never allow "one repeat" in the rig. `<details>` animates (~900 ms between presses). Hover reads need ~450 ms. Firefox ignores `scroll-margin` for visible elements. Sample ring pixels from a decoded screenshot PNG (small zlib decoder), not computed style. A cell-rect compare vs a `git archive <base>` build needs a sensitivity control (`padding-top:30px` moved 222 of 222 cells; `margin-bottom` collapsing moved 0).
- Independent palette sweep: own census of text-owning elements (ancestors composited), axe `violations` plus `incomplete` re-measured; a spec exemption proven by an axe-only run on a base build with sorted-line diff; committed screenshots bound by a pixel-by-pixel compare (0 differing pixels).
- Offline "0 requests before the control fetch": read the count BEFORE the control fetch. `locator.ariaSnapshot()` prints no `aria-current=step`; use `getByRole('link', {name})`. `node --test --experimental-test-coverage` under-reports `check-built.mjs` when its tests spawn a COPY of scripts/: rely on one killed wiring mutant per branch instead.

Rule: for an install-route or brownfield-order docs task, verify against the pinned-tag docs and mutate every untested claim site, including the pack's own "format decisions" lines.
**Why:** a deleted SWEEP_EXCLUDED key and an edited plan line 19 stayed green under mutants (restore the old claim, drop the `/plan` row cell) while the same mutants died on the base; run each such mutant on a `git archive <base>` copy as control. openspec.dev install scripts 302 to GitHub main (install.ps1 differs from the tag); fetch docs with `curl` from raw.githubusercontent at the tag; a release binary can be checksum-checked and run with `env -i HOME=<sandbox> OPENSPEC_TELEMETRY=0`.
**How to apply:** runner env overrides (`QA_COPY`, `QA_OUT`) let one mutant file run on both copies; rendered T4-style checks read tab panels by role (`getByRole('tab', {name, exact:true}).locator('visible=true')`) and need a negative-control build.
Rule: for a `check:built` rule (rules/built.mjs + check-built.mjs), run a mutant table over rule AND wiring, then replay defects on a scratch copy of the REAL build.
**Why:** fixture-only witnesses never show the rule reads real minified Docusaurus markup (unquoted attributes, `href=/Base/>`); and a wiring mutant that merely restates an option (`{routes: true, ...}` where `options` is already `{routes: true}`) is equivalent, not a survivor.
**How to apply:**
- Runner: list of `[id, desc, file, from, to, testFiles]`, `from` must occur exactly once (else SETUP ERROR), copy back from `.orig` after each, sha256 compare at the end, `node --test --test-reporter=spec` and collect the failing-test lines (cross-mark prefix). Add a "retarget bites" pair: drop the `navbar`/`levels` option and check the edited fixture tests go red.
- Real-build scratch layout MUST be `<top>/guide/{build,scripts,docusaurus.config.ts}` plus `<top>/docs` symlinked to the repo `docs` (built.mjs finds `docs/spec-pack` relative to scripts): without it the control run already fails on Windows PowerShell pack lines and every probe looks red for the wrong reason. Run the CLI with `cwd` = that guide dir for relative explicit dirs.
- Edits to built HTML need a unique anchor (`</nav>` and `href=/Base/wrap-up>` occur several times: the sidebar repeats links); keep the exact-once guard.
