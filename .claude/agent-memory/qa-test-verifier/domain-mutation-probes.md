Rule: a "rejects X" test only falsifies a clause if the input is rejected by THAT clause alone. Check what else would reject it under the mutation.
**Why:** an ISBN test with a non-ASCII digit at the check-digit position kills the Unicode-aware variant (`isDigit` + `Character.digit`), but survives the natural removal `allMatch(Character::isDigit)`: the `charAt - '0'` checksum arithmetic rejects the input by accident, so production can still accept other non-ASCII ISBNs.
**How to apply:**
- For a checksum-guarded format, build the witness so that the naive checksum still matches: replace digit d at weight w with a char c where `w * ((c - '0') - d) % 10 == 0` (U+0661 for the `5` at index 10, weight 1, of 9780141439518).
- Both factories sharing one private validating constructor: apply "factory B skips check K" as a constructor `boolean` flag (A passes true, B false). Only B's test should fail; that also proves A's path is still covered.
- Null guards (`requireNonNull`) are validation branches. Only the guards whose removal is not masked by a later NPE (`List.copyOf(null)`, `price.isGreaterThan`, `Year.now(null)`) need a pinning test. Name the unmasked ones by file:line.
- Rework rounds: keep a sha256 list of the fileScope from round 1. If `diff` shows only test files changed, cite the round 1 probe logs and re-probe only the Required Actions plus every round 1 probe whose only killer was an edited test. When a rework adds an assertion after an existing one, prove the new line bites: use a mutant that passes the old line and breaks only the new one (catch, publish or save, then rethrow the same instance); the failure must point at the new line number. Before any rework probe, `cmp` production against the earlier round's `.orig` copies and `diff` the tests (only `>` lines); see [[scaffold-verification-techniques]].
- Pass-through `Clock` parameters: always probe "use `Clock.systemUTC()` instead of the parameter". A test whose year is rejected by both the fixed clock and the real one (2028 against a 2026 clock) survives; the witness is a fixed clock in the past plus a year only the real clock accepts.
- Oracle trap: flow tests that compute the expected message by calling production code (a `domainMessage(() -> mapper...)` helper) fail inside the oracle when that code is mutated, before the flow assertion runs. The kill is real, but prove the flow assertion bites with a temporary oracle-free witness (exact type, code, `never().save`), run under the mutation and on restored code, then `rm` it.
- Parameter hard-coding on every read path: when the probe list pins a stored parameter against a hard-coded default on one path (reorder level in `lowStock()`), apply the same probe to every other branch that reads it (the reset in `receive`). Tests often use the default value on the unnamed paths. Prove it is not equivalent with a temporary witness testing both sides (level above and below the default).
- Exception payload witnesses: a "duplicate X" test with data A, B, A asserting `id() == A` cannot tell "the duplicated element" from "the first element". Probe "report `list.get(0)`" and "report `list.get(size - 1)`": the witness needs the duplicate in a non-first, non-adjacent, non-last position (B, A, C, A, B).
- Aggregate state cleared inside a method that already has an `if` (`receive` clears a pending restock next to `if (available() > level) resetSignal()`): always probe "move the clear into the existing `if`" (and its else). Fixtures that start well above the level never cross it, so the mutant survives at 100 percent branch coverage. The witness leaves the item still low after the call; give the implementer one that ends strictly BELOW the level, not at it (ending exactly at the level kills `> level` but leaves the twin `>= level` alive, costing a second rework round). Run it as a temporary witness class (snapshot, real code, mutant, `rm`).

Flow-layer probes (mocked port and publisher):
- "Returns the port result in order" tests: a stub that is "in neither id nor available order" can still be ascending in on hand or reserved, and a column constant across rows turns a stable sort into a no-op. Probe a sort by each DTO column. Prove a survivor with a witness stub monotonic in no column.
- Derived lists the flow builds itself (collected error details, published events) are "in X order" claims too, and plans often specify them with two rows. A two-row list is sorted in every column in one direction, so about half of the column-sort probes survive. Hunt for every list with fewer than three rows, probe its column sorts, then prove each survivor with a temporary three-row witness (green on real code, red under each survivor); it also gives the implementer verified data.
- Probe lists often name a mutant for one command only (toDomain outside the translator, value object before the load, save the loaded DTO). Run the counterpart in the other command too.
- A new line in a shared verify helper (`verifyNoInteractions(newPort)` in `verifyNothingLookedUpOrSaved()`): add a stray harmless port call (`newPort.findLowStock()`) as the first statement of the method under test. Expected: every helper caller fails at the helper's line number, plus separately named tests at their own lines, nothing else. Callers that survive are the rejection tests without the check.
- "No lookup or port call while X" probes (pre-check removed or moved) on unstubbed Mockito mocks die only by the NPE on the mock's null return, so `verifyNoInteractions(...)` is never reached. Add stray-call mutants on the guarded path (bare `books.findById(id)` without dereference, a port call with literal args, `save(stored)`, `publishEvent(item)`); each must fail at its own verify line.
- Probe the details `message` separately from the field (the title passed instead of the domain message). A test asserting only the field lets that mutant survive.

Mapper hand-offs into validating factories (`Money.of(amount, code)`, `new EmailAddress`, `OrderStatus.valueOf`, `new Quantity`):
- "Equivalent because the domain rejects it anyway" is wrong when the mutant drops the argument: the validator sits downstream of the mapped value and stored strings have no check constraint. Probe "drop the argument" (`Money.of(amount)`, hard-coded `"EUR"`, first-line currency for all lines) and need a rejected value (USD) asserted as the domain exception. Also probe the lenient-parse mutant (`valueOf` replaced by "SHIPPED else PLACED"): only a rejected value kills it.
- Write the per-field pass-through inventory FIRST: plain fields need two accepted values, hand-offs need a rejected one. Fixtures that reuse one e-mail, id or instant everywhere let a "replace by the test's own literal" mutant survive; prove with a temporary witness (snapshot, real code and each mutant, `rm`).
- Aggregate built inside a translator from an external DTO: "whole call outside the translator" is killed by any one rejected argument, so it proves nothing per argument. Probe moving EACH value-object construction (Title, AuthorName, Genre, Money) out of the translator separately. Check what the upstream adapter really guarantees (non-null is not non-blank).
- "Override replaces a default" (price override vs recommended price): when every override is above the default, "keep the higher of the two" survives; it needs an override below the default. Also probe "zero counts as absent" (`signum() == 0` like null) when the domain rejects zero only downstream; a zero override witness kills both. Run these families in round 0.
- Before round 0 verdicts, build an input x relation matrix for the use case (each input against: null/non-null, above/below/equal to the value it replaces, zero, each domain bound just outside, element position, duplicates). Each empty cell is a mutant family: clamp to the bound (`min(500.00)`, `max(1450)`), `limit(MAX)`, `distinct()`, `dropWhile(blank)`, "use the override only when it differs".

## View mappers and wrapped-cause detail pins
Rule: for a view record that copies an optional component, probe a guard on every DERIVED flag the DTO exposes, not only the null check.
**Why:** a view mapping `pending == null || !stock.lowStock() ? null : ...` survived every witness because all pending-restock fixtures were low items.
**How to apply:**
- Write guard mutants in both polarities and at the boundary (`<`, `<=`, `>=`, `!=` on available vs reorder level); a witness strictly above, one at, and one below the limit kills all of them.
- Null-key forms: `jsonPath("$", hasKey(k))` plus `value(nullValue())`, never `doesNotExist()`. `@JsonInclude` NON_NULL, NON_EMPTY, NON_ABSENT on class and component all die on `hasKey`; NON_DEFAULT also dies on dropped zero/false keys. Run the class-level one once under the full referee to prove the IT pins (a Map `isEqualTo` with a null value is itself a presence check).
- A list view needs element-index mutants: first, last, next and previous element's pending restock, plus a filter dropping null-pending items. The "pending only on the middle item" fixture kills all five.

Rule: a wrapped-cause detail message is pinned by `isEqualTo(prefix + domainMessage)` plus a cause-message assertion, not `startsWith`.
**Why:** `startsWith(prefix)` left the part after `": "` free, so `e.toString()`, an appended suffix and the class name all survived; a cause pinned only by `isExactlyInstanceOf` also let a different exception of the same type survive.
**How to apply:** probe the suffix expression (`getMessage`, `toString`, `getClass().getSimpleName()`, appended text, upper-cased, substring, dropped) and the cause (dropped, `getCause()`, wrapped, same type with another message). For a parameterized test derive the expected domain message per case inside the test.

## Batch runner for a use-case slice (state change plus mirror sites)
Rule: keep a pristine sandbox and a probe sandbox; a `python3 -I` mutator replaces OLD exactly once (exit 1 on 0 or 2 hits) in the pristine text and writes the probe copy; run the same fixed class list (all slice classes, pinned total) with `clean test -pl <module>` for every probe; after each probe restore by byte copy and `diff -rq` the two `src` trees (must be empty).
**Why:** one fixed list makes every probe's total comparable (a changed total means a compile or selection problem), and exactly-once replacement stops a mutant from silently not applying. `if (false)` replacements keep the edit compilable.
**How to apply:** add per mirror site (DTO ctor, domain mapper, JPA mapper in both directions, view) one "drops the new field" probe, per shared helper one "other caller's lambda swapped" probe, and the enum pin (add a fourth value). An allow-list rewrite of a two-value rule is an equivalent mutant on the current enum; prove it by the per-status tests passing on both, and rely on the enum pin.
