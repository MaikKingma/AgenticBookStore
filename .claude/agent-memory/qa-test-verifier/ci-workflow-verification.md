Rule: for CI-config tasks the evidence is real runs plus the file; script every gh call and recompute baselines yourself.
**Why:** a plan figure ("baseline median 52 s") was the minimum of five runs (median 58 s); copying it would carry a wrong gate number forward.
**How to apply:**
- gh/jq/python in a script under `.claude/comms/tmp/`; in `gh --jq` object construction write `.databaseId` (bare `databaseId` fails "function not defined"). Metrics: compute baseline and candidate in one script and compare per-run ranges, not only medians; `gh run view <id> --json jobs` gives step start/completion times; `Image:`/`Version:` lines sit in the "Set up job" log (old logs label the step `UNKNOWN STEP`).
- Cancellation proof: `gh api repos/<r>/check-runs/<job_id>/annotations` holds "Canceling since a higher priority waiting request for <workflow>-<pr> exists" (the group name proves the group expression). Timeout kinds: job timeout "The job has exceeded the maximum execution time of Nm0s" (job `cancelled`, `!cancelled()`/`failure()` steps skipped); step timeout "The action '<step>' has timed out after N minutes." (step and job `failure`). A hung test writes no `TEST-*.xml`, so the junit report still shows all-passed; the annotation is the only pointer.
- Job summaries (`$GITHUB_STEP_SUMMARY`, action-junit-report `job_summary`) are NOT rendered to logged-out viewers, even on public repos (`runs/<r>/jobs/<j>/summary_raw` answers a 9-byte 404, check-run `output.summary` is null). A plan demanding anonymous summary evidence is BLOCKED: ask for a signed-in human capture (the `claude-in-chrome` path works only when the extension is connected; the Skill call says so at once; WebFetch is anonymous). Return BLOCKED quoting the message; if the criterion is narrowed, still say the summary is UNVERIFIED by QA. The annotations API and run page do show action-junit-report failures; `gh run download -n <name> -D <fresh dir>` plus an ElementTree sum of `tests`/`failures` proves artifact completeness per module.
- Log traps: a `grep -c` on a string that is also in a `run:` script counts the echoed source in the "Run" header: anchor on the Actions timestamp (`Z <string> 20`). Run every mechanism regex on a baseline log first as a positive control. Cold Maven cache: setup-java prints `maven cache is not found`; a hit is `Cache restored from key: setup-java-Linux-x64-maven-<hash>` (`Cache not found` never matches; check the miss pattern on the first push run). `gh api repos/<r>/actions/jobs/<id>/logs > f` refuses Maven-coloured logs and leaves 0 bytes: add `--allow-escape-sequences` and `wc -l` first.
- actions/cache with a missing path: the post step still concludes `success`; the only trace is the log line `[warning]Path Validation Error: Path(s) specified ... do(es) not exist, hence no cache is being saved.` (not an annotation). Gate on absence of `Cache saved with key: <key>` per cache step and use `\[warning\]` (single bracket) in warning counts. A Windows cache path from a card literal is unverified until a run saves it (Maven-installed Node on `windows-latest` did not use `~\AppData\Local\npm-cache`; `npm_config_cache: ${{ runner.temp }}\npm-cache` held). On re-run accept hits by exact primary key as proof of an earlier save.
- Byte guards on a workflow (no `continue-on-error`/`|| true`/`-fn`, pins, ASCII): `python3 -I` on `git show <sha>:<file> > <SP>/x.yml`, one control copy per injected token (also one control per changed literal, old value restored and a one-character change in the new env value). Referee on committed bytes: `git -C <wt> archive <sha> | tar -x -C <SP>/<prefix>-tree`, then `cd` there and run the budgeted `./mvnw` (`find -type f` counts one less than `git ls-tree -r` because `agent-os/product` is a symlink).
- Gated-deploy workflows: count the gate bytes AND record each hit's job and step (track `^  <job>:` and `^      - name:` lines), so a moved `if` fails even when the count is right. Controls: unquoted `== true`, `||` for `&&`, one hit removed. Parse with js-yaml from an installed node tree (`createRequire(<dir>/package.json)`); YAML 1.2 keeps `on` as a string key. Side-effect proof for an untriggerable push path: 404 on `pages`, `releases/tags/<t>`, `git/ref/heads/gh-pages`, `git/ref/tags/<t>`, plus empty `actions/variables`, `environments`, `deployments`. The owner can arm the gate between rounds (Pages `build_type: workflow`, a `github-pages` environment, the variable): armed is not deployed; read `deployments`, `gh-pages`, the release, push-event runs and the site URL separately and report arming as a premise change with the env `created_at`.
- The base can move DURING a final sweep: re-run `git ls-remote origin refs/heads/<base>` and `gh pr view --json mergeable,mergeStateStatus` at the END (first query may say `UNKNOWN`). Name conflicts without touching the project repo: scratch clone, `git fetch -q <origin URL> refs/heads/<base>:refs/remotes/github/<base>`, `git merge-tree --write-tree --name-only refs/remotes/github/<base> <tip>` (exit 1 lists conflicted paths), `git diff --stat <old base> refs/remotes/github/<base>` for gated files that change without conflict.
