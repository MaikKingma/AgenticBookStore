Rule: check every README sentence that claims something about data or behaviour against the code AND the data files, not only commands and paths.
**Why:** prose overclaims ("no EAN matches a real edition", "never") survive command checks; one seed EAN was a real Penguin edition (found by grepping the seed plus a WebFetch of openlibrary `/isbn/<ean>.json`).
**How to apply:**
- Start proof: one script under `with-budget.sh 120`: preflight `lsof`, python `time.time()` stamp before `java -jar ... &`, 50 ms curl poll of `/actuator/health`, the `Started ... (process running for Y)` line, `lsof` LISTEN, `/actuator/info` 200 and `/actuator/env` 404, MCP `initialize` with `Accept: application/json, text/event-stream`, `kill`, `wait` (143), teardown `lsof` exit 1. macOS `date` has no `%N`.
- Real-jar STDIO: a `python3 -I` driver with a reader thread, stdin held open until both replies arrive, then closed (the server exits itself); stdout and stderr to separate files; a fresh scratchpad subdir as cwd so an older log cannot pass for yours. Check stdout lines strictly (no empty lines, ids exactly 1 and 2).
- `claude mcp add` is never run: compare README lines to `claude mcp add --help`, prove the URL by curl and the jar args by the piped run. Headless proxy: `claude -p ... --mcp-config <scratch json> --strict-mcp-config --allowedTools mcp__<server>__<tool> --output-format stream-json --verbose` from a script that `cd`s to the scratchpad; judge `system/init` (`mcp_servers[].status`, `tools`), then `tool_use`/`tool_result`. A 429 `model_requires_usage_credits` kills the turn but init still proves the connection (retry with `--model <alias>`, a deviation). The server's `Client initialize request - Protocol: ...` line proves the negotiated version.
- After a Claude Code HTTP session, SIGTERM on a Boot MCP server hangs ~30 s in graceful shutdown (open SSE GETs) while the port is already free: wait for the PID (up to 35 s) before the next jar; never kill -9.
- Multi-phase run with app restarts: one `python3 -I` session script under `with-budget.sh`; start each `./mvnw -pl <m> spring-boot:run` with `Popen(start_new_session=True)`, stop with `os.killpg(pid, SIGTERM)` (reaches the forked JVM, mvn exits 143), poll `lsof` until free. Flags as `-Dspring-boot.run.arguments=--<prop>=<v>`. Every chaos phase needs a witness hitting the dependency directly (a 503 body, a 6 s `time_total`) proving the flag took effect. One CHECK line per expectation.
- Counting calls to a downstream that logs nothing: start the app with `--distributor.base-url=http://127.0.0.1:<port>` and host a recording forwarder (python `ThreadingHTTPServer`) that counts POSTs and keeps bodies (also fields stored but never echoed). A JDK-client RestClient sends CHUNKED bodies: a Content-Length-only forwarder hangs to the read timeout and looks like an outage; decode chunked, drop upgrade/transfer-encoding headers.
- Shared Compose trap: `spring-boot:run` plus `docker compose down -v` removes the `bookstore` project's postgres for every checkout and worktree. When other cycles may run use your own container (`docker run -d --name <id>-pg ... -p 127.0.0.1:<free>:5432`), start jars with `env -u ANTHROPIC_API_KEY java -jar <jar> --spring.docker.compose.enabled=false --spring.datasource.url=...`, psql via `docker exec -i`, quote `docker ps -a` before and after. `pg_isready` already answers during image init: also require `docker logs <id>-pg | grep -c 'ready to accept connections'` = 2. Foreign containers (`s<NN>-<id>-pg`, `testcontainers-ryuk-*`) appear in your window: prove foreign with `docker inspect -f '{{.Name}} {{.Created}}'`, never touch.
- Docs-only task (README plus architecture page): two-way scripts with mutated-copy controls. (a) Endpoints: parse the README endpoint section and every `@RestController` (class prefix plus method mapping; an unmerged spec's controller via `git show origin/<branch>:<file>`), compare both set differences; controls drop one endpoint, add a fake. (b) Rule and suffix names: regex the `@ArchTest` constants and `classNames(PKG, "A", ...)` calls against the doc tables, restricted to the rules section (a plain scan also catches `HALF_EVEN`); controls: renamed constant, dropped and extra suffix, changed `ignoreDependency`. (c) Live probe of each documented endpoint: a bare POST `{}` answering 400/422/202 proves the mapping, 404/405 does not; GET by a non-existent id answers 404 too, use a real id. (d) Backticked paths: resolve against the folder the sentence names (`catalogue.http` lives in `http/`) before calling a path missing; a literal grep over a non-existent path exits 2 with no matches.
- LLM-endpoint claims without the real API (503 offline, 400 limit, 429): start the jar twice on your own PG, once with `env -u <KEY>`, once with a made-up key plus `SPRING_AI_ANTHROPIC_BASE_URL=http://127.0.0.1:<port>` at your own `python3 -I` stub (relaxed binding overrides the pinned `application.yml` base URL; the SDK's own `ANTHROPIC_BASE_URL` is not honoured, never test it against the real host). The stub counts requests and prints request JSON keys (default `model`, no `temperature`/`top_p`/`top_k` are wire facts). Restart to reset an in-memory rate window. A 500 stub sees 3 POSTs per chat (client retries 5xx twice): expect "requests >= 1". Limits counted in UTF-16 units: code-point-built strings (500 emoji = 1000 units accepted, 501 refused).

Rule: prove captured bodies are real by replaying them against a service you start yourself, with a comparator you have shown can fail.
**Why:** a census over the files proves only internal consistency; a hand-edited or stale capture passes it.
**How to apply:**
- Drive the replay from the README tables and committed request files (`curl -o <file> -w %{http_code}`, `--data-binary @<request file>`), never a retyped list; one run per server flag set, then one comparator over both status files.
- Comparator: status vs README column, byte-equality first, parsed-JSON equality after popping only named capture-day fields (ids, delivery dates, framework timestamp); report byte-identical vs ignored-field-only counts. Controls on committed-dir copies: +1 on a number, one letter in a name, a changed README status, a changed non-ignored field, and a changed IGNORED field that must still exit 0.
