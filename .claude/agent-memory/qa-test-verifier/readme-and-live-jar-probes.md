Rule: check every README sentence that makes a claim about data or behaviour against the code AND the data files, not only commands and paths. Prose overclaims ("do not match real editions", "never") survive command checks.
**Why:** a README stated that no EAN matched a real edition; one seed EAN (the shared Pride and Prejudice ISBN) is a real Penguin edition. Found by `grep -o -E '"ean": "978[0-8]...'` on the seed plus a WebFetch of openlibrary `/isbn/<ean>.json`.
**How to apply:**
- Start proof: one script in `.claude/comms/tmp/` run through `with-budget.sh 120`: per run preflight `lsof`, a python `time.time()` stamp before `java -jar ... &`, a 50 ms curl poll of `/actuator/health`, the `Started ... (process running for Y)` line, `lsof` LISTEN, `/actuator/info` 200 and `/actuator/env` 404, curl MCP `initialize` with `Accept: application/json, text/event-stream`, `kill`, `wait` (143), teardown `lsof` exit 1. macOS `date` has no `%N`.
- Real-jar STDIO: a `python3 -I` driver with a reader thread, stdin held open until both replies arrive, then close stdin (the server exits by itself); stdout and stderr to separate files; a fresh scratchpad subdirectory as cwd so an older log file cannot pass for yours. Check stdout lines strictly (no empty lines, ids exactly 1 and 2).
- `claude mcp add` is never run; compare README lines to `claude mcp add --help` and prove the URL by curl and the jar arguments by the piped run. Headless proxy: `claude -p ... --mcp-config <scratch json> --strict-mcp-config --allowedTools mcp__<server>__<tool> --output-format stream-json --verbose` from a script that `cd`s to the scratchpad; judge `system/init` (`mcp_servers[].status`, `tools`, `apiKeySource`), then `tool_use`/`tool_result`. A 429 `model_requires_usage_credits` kills the turn but init still proves the connection; retry with `--model <alias>` (a deviation). The server's `Client initialize request - Protocol: ...` line proves the negotiated version.
- After a Claude Code HTTP session, SIGTERM on a Boot MCP server hangs 30 s in graceful shutdown (open SSE GETs) while the port is already free: wait for the PID (up to 35 s) before the next jar, never kill -9 it as "stuck".
- `.http` request collections: see [[http-collection-replay-probes]] (replay driver, fresh DB per scenario, mutated copies); static byte checks are in [[scaffold-verification-techniques]].
- Tip-vs-base live comparison: one session script per phase starts both jars (`--server.port`), polls health, runs one driver against each URL, stops by PID and waits for exit, then diffs only the outside-scope requests. For a chaos share, `seq 1 400 | xargs -P 8 -I{} sh -c 'curl -o d/b{} -w %{http_code} ... > d/c{}'` gives one body and code file per request; count codes and check every 503 body.
- Multi-phase live run with app restarts: one `python3 -I` session script under `with-budget.sh`. Start each `./mvnw -pl <m> spring-boot:run` with `Popen(start_new_session=True)`, stop it with `os.killpg(pid, SIGTERM)` (reaches the forked JVM, mvn exits 143), poll `lsof` until the port is free. Pass flags as `-Dspring-boot.run.arguments=--<prop>=<v>`. Every chaos phase needs a witness hitting the dependency directly (a 503 body, a 6 s `time_total`) so the phase proves the flag took effect. One CHECK line per expectation, DB count at the end.
- Counting calls to a downstream that logs nothing and has no list endpoint: start the app with `-Dspring-boot.run.arguments=--distributor.base-url=http://127.0.0.1:<port>` and host a recording forwarder (python `ThreadingHTTPServer`) in the replay driver; it counts POSTs and keeps bodies (also fields stored but never echoed). A JDK-client RestClient sends CHUNKED bodies: a Content-Length-only forwarder hangs until the read timeout and looks like a product outage. Decode chunked, drop upgrade/transfer-encoding headers, log forwarder errors.
- Shared Compose project trap: `spring-boot:run` plus `docker compose down -v` removes the `bookstore` project's postgres for every checkout and worktree. When other cycles may run, use your own container (`docker run -d --name <id>-pg ... -p 127.0.0.1:<free port>:5432`), start jars with `env -u ANTHROPIC_API_KEY java -jar <jar> --spring.docker.compose.enabled=false --spring.datasource.url=...`, reach the DB with `docker exec -i <id>-pg psql`, and quote `docker ps -a` before and after. `pg_isready` already answers during the image's init: also require `docker logs <id>-pg | grep -c 'ready to accept connections'` = 2. Other cycles create containers (`s<NN>-<id>-pg`, `testcontainers-ryuk-*`) inside your window: `docker inspect -f '{{.Name}} {{.Created}}'` read-only proves they are foreign; never touch them. A forwarder toggle in the driver lets one script prove the default-URL path and the counted path.
- README curl replay: one `python3 -I` script regex-extracts the fenced blocks from the README bytes, asserts exactly one `curl ` block, `str.replace` of host:port only, prints a `difflib` diff, runs the replayed string with `bash -c`, writes all bash blocks to a scratch file for `bash -n`, and starts/stops the jar itself (`Popen(start_new_session=True)`, `killpg`, `wait`).
- Docs-only task (README plus architecture page): two-way scripts with mutated-copy controls. (a) Endpoints: parse the README endpoint section and every `@RestController` (class prefix plus method mapping; add an unmerged spec's controller via `git show origin/<branch>:<file>`), compare both set differences; controls drop one endpoint, add a fake, drop the chat line. (b) Rule and suffix names: regex the `@ArchTest` constants and `classNames(PKG, "A", ...)` calls, compare with the doc tables, restricting the doc side to the rules section (a plain scan also catches `HALF_EVEN`, `REQUIRES_NEW`); controls: renamed constant, dropped and extra suffix, changed `ignoreDependency`, renamed package row. (c) Live probe of each documented endpoint: a bare POST `{}` answering 400/422/202 proves the mapping, 404/405 does not; a GET by a non-existent id answers 404 too, so use a real id. (d) Link/path check on backticked tokens: resolve against the folder the sentence names (`catalogue.http` lives in `http/`, `db/seed` under `bookstore/src/main/resources`) before calling a path missing; a literal grep over a path that does not exist exits 2 with no matches: say that instead of "clean empty".
- Live LLM-endpoint claims without the real API (503 offline, 400 limit, 429 rate limit): start the jar twice on the own PG, once with `env -u <KEY>` (offline) and once with a made-up key plus `SPRING_AI_ANTHROPIC_BASE_URL=http://127.0.0.1:<port>` pointing at your own `python3 -I` stub (Spring relaxed binding overrides the pinned `application.yml` base URL; the SDK's own `ANTHROPIC_BASE_URL` is not honoured, so never test that variable against the real host). The stub counts requests and can print the request JSON keys: `model` default and the absence of `temperature`/`top_p`/`top_k` are then wire facts. Restart the keyed jar to reset an in-memory rate window. A stub answering 500 sees 3 POSTs per chat (the Anthropic Java client retries 5xx twice) and the app logs one WARN: expect "requests >= 1". Length limits counted in UTF-16 units: probe with code-point-built strings (500 emoji = 1000 units accepted, 499 emoji + 2 chars = 501 code points still accepted, 501 emoji refused) and print both counts.

## Contract capture replay
Rule: prove captured bodies are real by replaying them against a service you start yourself, with a comparator you have shown can fail.
**Why:** a census over the files only proves internal consistency; a hand-edited or stale capture passes it. The replay is the only evidence of "byte for byte the real service".
**How to apply:**
- Drive the replay from the README tables and the committed request files (curl `-o <file> -w %{http_code}`, `--data-binary @<request file>`), so the driver never holds a retyped request list. One run per server flag set (normal, chaos), then one comparator over both status files.
- Comparator: status vs README status column, byte-equality first, parsed-JSON equality after popping only the named capture-day fields (ids, delivery dates, relative release date, framework timestamp). Report byte-identical vs ignored-field-only counts. Controls on committed-dir copies: +1 on a number, one letter in a name, a changed README status, a changed non-ignored field, and a changed IGNORED field that must still exit 0.
- Derived files: `sed '<one substitution>' <source> | cmp - <derived>` exits 0, plus a control `cat <source> | cmp - <derived>` exits 1. List insertions (subjectCodes) and swaps (contributors) are a single README-named change but several flattened paths: assert whole-key comparisons. Genre/prefix tables: parse the spec line itself (regex on backticked codes) and assert a falsifier where the second subject code would give a different genre.
- Start/stop: `./mvnw -pl distributor spring-boot:run` via a script in `.claude/comms/tmp/`, `run_in_background`; the background task reports "failed exit 1" after you kill the child (expected). Health is UP even with failure-rate=1.0 (chaos covers only /api/**). Kill the java PID shown by `lsof -nP -iTCP:8090 -sTCP:LISTEN`, then `lsof` exit 1 and `ps -p <pid>` empty prove teardown.
