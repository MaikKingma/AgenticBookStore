Rule: check every README sentence that makes a claim about data or behaviour against the code AND the data files, not only
commands and paths. Prose overclaims ("do not match real editions", "never") survive command checks.

**Why:** a README stated that no EAN matched a real edition; one seed EAN (the shared Pride and Prejudice ISBN) is a real
Penguin edition. Found by `grep -o -E '"ean": "978[0-8]...'` on the seed plus a WebFetch of openlibrary `/isbn/<ean>.json`.
**How to apply:**
- Start proof: one script in `.claude/comms/tmp/` run through `with-budget.sh 120`: per run preflight `lsof`, a python `time.time()` stamp before `java -jar ... &`, a 50 ms curl poll of `/actuator/health`, the `Started ... (process running for Y)` line, `lsof` LISTEN, `/actuator/info` 200 and `/actuator/env` 404, curl MCP `initialize` with `Accept: application/json, text/event-stream`, `kill`, `wait` (143), teardown `lsof` exit 1. macOS `date` has no `%N`.
- `spring-boot:run` forks: kill the mvn PID, then re-check the port and kill a leftover java PID only if you started it.
- Real-jar STDIO: a `python3 -I` driver with a reader thread, stdin held open until both replies arrive, then close stdin (the server exits by itself); stdout and stderr to separate files; use a fresh subdirectory of the scratchpad as cwd so an implementer's older log file cannot pass for yours. Check stdout lines strictly (no empty lines, ids exactly 1 and 2).
- `claude mcp add` is never run; compare README lines to `claude mcp add --help` (usage and the two example shapes) and prove the URL by curl and the jar arguments by the piped run.
- `localhost` tries `::1` first; a server bound to 127.0.0.1 only answers after curl falls back (`curl -v` shows both Trying lines).
- Headless Claude Code proxy (never `claude mcp add`): `claude -p ... --mcp-config <scratch json> --strict-mcp-config --allowedTools mcp__<server>__<tool> --output-format stream-json --verbose` from a script that `cd`s to the scratchpad. Judge the `system/init` event (`mcp_servers[].status`, `tools`, `apiKeySource`), then `tool_use` and `tool_result`. A 429 `model_requires_usage_credits` kills the turn but init still proves the connection; retry with `--model <alias>` (a deviation). The server's `Client initialize request - Protocol: ...` log line proves the negotiated version.
- After a Claude Code HTTP session, SIGTERM on a Boot MCP server hangs 30 s in graceful shutdown (open SSE GETs) while the port is already free: wait for the PID (up to 35 s) before the next jar, never kill -9 it as "stuck".
- `clean test` order runs delete `target/<app>.jar`: rebuild (`clean verify`) before live runs from the jar.
- Tip-vs-base live comparison: one session script per phase starts both jars (`--server.port`), polls health, runs one driver against each URL, stops by PID and waits for exit, then diffs only the outside-scope requests. For a chaos share, `seq 1 400 | xargs -P 8 -I{} sh -c 'curl -o d/b{} -w %{http_code} ... > d/c{}'` gives one body and code file per request (no interleaving); count codes and check every 503 body afterwards.
- Multi-phase live run with app restarts: one `python3 -I` session script under `with-budget.sh`. It starts each `./mvnw -pl <m> spring-boot:run` with `Popen(start_new_session=True)`, stops it with `os.killpg(pid, SIGTERM)` (reaches the forked JVM, mvn exits 143), then polls `lsof` until the port is free. Pass flags as `-Dspring-boot.run.arguments=--<prop>=<v>`. Every chaos phase needs a witness hitting the dependency directly (a 503 body, a 6 s `time_total`) so the phase proves the flag took effect. One CHECK line per expectation, DB count at the end.
- Counting calls to a downstream that logs nothing and has no list endpoint: start the app with `-Dspring-boot.run.arguments=--distributor.base-url=http://127.0.0.1:<port>` and host a recording forwarder (python `ThreadingHTTPServer`) in the replay driver; it counts POSTs and keeps bodies (also fields the downstream stores but never echoes). A JDK-client RestClient sends CHUNKED bodies: a Content-Length-only forwarder hangs until the read timeout and looks like a product outage. Decode chunked, drop upgrade/transfer-encoding headers, log forwarder errors.
- State a view hides: compare `row_to_json(s)` (version included) before and after via `docker compose -f <abs compose> exec -T postgres psql -At`; truncate tables between runs; `compose down -v`, `lsof`, `compose ps -a` prove teardown.
- A mutant that deletes the capture handler crashes a naive driver (KeyError): turn it into a CHECK FAIL line.
- Shared Compose project trap: `spring-boot:run` plus `docker compose down -v` removes the `bookstore` project's postgres for every checkout and worktree. When other cycles may run, use your own container (`docker run -d --name <id>-pg ... -p 127.0.0.1:<free port>:5432`), start the jars with `env -u ANTHROPIC_API_KEY java -jar <jar> --spring.docker.compose.enabled=false --spring.datasource.url=...`, reach the DB with `docker exec -i <id>-pg psql`, and quote `docker ps -a` before and after. `pg_isready` already answers during the image's init (temporary socket-only server), so also require `docker logs <id>-pg | grep -c 'ready to accept connections'` = 2 before starting the jar. Other cycles create containers (`s<NN>-<id>-pg`) inside your window: `docker inspect -f '{{.Name}} {{.Created}}'` read-only proves they are foreign. A forwarder toggle in the driver (forwarder checks become INFO when off) lets one script prove the default-URL path and the counted path.
- Bookstore `spring-boot:run` smoke: `GET /` answers 302 to `/shop/`, so check `Location` and GET the target, not a literal 200. Boot's compose support creates `bookstore-postgres-1` when absent; quote `docker compose ps -a` before and after and report who created it.
- README curl replay: one `python3 -I` script regex-extracts the fenced blocks from the README bytes, asserts exactly one `curl ` block, replaces host:port only, prints a `difflib` diff, runs the string with `bash -c`, writes all bash blocks to a scratch file for `bash -n`, and starts/stops the jar itself (`Popen(start_new_session=True)`, `killpg`, `wait`). A foreign `testcontainers-ryuk-*` from another cycle may show in a `docker ps -a` diff: quote it, never touch it.
- Docs-only task (README plus architecture page): two-way scripts with mutated-copy controls in the scratchpad. (a) Endpoints: parse the README endpoint section and every `@RestController` (class `@RequestMapping` prefix plus method mapping; add the unmerged spec's controller via `git show origin/<branch>:<file>`), compare both set differences; controls drop one endpoint, add a fake, drop the chat line. (b) Rule and suffix names: regex the `@ArchTest` constants and `classNames(PKG, "A", ...)` calls from the test, compare with the doc tables; restrict the doc side to the rules section (a plain scan also catches `HALF_EVEN`, `REQUIRES_NEW`). Controls: renamed constant, dropped and extra suffix, changed `ignoreDependency`, renamed package row. (c) Live probe of each documented endpoint: a bare POST `{}` answering 400/422/202 proves the mapping, 404/405 does not; a GET by an id that does not exist answers 404 too, so use a real id (create one first). (d) Link/path check on backticked tokens: resolve against the folder the sentence names (`catalogue.http` lives in `http/`, `db/seed` under `bookstore/src/main/resources`) before calling a path missing; a literal grep over a path that does not exist yet exits 2 with a warning and no matches, so say that instead of calling it a clean empty result.
- Live LLM-endpoint claims without the real API (503 offline, 400 limit, 429 rate limit): start the jar twice on the own PG, once with `env -u <KEY>` (offline) and once with a made-up key plus `SPRING_AI_ANTHROPIC_BASE_URL=http://127.0.0.1:<port>` pointing at your own `python3 -I` stub (Spring relaxed binding overrides the pinned `application.yml` base URL; the SDK's own `ANTHROPIC_BASE_URL` is not honoured, so never test that variable against the real host). The stub counts requests (20 of 20 reached it, 429s did not) and can print the request JSON keys: `model` default and the absence of `temperature`/`top_p`/`top_k` are then wire facts. Restart the keyed jar to reset an in-memory rate window instead of waiting a minute. Length limits counted in UTF-16 units: probe with code-point-built strings (500 emoji = 1000 units accepted, 499 emoji + 2 chars = 501 code points still accepted, 501 emoji refused) and print both counts.
- Foreign live runs: before choosing ports run `lsof -nP -iTCP:8080 -iTCP:8090 -sTCP:LISTEN` and never `ps -o command` a Java pid (the classpath prints 10k characters); use `lsof -Fpn` and `ps -o pid,comm`. Override ports with `SERVER_PORT` and the app's own base-URL property, make probe scripts read `QA_B`/`QA_D` env URLs, and disclose any hard-coded proxy (Vite `/books` to 8080) that then lands on the foreign instance (read-only GETs only).
- Count-sentence task (a seed grows and README/http line-2 counts follow): a `python3 -I` census parses the seed INSERT rows itself and pulls each claim from the prose by regex that must match exactly once; mutated README and http-dir copies (one number each, a stale "40", a wrong link scheme, host case, missing baseUrl, trailing slash) must each exit 1. Trap: `re.findall` on a one-group pattern returns strings, so `m[0]` is one character (claimed "2" for 20); positive run must print every claimed value. Link target: compare to url + baseUrl parsed from the guide's `docusaurus.config.ts` via `git show origin/<branch>:path`.
- A probe that POSTs (`discontinue`, `ship`) dirties the seed: reset the own DB (`drop schema public cascade; create schema public;`, restart the jar, Flyway reseeds) before a data census.

## Contract capture replay

Rule: prove captured bodies are real by replaying them against a service you start yourself, with a comparator you have shown can fail.

**Why:** a census over the files only proves internal consistency; a hand-edited or stale capture passes it. The replay is the only evidence of "byte for byte the real service".
**How to apply:**
- Drive the replay from the README tables and the committed request files (curl `-o <file> -w %{http_code}`, `--data-binary @<request file>`), so the driver never holds a retyped request list. One run per server flag set (normal, chaos), then one comparator over both status files.
- Comparator: status vs README status column, byte-equality first, parsed-JSON equality after popping only the named capture-day fields (ids, delivery dates, relative release date, framework timestamp). Report byte-identical vs ignored-field-only counts. Controls on committed-dir copies: +1 on a number, one letter in a name, a changed README status, a changed non-ignored field, and a changed IGNORED field that must still exit 0.
- Derived files: `sed '<one substitution>' <source> | cmp - <derived>` exits 0, plus a control `cat <source> | cmp - <derived>` exits 1. This proves "exactly one change" at byte level; list insertions (subjectCodes) and swaps (contributors) are a single README-named change but several flattened paths, so assert them as whole-key comparisons.
- Genre/prefix tables: parse the spec line itself (regex on backticked codes) instead of retyping it; assert a falsifier where the second subject code would give a different genre.
- Start/stop: `./mvnw -pl distributor spring-boot:run` via a script in `.claude/comms/tmp/`, `run_in_background`; the background task reports "failed exit 1" after you kill the child, which is expected. Health is UP even with failure-rate=1.0 (chaos covers only /api/**). Kill the java PID shown by `lsof -nP -iTCP:8090 -sTCP:LISTEN`, then `lsof` exit 1 and `ps -p <pid>` empty prove teardown.
- Before running a README jar command "as written" from a repo root that holds a `compose.yaml`, prove the fat jar
  cannot start Compose (and so cannot touch a shared `bookstore-postgres-1`): `unzip -l <jar> "BOOT-INF/lib/spring-boot-docker*"`
  lists 0 files, with `"BOOT-INF/lib/postgresql*"` as the positive control; then grep the run log for `compose` (none).
  A busy 8080 gets `SERVER_PORT=<free>` as the one disclosed deviation besides the JDBC port.
