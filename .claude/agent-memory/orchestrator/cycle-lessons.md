- **Workflow-file pushes over https are rejected** even after `gh auth status` shows the `workflow` scope: git's https credential is a different OAuth token. Push over SSH (the SSH form of the origin URL: `git push <ssh-url> <branch>`); `gh pr create/merge` work fine.
- **CI-config specs:** real runs are the evidence, so push and open the task PR before the verifier, and commit plan/memory before QA (the verifier binds evidence to the PR head sha; a later push invalidates it). Throwaway proof branches go through a draft PR into the spec branch (the push filter excludes them), then close unmerged and delete.
- **GitHub job summaries (`$GITHUB_STEP_SUMMARY`) are invisible to logged-out viewers and to every API** (`summary_raw` 404, check-run output null). Never gate a criterion on summary content: no agent can verify it, and the QA lead rejects log-line or `checks: write` substitutes. Gate "full report on failure" on `-fae` reactor lines, the annotations API, the uploaded Surefire artifact and the red job; list the summary as unverified in the PR body (owner-delegated decision, ci-performance plan.md A3, after a needs-decision stop).
- **CI hang/timeout bugs: prove with a throwaway probe pair** (fix-ci-report-on-timeout plan.md). Red: base workflow plus a `Thread.sleep` probe test, job timeout lowered for speed. Green: the exact gated workflow plus only the probe test (never lower its timeouts). I write probes myself (sdd-bugfix 1a.2) in scratchpad worktrees, push over SSH, draft PR, close unmerged, delete. A job timeout, manual cancel and supersede all set `cancelled()`; only a step timeout ends as failure. Lite path with sonnet impl and opus QA held in one round.
- **Worktree Bash guard (isolated orchestrator):** it refuses `cd X && git ...`, `$(...)` and any compound command naming git or gh; run one plain git command per call from the worktree root (or `git -C <scratch worktree>`).
- **CI check names** are `verify` (ubuntu, full tests with Docker), `windows-build` (compile-only) and, since spec 09, `publish-script-test`. Every push and pull_request runs both, so a task PR gets two runs per push; use `gh run view <id> --json headSha` to find the runs on a given commit (the pull_request run's headSha is the PR merge commit).
- **Base moved during a cycle** (owner committed to `factory`): qa-final fails the base-ancestor item. Fix is `git merge origin/factory` into the spec branch (merge commit, never rebase or force-push), then re-run only the tip-dependent sweep items; carry the rest forward with a `git diff --name-status <old tip> <new tip>` proof. An untracked byte-identical copy of the owner's file blocks the merge: move it aside, merge, `cmp`. When factory moves while qa-final runs (spec 07: fix-12 landed mid-sweep), let the sweep finish, then merge, curate memory, push and resume qa-final for only M0 to M3 plus PR readiness with the delta proof; the QA lead's final-review then covers both rounds.
- **Parallel cycle in an isolated Agent-tool worktree** (spec 05): the worktree starts on stripped `main`, not factory; cut the spec branch with `git switch -c sdd/<slug>/spec --no-track origin/factory`. Comms live in the worktree's own `.claude/comms/`. Other cycles merge into factory meanwhile: merge `origin/factory` into the spec branch after the last task PR and BEFORE the final sweep, so qa-final reviews exactly what merges and no sweep re-run is needed. Expect agent-memory conflicts only: union the `MEMORY.md` index files yourself, let the owning agent type (sonnet) curate its conflicted topic files to budget.
- **Headless Claude Code proxy for the manual smoke item:** `claude -p "<prompt>" --mcp-config <scratch json> --strict-mcp-config --allowedTools mcp__<server>__<tool> --output-format stream-json --verbose` writes no user config (never `claude mcp add`). The CLI default model can hit a usage limit (429): pre-authorize a `--model sonnet` retry in the directive and name the model in the record. Judge on the init event (server connected, exact tool list) plus one tool_result.
- **Memory guard trap:** agents keep growing their MEMORY.md hook line past 250 chars; the curation prompt must say "short hook, do not list every trap". Run the guard before the memory commit, not after.
- **Shared scratchpad:** verifiers overwrite each other's generic `referee.log`; brief every agent with a role and task prefix for evidence files (`t5-qa-*`).
- **Timestamps:** agents (and I) hand-write `updated:`/`created:` and drift ahead of the real clock; take every ledger, registry and plan timestamp from `date -u` (spec 02: my shaping timestamps ran 45 minutes ahead and `gate1:` had to be corrected in a later commit). The QA lead checks ordering by mtime.
- **PR checks right after a push:** `gh pr checks <n> --watch` within the first seconds reports "no checks reported"; sleep 45 to 60 s after the push, then watch. Two runs per push (push and pull_request), four check lines.
- **Composite ArchUnit rules need per-half pins and a fixture per parameter position:** a `CompositeArchRule` with the same package list in both halves lets one-half drops survive unless the self-test pins each half's description; a "contains any double/float parameter" predicate needs fixtures with the floating-point parameter alone, first, middle and last (spec 02 T7: one REJECT, two rework rounds, two plan amendments). Put this in the task criteria up front next time.
- **Reject reflective tests of private helpers** proposed by verifiers; the fix is a fixture (or a plan amendment adding one), which proves behaviour. Amendments that only add test fixtures inside a task are within authority: log under `## Amendments`, self-accept the gate re-run.
- **Hibernate drops duplicate entities in memory:** an author `join` instead of `exists` only shows with a small `Limit` (spec 02 T4 probe D3); the limit-counts-books test belongs in the criteria of any search over a collection.
- **Model choices that held:** opus for the foundation build skeleton, database and test infrastructure, the ArchUnit tasks, the domain and the data adapter; sonnet was enough for the CI workflow (ci-performance T1 and T3, impl and verifier, one round each), a database-free module config and the DTO/port task (spec 02 T2, elevated tier, one clean round; the QA lead rated the sonnet verifier as good as the opus ones). Spec 03 confirmed sonnet for web adapters (command and query adapter, one clean round each, impl and verifier) and the static `.http` collection; opus for domain, flow, data adapter, changes to spec 02 flows and views, and integration tests. Spec 04 again: sonnet adapters (T5, T6) and `.http` passed in one round; the sonnet mapper task (T2) needed a lead REJECT plus an opus round over validator hand-offs. Rework rounds so far were tests only (missing falsifiers), never production defects; the QA lead's T<n>-2 falsifier lists appended to the implDirective cut rounds. Spec 05 (distributor, plain Spring): opus for seed data, MCP and the STDIO in-process test; sonnet for services, REST, chaos, packaging/README and `.http`. Its three rework rounds were a missed length-cap boundary and unpinned required params (T3), an unasserted pass-through (T4) and a false README data claim (T7): name both sides of every cap, every pass-through field and a seed census for README facts in the implDirective up front. Spec 06 (distributor ACL): opus impl and verifier for the RestClient adapter, the import flow and the ArchUnit rule; sonnet impl and verifier held in one round for the command endpoint, the integration test and the test-only follow-up task. Spec 07 (process layer): opus impl and verifier for persistence, flow, process adapter and the manual-path IT plus ArchUnit fixtures held, rework only where an "unchanged" claim ran from one flag value (T6); sonnet domain needed two test-only rounds (partial-delivery region witnesses), sonnet view/endpoint one (a not-low pending witness, an exact detail pin); `.http` sonnet one round.
- **Resume after a cut-off: background agents of the dead run can still be alive.** A qa-lead spawned before an orchestrator usage-limit cut-off finished its review minutes after the relaunch; respawning it made two writers on one ledger. Before respawning on resume, check the agent's artifact `updated`/mtime and `activity`; if fresh (under 15 min), arm a Monitor on its artifact and inbox and wait instead of respawning.
- **Waiting on background children as a subagent:** a foreground Bash call is moved to the background after about 180 s, so poll in loops of at most 160 s with `.claude/comms/tmp/orchestrator-wait-inbox.sh <inbox> 160` (exits on the first message) or `orchestrator-wait-status.sh <artifact> 160 [ignore-updated]`; that keeps the run alive without ending the turn. Agents' hand-written `updated:` stamps run ahead; trust file mtimes and `date -u`.
- **Ordering and witness data cost most rework rounds (spec 04: T2 to T4, T7):** two-row witnesses are always monotone; implementers vary the named columns and leave another monotone (fixture isbn, joined line columns, NULL position). Put in every implDirective from the start: three or more rows per order claim, every in-scope attribute non-monotone in every asserted order (stored and sorted), a tabulation table in the outbox, two values per pass-through, a rejected witness per validating hand-off. See plan.md Amendments A1 and A3 of spec 04 for the QA reading.
- **Falsifier classes that cost spec 06 its rework rounds (T3 two, T4 two, T6 one), all test-only:** malformed bodies probed per key but not per list element (null element after a valid one) or per numeric type (float in an integer field); an optional value vs its default not tested below, equal, above and zero; an enclosing-class walk not tested at every chain position plus exact-name and letter-case controls. Put these in the implDirective and qaDirective of round 0 (the QA lead's SP-1/SP-2 in the spec 06 ledger). The QA lead's test-only follow-ups after an ENDORSE are cheapest as one tail task (spec 06 T8, amendments A1/A2/A4) before qa-final.
- **Exact-equality and escape criteria: name the whole witness and mutant family in round 0** (fix-06 plan.md FF2,
  FF4, FF5). Identity checks need leading pad, trailing pad, front and end extension, proper prefix, proper suffix and
  null rows, and mutants `a.op(b)` and `b.op(a)` for startsWith/endsWith/contains plus the strip family; log-escape sets
  named by a JDK predicate need every `\R` member plus the predicate's boundaries; a new constructor that must leave a
  field untouched needs that field asserted. Leaving these to the verifier cost two rework rounds per task.
- **Before planning a defence-in-depth check, grep every fixture that feeds it** (fix-06 D3): one helper with a foreign
  isbn fed about twenty flow tests; aligning stub literals without touching assertions is within authority, log it.
- **Lite bugfix with sonnet impl and verifiers held** for acl, flow and e2e tasks (fix-06), web config and frontend
  state (fix-12), and chat-client options, test config and prompt text (fix-08; opus only for the boundary catch T1);
  every rework was test-only. The main session's model rule (opus only for qa-lead,
  qa-final, critical tasks) overrides "rework >= 2 -> opus". Shared in-flight state: name "every reset branch has a
  test that sends again" in round 0 (fix-12 T2 r0 survivor). Bugfix criteria for new UI elements: "red set = the named
  tests plus any test of a new element; no pre-existing test red" up front (fix-12 plan.md A1). Also held in one
  round each for labels and CSS layout (fix-12-genre-labels-footer): pasting the QA lead's must-fail probe list into
  the implDirective round 0 avoided rework. A requirement change (pack decision) that old tests pin is a listed D3
  carve-out of exact lines, each replaced by a stronger assertion, never a blanket "tests may change".
- **Spring static entry document (fix-12 T1):** `no-cache` alone is not enough, the jar fixes `Last-Modified` at
  1980-02-01, so a revalidation still answers 304; a literal resource-handler pattern for one file gives an empty
  resource path (404), use a capture variable. qa-final warning allow-lists must be judged base vs tip, not by a list.
- **Multi-class surefire selectors use a comma between classes** (`A#m1,B#m2`); `A#m1+B#m2` runs only one class.
- **Implementers must not mutate production files outside their fileScope to self-probe** (spec 06 T7): say in the implDirective "describe each mutant in the outbox; the verifier runs it".
- **When a QA lead Required Action literal fails the lead's own rule** (spec 04 T4: a fixed isbn made another asserted order monotone), the implementer should block and ask; choosing a stronger literal within the rule is within authority and the lead endorsed it.
- **Bugfix criteria traps (fix-05):** a guard test that asserts a new message or a defect value cannot be "green before and after"; write "green after only" for those up front. "No double rounding" needs sub-ulp witnesses (`500.00000000000001`), not merely distinct doubles. A QA lead feed-forward "implementers never edit production files to probe" collides with a test-only fix whose plan-defined control IS a production-file probe; carve that probe out in the directive. A thread-safety defect has no deterministic behavioural test: a package-private seam plus a structural test, with the negative control restoring only the root-cause file, held. One combined senior brief (lite+research) settled three framework questions in about 20 minutes.
- **Criteria I add beyond the pack spec can block an agent** (spec 01: "no package-info.class is produced", impossible without a POM change). Keep orchestrator-added criteria source-level and inside the task's file scope.
- **Content checkers that model MDX with regexes loop** (spec 11 T5: four QA rounds, each found a new missed-span bypass). Decide at shaping whether a source-level oracle is worth it; prefer checking the built HTML (`check:built`) for security-relevant rules, and give the QA lead a closed construct list as the bar from round 1. A subagent orchestrator can be force-handed-back mid-wait: keep the ledger resume point current before every long wait.
- **Docs-site cycles (spec 11):** freeze the checker by a hash baseline once the content tasks start, and bind each page by a hash file per task; later one-line amendments (A11, A12) then prove themselves by removal hashes. A literal ban in a directive needs replacement wording, and trim-for-fit needs a list of qualifiers that must survive (T12 REJECT). A Node CLI self-test that reads a long failing stderr over a pipe is flaky on Linux only (`process.exit` drops the tail): capture through files, reproduce in a Linux container before any ruling. A CI run can fail at startup with 0 jobs ("workflow file issue"): re-run it, and make the PR watch confirm every expected check name (build, verify, windows-build) is listed before merging.
- **Follow-up relaunch of a finished cycle (spec 11 T13):** a relaunch can start with cwd in the main checkout while the project root is a worktree; put "memory only under <worktree>/.claude/agent-memory" in every spawn prompt and check `git status` of the main checkout after each agent. Before touching a frozen checker on a coordinator brief, grep what the check really pins: the brief may rest on a premise from a decision's wording (D16 "hook tabs" that never existed). Combine the QA lead's last task review and the qa-final brief in one spawn to save a round.
- **Frontend tasks (spec 12): most rework was literal-grep and fixture hygiene, never product code.** Put in every frontend implDirective up front: run the QA lead's literal C0-6 grep set before handoff (titles, comments and fixtures are scanned: `style={{ color` in a fixture, a package name in a test title, "document title" matching unescaped `document.title`); build banned-form fixtures from string parts; tabulate every array inside a pass-through `toEqual` (3+ elements, no attribute sorted either way, one UUID per entity). Licence files are never edited to pass a grep: exempt the file. Run the memory guard BEFORE the memory commit.
- **Long parallel cycles (spec 12):** merge origin/factory into the spec branch before the verification task and again before qa-final; every factory merge brings memory conflicts (union index lines yourself, owner curates topic files) and can push a memory dir over budget, so run the guard after each merge. Re-baseline Java counts and warnings from a base referee on the merged factory commit, check a pom by patch-id instead of a file hash, and judge screenshot freshness by commit order. A verification task (live walk-through) found real UI defects: plan a fix task slot after it. Referee times swing 20 to 34 s with parallel orchestrators on the machine; quote both measurements.
- **Live replays on a shared machine must name an isolated database** in the directive: `spring-boot:run` plus `docker compose down -v` removes the shared `bookstore-postgres-1` volume of every checkout (spec 07 T7), and `spring-boot:run` alone creates it (spec 08 T4). `bookstore/compose.yaml` binds host 5432, so a second compose project cannot run beside it. Ask for an own `docker run` Postgres on a free port, `java -jar` with `--spring.docker.compose.enabled=false`, app port never 8080, a quoted teardown, and a name-based docker proof (other cycles start containers mid-run, so an empty `docker ps -a` diff never holds).
- **Spec cut from another unmerged spec branch (spec 08 on 07):** merge `origin/factory` in a scratch `git worktree add` on the local spec branch while a task branch is checked out in the main worktree; then each open task branch merges the spec tip before its ship gate (memory-only conflicts). PR checks can register after 60 s: the watch script must loop on "no checks reported".
- **LLM adapter specs (spec 08):** check vendor API rules against the pack config (a sampling setting the API now rejects was dropped as a self-accepted, flagged decision); keep tests offline by construction and run every gate's referee twice, plain and with a fake key exported. Sonnet held for tools, integration tests and README; opus for config, ChatClient wiring and the HTTP adapter. Every round-0 FAIL was one surviving mutant, closed test-only in one round.
- **Offline pin for integration tests (fix-08 A4):** pinning `spring.ai.model.chat` in a shared test base makes the
  offline EnvironmentPostProcessor skip and breaks its full-boot witness; pin the blank key plus a loopback base URL
  instead (inlined test properties outrank the environment). Prove exported-variable safety with a decoy loopback
  base URL and a per-host connection count.
- **LLM live checks find what offline tests cannot** (fix-08 A2, A3): thinking-block replay order (Spring AI 2.0.2),
  follow-up lookups without tool results in memory, fields the prompt never names. Plan a stub-server contract test
  of the real model client and a prompt-text test set up front; a readable genre list needs the tool argument form too.
- **Pausing for a main-session check as a subagent:** the harness forces a hand-back when the run idles; hand back
  with a precise resume point instead of waiting.
- **Spec 09 (scripts, docs, seed amendments):** a mid-cycle amendment can contradict the pack (D12: 10 genres x 10
  AVAILABLE with exactly 100 books leaves no room for discontinued books); count the enum before planning and stop
  with options. I cannot TaskStop my own children; stop a superseded verifier with an urgent inbox directive and accept
  a BLOCKED verdict. Merging the spec tip into an in-flight task branch: WIP-commit, merge, leave only the doc conflict
  to the implementer, commit the merge myself. A "line N reads X" criterion deletes other sentences on that line; name
  the sentence. Rewriting a census test (T8) silently dropped an all-rows check: ask the lead to diff old clauses, not
  counts. The qa-final base can move mid-sweep: re-check `ls-remote factory` before readiness, merge, re-baseline
  changed gated files by patch-id, re-run only tip-dependent items. Opus held for the publish script and its follow-up
  (both one test-only rework round); sonnet held for seed, http, docs, cap, count tasks.
- **Participant-baseline probes (fix-09):** a temporary `V<n+1>__*.sql` under `bookstore/src/test/resources/db/migration/`
  is applied by the test profile, so "a participant adds a migration" needs no production file; Maven keeps removed
  test resources in `target/test-classes`, so probes need `clean` or a manual move. Brief qa-final to run the whole
  module with the probe. Feed-forward only lands if copied into plan.md and the next task prompt (ledger-only items
  were skipped by verifiers). Lite bugfix with sonnet docs/test tasks and opus script task held in one round each.
