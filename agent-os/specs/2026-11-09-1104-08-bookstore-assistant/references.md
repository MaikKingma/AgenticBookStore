# References: Spec 08 Bookstore assistant

## Research summary (2026-11-09)

- Spring AI 2.0.2 on Boot 4.1.2 and Java 25 (verified by the senior researcher in a throwaway project on the pins, no real API call): an empty `spring.ai.anthropic.api-key` does not stop startup (the first real call would get a 401); `spring.ai.model.chat=none` switches the Anthropic chat model off; Boot 4.1 registers environment post-processors under `org.springframework.boot.EnvironmentPostProcessor` in `META-INF/spring.factories`; `AnthropicChatModel.call()` runs no tools, the tool loop runs in the `ToolCallingAdvisor` that `ChatClient` registers on every call; a test `ChatModel` must return `ToolCallingChatOptions` from `getOptions()`, otherwise Spring AI drops every tool silently; `MessageWindowChatMemory` over `InMemoryChatMemoryRepository` with `maxMessages(20)`, `MessageChatMemoryAdvisor`, and the `ChatMemory.CONVERSATION_ID` advisor param, which has no default (missing gives `IllegalArgumentException`); the memory stores only the user message and the final answer; `@ToolParam(required = false)` gives null; a tool exception reaches the model as its message only; `spring.ai.anthropic.chat.model`, `.max-tokens` and `.temperature` bind without `.options` (`AnthropicChatProperties`); with no temperature property set, Spring AI sends no temperature, top_p or top_k; the Anthropic SDK reads `ANTHROPIC_BASE_URL` when no base URL is configured; the SDK's Jackson 2 sits next to Jackson 3 without conflict.
- Anthropic API (claude-api reference, read 2026-11-09): the current Haiku model id is `claude-haiku-5-5` (alias form, no date suffix); since 2026-10-21 any Messages request that sends `temperature`, `top_p` or `top_k` gets a 400 on every model.
- Bookstore seams: `CatalogueFlow.search(q, title, author, genre)` returns up to 100 `BookDTO` sorted by title then ISBN, DISCONTINUED books included, no paging or sort option; `findById` and `InventoryFlow.findByBookId` throw `NotFoundException` (`book-not-found`); an unknown genre throws `InvalidInputException` (`unknown-genre`, 422, details list the valid genres); spec 07's `StockItemDTO.pendingRestock()` carries `expectedDeliveryDate`; `BookQueries` computes `inStock` as `available > 0`, ignoring status; `CommandExceptionHandler` and `QueryExceptionHandler` are scoped with `basePackageClasses`, so nothing covers `assistant`; the ArchUnit fixture `archfixtures/command/ChatCommands.java` uses the test-only stub `org.springframework.ai.archfixtures.StubChatClient`, which can now be a real Spring AI type; `IntegrationTestBase` holds one shared context and a forked context costs about 1 to 3 s. Baseline on this branch (spec 07 at 9196b08): bookstore 1138 tests, distributor 190, referee 19.9 s.
- Storefront contract (spec 12 on `origin/factory`, `frontend/src/api/types.ts` and `pages/AssistantPage.tsx`): `ChatPayload {conversationId, message}`, `AssistantReplyView {conversationId, reply}`, 429 recognised by status alone, 503 recognised by `code` `assistant-offline`, 1000 characters mirrored. It matches the spec text.
