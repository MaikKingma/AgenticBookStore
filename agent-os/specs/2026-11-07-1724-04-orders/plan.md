## Binding decisions (shape.md has the rationale; do not reopen)

- B1 Clock and time: `Order` does not keep a `Clock`; `Order.place(EmailAddress, List<OrderLineRequest>, Clock)` and `ship(Clock)` take it, read `clock.instant().truncatedTo(ChronoUnit.MICROS)` once per call and use that one value for `placedAt` and `OrderPlacedEvent.occurredAt` (or for `shippedAt`). `restore` keeps the given instants as they are. Flows inject the spec 02 `Clock` bean; no second `Clock` bean, no change to `ClockConfig`.
- B2 Value types: `OrderId(UUID value)` with `Objects.requireNonNull` and `static newId()` (the `BookId` pattern). `EmailAddress(String value)`: null throws `InvalidEmailAddressException`; otherwise `value.trim().toLowerCase(Locale.ROOT)`, then the normalised value must have at most 254 characters and match `^[^@\s]+@[^@\s]+\.[^@\s]+$` (compiled once, no flags), else `InvalidEmailAddressException`. `trim()`, never `strip()` (B8 subset argument). `OrderStatus { PLACED, SHIPPED }` only. `OrderLineRequest(BookId bookId, String isbn, String title, Money unitPrice, Quantity quantity)` is a domain record whose compact constructor only null-checks (`NullPointerException`). `OrderLine` keeps `isbn` and `title` as `String` snapshots (copies of already validated catalogue values; the order never re-validates a copy) and `unitPrice` as `Money`.
- B3 Line rules: `public static Quantity OrderLine.quantityOf(int quantity)` is the one home of the 1 to 10 rule: outside 1 to 10 (checked on the `int` before any `Quantity` is built, so -1 gives the same exception) throws `OrderedQuantityOutOfRangeException(quantity, 1, 10)`, otherwise returns `new Quantity(quantity)`. The `OrderLine` constructor applies the same rule. `Order` rejects fewer than 1 or more than 20 lines (`OrderLineCountOutOfRangeException(count, 1, 20)`) and two lines with the same book (`DuplicateOrderLineException(bookId)`). Both factories (`place`, `restore`) check every rule; only `place` registers an event.
- B4 Flow inputs and outputs: `placeOrder(String customerEmail, List<PlaceOrderLineDTO> lines)` returns `UUID`; `PlaceOrderLineDTO(UUID bookId, int quantity)` is a new DTO (the standard requires flow parameters to be JDK types or DTOs). `OrderDTO(UUID id, String customerEmail, String status, Instant placedAt, Instant shippedAt, List<OrderLineDTO> lines)` and `OrderLineDTO(UUID bookId, String isbn, String title, BigDecimal unitPriceAmount, String unitPriceCurrency, int quantity)` carry the derived read values as accessor methods pinned against the aggregate: `OrderLineDTO.lineTotal()`, `OrderDTO.total()` (both scale 2, `HALF_EVEN`) and `OrderDTO.currency()` (the currency of the lines). `itemCount` is a presentation value computed in `OrderSummaryView` as the sum of line quantities (O1).
- B5 Check order of `placeOrder` (O5 refined): (1) `EmailAddress`; (2) every requested quantity through `OrderLine.quantityOf` in request order; (3) merge per book in a `LinkedHashMap` (first appearance keeps its position, quantities summed) and every merged quantity through `OrderLine.quantityOf`; (4) every distinct book through `BookDataService.findById` once, in first-appearance order, stopping at the first unknown book (404 passes through) or discontinued book (`BookNotOrderableException`, 409); (5) every stock item through `StockItemDataService.findByBookId` once, in first-appearance order, `reserve(quantity)` with each `InsufficientStockException` collected into `details` in request order; any shortage throws one `ConflictException` `insufficient-stock`; (6) `Order.place` with snapshots of isbn, title and current price (line count and duplicate rules live there, unreachable over HTTP); (7) save and publish (B6). Steps 1 to 6 write nothing.
- B6 Save and publish: one private helper used by `placeOrder` and `ship`: `orders.save(new OrderDTO(order))`, then each stock item in ascending `UUID` order of its book id (`UUID.compareTo`) through `stockItems.save`, then `publishEvent` for every pulled event of the order, then for every pulled event of each stock item in the same book-id order. `ship`: `orders.findById` (404 passes through), `OrderDomainMapper.toDomain`, `order.ship(clock)` before any stock item is read, then per line in book-id order `findByBookId`, `StockItemDomainMapper.toDomain(stored, clock)`, `ship(line.quantity())`, then the helper.
- B7 Translation: one private static translator in `OrderFlow`; no domain exception escapes the flow. Rows in the ProblemDetail contract below. Accepted untranslated (500, as since spec 02): optimistic locking and lock conflicts between concurrent orders, an unknown stored status string (`OrderStatus.valueOf`), null arguments from a caller (programming errors, not tested).
- B8 Place payload (O2): `PlaceOrderPayload(@NotNull @Size(max = 254) @Pattern(regexp = "[^@\\x00-\\x20]+@[^@\\x00-\\x20]+\\.[^@\\x00-\\x20]+") String customerEmail, @NotNull @Size(min = 1, max = 20) @Valid List<@NotNull OrderLinePayload> lines)`; `OrderLinePayload(@NotNull UUID bookId, @NotNull @Min(1) @Max(10) Integer quantity)`. Subset argument: a value accepted by the payload has no character at or below U+0020, so `trim()` leaves it unchanged and it matches the domain pattern after lower-casing; the only HTTP path to 422 `invalid-email` on place is a 254-character address whose lower-case form is longer (for example with U+0130), accepted and documented.
- B9 Customer query (O3): `GET /orders` without `customerEmail` is 400 `validation-failed` with `details = [{field: "customerEmail", message: "is required"}]` through the nested `OrderQueries.MissingQueryParameterException` and one new `QueryExceptionHandler.handleMissingQueryParameter`; any present value (empty and blank included) goes to `OrderFlow.findByCustomer`, which parses `EmailAddress` (422 `invalid-email`) and asks the port with the normalised value. A repeated parameter arrives comma-joined and is a 422.
- B10 Views: `OrderView(UUID id, String customerEmail, String status, String placedAt, String shippedAt, List<OrderLineView> lines, String total, String currency)`, `OrderLineView(String isbn, String title, int quantity, String unitPrice, String lineTotal)`, `OrderSummaryView(UUID id, String status, String placedAt, int itemCount, String total)`, component order as in the spec. Money as `toPlainString()` of the scale-2 amount; instants as `Instant.toString()` (ISO-8601, UTC `Z`); `shippedAt` is JSON `null` before shipping (key present). `currency` from `OrderDTO.currency()`.
- B11 Persistence (O7): V3 DDL as in T3 (no check constraint, FK to `book` kept, `uq_order_line_book`, index `ix_customer_order_customer_email`); `OrderJPA` with an `@ElementCollection` of `@Embeddable OrderLineJPA` and `@OrderColumn(name = "position")`; `save` mirrors spec 02 and 03 (`findById` first, update the managed entity or insert, `saveAndFlush`); the update path copies only `status` and `shippedAt`; the customer list is one JPQL `join fetch` query on the stored lower-case email, `order by o.placedAt desc, o.id desc`, no `lower()`, no `Limit`.
- B12 Test devices (O8): `OrderEventRecorder` (TEST root package, plain class, no stereotype) shaped like `StockEventRecorder` but typed on `OrderPlacedEvent`, imported by `IntegrationTestBase`, reset in its `@BeforeEach`; the existing `@MockitoSpyBean StockItemDataService` is the second device (a later stock save fails). No new spy, no new context.
- B13 F28 (O9): `StockItemTest` gains additions-only cases proving `reserve` and `ship` keep a set signal above and at the reorder level; `StockItem.java` is unchanged.
- B14 `OrderPlacedEvent(UUID orderId, String customerEmail, BigDecimal total, Instant occurredAt)` carries the normalised address (O10), `total().amount()` and the truncated placement time; record with JDK types, no validation.

- S24 (new): a use case that writes several aggregates in one transaction saves them in a deterministic total order (for example ascending id after the owning aggregate), pinned by an `InOrder` test whose request order and every other column order differ from the sort order; every failure path verifies that nothing is saved and nothing is published, and the integration layer proves the boundary with a failure device plus a must-fail swallow probe.
- S25 (new): a flow translator has a flow test per caught exception type, including types reachable only through stored data, provoked by a mocked port returning a corrupt stored DTO; "no domain exception escapes the flow" is otherwise unproven.
- S26 (new, extends S20): a value with a single production default that a layer passes through without validating it (currency `EUR`, status, quantity 1, an empty list) gets one other value in that layer's tests (DTO, JPA mapper, view, handler), and a regex whose character class repeats gets one rejecting witness per position.
